# 五场景环境音 v0.1 · 交给场景/语音同伴

标注：Emma0923。音频设计基于场景快照 621dfa3；本交付分支 emma0923/audio-pack 基于 main 90a8470，仅新增「音效包/Emma0923」目录，供同事选取合并。操作命令均从本音效包目录执行。

## 可以立即用

本 GitHub 包提供 WAV 和可运行试听台。另行提供的本地交付物「AIMA_五场景环境音与眼镜测试.html」是内嵌音频的单文件版本（未重复放入 GitHub）：复制到眼镜连接的电脑，使用 Chrome/Edge 打开并点击启用声音。无需网络、Google Key、Python、麦克风权限或眼镜 SDK。页面不能自动认出眼镜，也不读取眼镜摄像头。

工程版在 `音效包/Emma0923` 目录执行：

```sh
python tools/serve_soundscape.py --port 8890
```

打开 http://127.0.0.1:8890/ 。要跟随游戏实际步数，在同一电脑指定真实 ShellOS 地址，例如：

```sh
python tools/serve_soundscape.py --port 8890 --source http://127.0.0.1:8877
```

页面展开「跟随正在运行的游戏」并点击连接。8877 只是例子，请使用游戏实际端口。独立服务器默认仅监听回环地址；代理仅 GET /state、禁用重定向，输出只含时间、路段、进度、主题和移动状态，不转发用户档案、力矩或凭据。未改已有游戏的启动方式。

## 合并到游戏

`audio.mjs` 提供 Soundscape，`state.mjs` 提供 ProgressGate。`lab.mjs` 是可以直接运行的接入参考，包含解锁、主题切换、步数门控和失联停止。集成方应在游戏自己的 UI 中提供「启用声音」，从用户手势调用 `sound.start()`。

```js
import { Soundscape } from '/soundscape/audio.mjs';
import { ProgressGate } from '/soundscape/state.mjs';
const sound = new Soundscape(name => '/soundscape/assets/' + name);
const gate = new ProgressGate();
// 启用按钮 onclick: await sound.start()
// onState: const r = gate.accept(S, performance.now())
// 有效状态: 按 r.style 切主题，sound.setRegion(r.terrain)
// r.step: sound.step(r.material)
// !r.moving: sound.stopSteps()
// r.arrive: sound.cue('arrive')
// 超过 1.6 秒无有效状态: sound.stop(); gate.reset()
// 恢复连接不自动复播，用户再次点击启用声音
```

上述是接口示意，不是完整启动器；可运行版本见 lab.mjs。切主题应处理异步竞态，停止之后不要让迟到状态重新发声。无需每帧调用 switchScene；只在主题改变时调用。

主服务器目前没有 /soundscape 静态路由。由服务器维护人增加只读静态路由，并设置 `.mjs → text/javascript`、`.wav → audio/wav`、`.json → application/json`；保留路径穿越检查。也可以先使用独立试听服务器，不必修改现有主服务器。

状态门控：第一包只定基线；重复、乱序、断线、跳步、复位、换世界均不补播脚步；每次严格增加 1 个有效游戏步才播放一次。它不根据步频猜测未来动作。游戏步数不当作真实米数。

多屏同一浏览器来源使用 BroadcastChannel，后启用者接管。不同电脑/不同来源仍需产品端指定唯一音频主机；电视、手机、眼镜不要同时播三份。默认进入后台停止，在游戏集成页面或旁边窗口保持试听页面可见；后台音频策略需产品端后续单独设计。

## 与峰哥解说协作

预留 `sound.setNarrationActive(true/false)`：解说中环境音降到原电平 22%，脚步降到 45%。测试页有复选框演示。

这不是现有 voice.js 的自动联动：请语音维护人在真正开始播放时调用 true，在 ended/error/pause 时调用 false。仅看到 /state.fengge 的新文本不等于语音正在播放，所以这里不靠猜测文本事件压低环境音。也未复制或抢占峰哥的 TTS 服务。

## E06s 与其他眼镜的边界

当前实现走电脑/手机的标准音频输出。若 E06s 能在系统里作为媒体音频设备使用，即可走这条路径；包装所写蓝牙版本不能替代实际配对与播放验证。

有屏眼镜仍可使用同一声音模块，画面另由手机/电脑镜像或厂商 SDK 适配。未宣称支持所有厂商的屏显、头部姿态、麦克风或摄像头。此版本没有空间锚定的头部追踪，左右声道与轻微脚步声像不等于完整空间音频。

## 远程电脑怎样测试

1. 在连接眼镜的电脑打开单文件试听页；配对成功后，在系统音频输出中选择眼镜。先用系统测试音确认实际设备。
2. 远程控制软件若将声音重定向到控制端，需要选择在远程电脑播放/保留远端声音。具体选项取决于远程软件，先确认系统和工具名称。不要把能听到远程桌面音频当成眼镜测试通过。
3. 佩戴者依次测试左、居中、右，再听四套环境声和训练场静音；开启/停止模拟脚步，检查脚步不会继续自走。
4. 观察连接眼镜的电脑屏幕，按声画同步脉冲，记录体感提前/滞后。浏览器 baseLatency/outputLatency 只是估计，不能证明蓝牙端到端延迟；准确测量需要同一录制设备同时记录屏幕闪光和眼镜声，用多次样本对齐。
5. 断开蓝牙再重连，检查系统是否退回电脑扬声器以及浏览器是否需再次启用。网页不能可靠自动判定配对丢失，应由佩戴者确认。
6. 不开启麦克风即可完成当前测试。将来启用语音通话时单独复测媒体声质/延迟；不能假定双向语音仍保留相同播放路径。
7. 填写页面下半部，导出 aima-glasses-test.json。此记录不含眼镜设备 ID、麦克风录音或账户信息；手填备注请自行确认内容。

当前 Codex 会话没有这台远程电脑的操作通道；只能完成本地代码/数字音频检查。只有在确认系统、远程连接方式并取得可用操作入口后才能远程部署。无需发送密码。最终硬件验收需要佩戴者反馈。

## 构建与验证

运行时仅浏览器，独立服务器仅 Python 3.9+ 标准库。重新生成音频需要 numpy 和 ffmpeg：先按 manifest.sources 下载原文件到各项 file 文件名、核对 SHA-256，将 sources 数组保存为 sources.json，并将雨/脚步 ZIP 解压至 rain/、steps/。构建命令 `python tools/build_soundscape.py --sources <目录>`。

```sh
node --test tests/soundscape-state.test.mjs
python -m unittest discover -s tests -p test_soundscape.py -v
```

原素材授权与改动见 `CREDITS.md`；音频作者和哈希见 manifest.json。

本次验证：5 个状态门控测试、3 个文件与代理检查通过；本地 HTTP 试听页五套环境音解码成功，数字输出有信号，训练场默认静音、红灯抑制脚步、未配置游戏源时停播已检查。循环接缝幅度小于正常波形高分位相邻差分，无数字削波。并非人耳音质验收或 E06s 验收。

单文件版已打包，自动浏览器限制访问 file:// 本地文件，因此其双击打开流程留待远程电脑实测；HTTP 版已验证。暂无远程硬件听感、实际蓝牙时延或兼容全部眼镜的测试结论。
