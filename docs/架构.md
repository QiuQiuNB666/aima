# ShellOS：外骨骼主机端控制栈架构

> 2026-09-22。官方 App 不认黑客松固件，串口是唯一入口，所以主机（Mac）要接管 App 的全部职责：连接、模式、控制、安全、记忆、界面。
> 目标不是做"操作系统"，是做一个 44 小时内跑得稳、评委敢穿的控制栈。一个 Python 进程，四个线程，一个网页。

## 0. 设计原则

1. **安全层是硬件和一切代码之间的唯一通道。** 任何模块都不能直接写串口，只能向安全层提交"期望力矩"；安全层决定发不发、发多少。
2. **控制律是确定性的，大模型只碰参数。** 大模型永远不在 200 Hz 循环里，它的输出是带范围的参数差值，经校验后才生效。
3. **没设备也能开发。** 所有模块对着一份录制的 200 Hz 数据跑，回放器和真串口对上层长得一样。
4. **能砍。** 第 1–3 层做完就是一个能演的 demo；第 4–6 层每一层都是加分，砍掉不影响下面。

## 2. 线程与数据流

```
串口线程 (200 Hz)          控制线程 (100 Hz)            主线程 / 界面
──────────────             ──────────────              ────────────
readline → Frame ──→ ring ──→ 步态估计 → 控制律 → 期望力矩
                     buffer                     ↓
                                            安全层 → T,l,r ──→ 串口 write
                                                ↑
                              手柄线程: 扳机/急停 ──┘
                                                          WebSocket 每 20 Hz
                                                          推 Frame + 状态 + 参数
                              Agent(按需，秒级): 评委一句话 → 参数差值 → 参数表
```

- **串口线程**只做两件事：按行读、解析成 `Frame`、放进环形缓冲；把安全层批准的命令写出去。不算任何东西。
- **控制线程**固定 100 Hz（协议允许 10–500 Hz，100 Hz 足够，Python 在 Mac 上 10 ms 周期抖动可接受）。每拍取最新 Frame → 更新步态状态 → 当前控制律算期望力矩 → 交安全层。
- **手柄线程**读 DualSense（USB），产出两个信号：`deadman`（扳机是否按住，连续量）和 `estop`（任意一键急停）。
- **界面**是 FastAPI + 一个 HTML 页，WebSocket 20 Hz 推状态；命令（切模式、改参数、删经验）走 HTTP。
- **Agent** 不是线程，是一次函数调用：输入评委原话 + 当前参数 + 用户画像，输出经过 schema 校验的参数差值。

## 3. 各层职责

### 0 设备层 `device/`

| 模块 | 做什么 |
|---|---|
| `serial_link.py` | 打开 `/dev/cu.usbmodem*`，3000000 8N1；`send(cmd)`；后台 `readline` 解析 `S:` 行为 `Frame`（15 个字段 + 主机时间戳）；解析 `OK,` / `ERR,` / `PONG` 为应答事件；连接握手 `PING → VERSION → ENABLE` |
| `replay.py` | 读录制的 CSV，按原始时间戳以 200 Hz 吐 `Frame`，接口与 `serial_link` 一致；`send()` 只打印。**没设备时整个栈对着它跑** |
| `recorder.py` | 每一帧和每一条发出的力矩写 CSV（文件名带时间戳和穿戴者 ID）。既是调试素材，也是 EvoMap 的"数据" |

`Frame`：`t_host, ms, pitch, roll, yaw, gx, gy, gz, ax, ay, az, kpa, l_deg, r_deg, l_dps, r_dps`

### 1 安全层 `safety/guard.py` ★ 先写、先测、不再动

输入：期望力矩 `(tl, tr)`、`deadman ∈ [0,1]`、`estop`、步态置信度。输出：真正发出的 `T,l,r` 或 `DISABLE`。规则按顺序，任一触发即短路：

1. `estop` 或 `deadman == 0` → 发 `DISABLE`，状态机进 `DISARMED`，要重新握手才能再 ENABLE
2. 软限：`|t| ≤ SOFT_CAP`（默认 3 Nm，配置可到 5，硬件 7.5 永远不用满）
3. 斜率限：每拍变化 `≤ SLEW` Nm/拍（默认 0.1 Nm/10 ms = 10 Nm/s），起步从 0 爬
4. 死人开关按压深度做全局缩放：`t *= deadman`——扳机按一半，力就只有一半
5. 步态置信度低于阈值 → 力矩归零（不 DISABLE，等它恢复）
6. 看门狗：控制线程超过 50 ms 没提交 → 发 `T,0,0`；超过 200 ms → `DISABLE`（协议本身 100 ms 清零是最后一道，别依赖它）
7. 进程退出、异常、`Ctrl+C`、串口断开 → `atexit`/信号处理里发 `DISABLE`

状态机：`DISCONNECTED → CONNECTED → ARMED(ENABLE 已发) → ACTIVE(deadman>0) → DISARMED`。界面上永远显示当前状态和最近一次发出的力矩。

### 2 步态估计 `gait/`

| 模块 | 输出 |
|---|---|
| `filters.py` | 髋角、角速度的一阶低通（EMA），去均值 |
| `phase.py` | 极角相位 `φ = atan2(k·ω, θ−θ̄) ∈ [0, 2π)`，左右各一个；置信度 = 相图半径是否在正常范围（站着不动时半径≈0 → 置信度 0，力矩自动归零） |
| `events.py` | 髋最大伸展（≈离地）、最大屈曲（≈触地前）事件；步频；左右步时 |
| `posture.py` | 站/坐/前倾判断（躯干 pitch + 髋角），给坐站控制律用 |
| `metrics.py` | 每 10 步汇总：步频、左右步时对称比、步时变异、髋活动度。给记忆层当"用户画像"，给界面当"步态签名" |

### 3 控制律 `control/`

统一接口：

```python
class Controller(Protocol):
    name: str
    params: dict            # 全部可调参数，带 (min, max, default)
    def step(self, frame: Frame, gait: GaitState) -> tuple[float, float]: ...  # 期望 (tl, tr)
```

| 控制律 | 参数 | 用途 |
|---|---|---|
| `transparent` | 无 | 力矩恒 0。穿上先跑这个，评委适应 |
| `dofc` | `gain, delay_s, ema` | 延迟输出反馈：`t = −gain·(θ_L(t−d) − θ_R(t−d))/2`，不依赖相位。**主力**，三参数好讲 |
| `phase_profile` | `peak_ext, t_ext, peak_flex, t_flex, rise, fall`（单位：Nm、%周期） | 相位驱动的力矩曲线，"早一点/晚一点/轻一点"直接对应参数，演示最直观 |
| `sit_to_stand` | `boost, onset_pitch, duration` | 前倾超过阈值起身时给伸展助力。展位没走廊时用 |

切换控制律 = 先经安全层斜率降到 0，再换。参数改动只允许通过 `set_params(delta)`，内部裁剪到 (min, max)。

### 4 界面 `ui/`

- `server.py`：FastAPI。`GET /` 仪表盘；`WS /stream` 20 Hz 推 `{frame, gait, torque_cmd, torque_sent, safety_state, controller, params, hits}`；`POST /param`、`POST /mode`、`POST /feedback`（评委原话）、`POST /memory/delete`、`POST /demo/reset`
- `static/index.html`：一页，Canvas 画三条曲线（左右髋角 + 发出的力矩）、相位圆、状态灯、参数表、经验卡片流。**暗场展位要看得清：深底大字**
- `input/gamepad.py`：pygame 线程；扳机 → deadman，× → 急停，○ → 演示复位，方向键 → 参数微调一档
- 键盘热键做手柄的备份（空格 = deadman，Esc = 急停）

### 5 记忆与 Agent `memory/`、`agent/`

**经验条目**（JSON 一行一条，`memory/experiences.jsonl`）：

```json
{"id": 7, "ts": "...", "trigger": {"cadence": [95, 110], "controller": "phase_profile"},
 "delta": {"t_ext": -5}, "quote": "早一点", "wearer": "judge-03",
 "confidence": 0.8, "hits": 2, "enabled": true}
```

**流程**：
- 穿上 → 走 10 步 → `metrics` 出步频等画像 → `retrieve()` 按画像找 `enabled` 且 `trigger` 命中的条目 → 叠加 `delta` 得初始参数 → 界面显示"命中经验 #N"或"0 命中，用缺省"
- 评委说话（键盘输入或麦阵转写）→ `agent.interpret(quote, params, profile)` → 大模型返回 `{"delta": {...}, "trigger": {...}, "confidence": ...}`，schema 校验 + 范围裁剪 → 写入经验 + 立即 `set_params` → 界面弹卡
- `delete(id)` → `enabled=false` → 参数回退 → 再走就回到原状（"不是写死的"证据）
- `demo/reset`：物理状态复位、目标意图那条经验停用、历史卡片保留。评审用"演示态"，Open Hour 用"累积态"

**大模型**：走 EvoMap 官方 API（先确认 OpenAI 兼容），备一个国内 key。提示词里给参数表、范围、当前值、画像，只允许输出 JSON。断网降级：一张固定映射表（"早"→ t −5%，"轻"→ peak −1 Nm，"左腿"→ 只改左）。

### 6 EvoMap 层 `evomap/` 可砍

- 每次会话开始 `recall`、结束 `record`（节点私有记忆）
- 把一条真实踩过的坑发成 Gene + Capsule（比如"pyserial 3 Mbps 在 macOS 要设 `timeout` 否则 readline 阻塞"，或"髋角相位法站立时半径塌缩要用置信度门控"），validation 用 `node` 跑一个回放断言脚本
- 界面常驻一张卡：已发布资产、状态、被 fetch 次数

## 5. 时序预算（控制线程一拍 10 ms）

| 步骤 | 预算 |
|---|---|
| 取最新帧 | <0.1 ms |
| 滤波 + 相位 + 事件 | <0.5 ms |
| 控制律 | <0.1 ms |
| 安全层 | <0.1 ms |
| 串口 write（一行 ~16 字节 @3 Mbps） | <0.1 ms |
| 余量 | >9 ms |

200 Hz 读线程用 `readline()`；一行约 100 字节 @ 3 Mbps 是 0.3 ms，跟得上。pyserial 打开时 `timeout=0.05`，否则断线时 readline 永远阻塞。

## 6. 故障与降级

| 故障 | 表现 | 处理 |
|---|---|---|
| 串口断开 | readline 超时 3 次 | 安全层进 DISARMED；界面红灯；自动重连，重连后要重新握手 |
| 数据流停 | 200 ms 无新帧 | 力矩归零；500 ms → DISABLE |
| 控制线程卡死 | 看门狗 | 串口线程自己发 DISABLE |
| 大模型超时/断网 | >3 s | 用 `fallback.py` 固定映射表，界面标"离线规则" |
| 手柄掉线 | pygame 事件 | deadman 视为 0 → 力矩归零；键盘接管 |
| 评委体型异常 | 相位置信度低 | 力矩自动归零，界面提示"请走几步" |
| 设备没电 | — | 回放器 + 录屏。这是最后一档 |

## 8. 不做的

- 不做 App、不做手机端、不做蓝牙——串口是唯一入口，也是最稳的入口
- 不做步态分类模型、不做端到端策略——文献和时间都不支持
- 不做多用户账户体系——`wearer` 就是一个字符串
- 不做固件侧任何东西——固件是 Hypershell 的，我们只发 T
- 不碰蓝牙协议逆向——那篇安全论文别引
