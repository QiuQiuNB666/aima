# 峰哥导游 · 稳定性（G 线，9/24 凌晨）

目标：展位上 100 次开讲，100 次正常。链路：`game/guide.js`（开讲 / 打断 / 镜头）+ `game/voice_bus.js`（新，峰哥声道仲裁 + 自动播放解锁）+ `shellos/agent/guide.py`（话术、缓存检查）+ `server.py` 的只读 `/guide/*`。

## 怎么测

`scripts/guide_stress.mjs`：无头 Chrome 反复跑「进 /game → Enter 关标题屏 → 等导游 → 听完 / 走路打断 / 急停 / 待机 / 登顶 → 复位 → 再来」，每一轮自动判对错。

- 每一轮代码先 `git archive` 成一份冻结副本，在自己的端口起 `--sim`（8858 基线、8859–8862 第 1–4 轮）。大脑 / TTS 指向死端口，不打真接口。worktree 里接着改代码，不会影响正在跑的那一轮。
- 自动播放策略：缺省 `document-user-activation-required`（桌面 Chrome 默认：页面收到过一次按键 / 点击之后才能出声）；`--policy=strict`（每次 play 都要紧跟着手势，Safari / 手机那种）；`--policy=none`（Chrome 带 `--autoplay-policy=no-user-gesture-required`）。Enter / K 用 CDP 的真实按键发，算用户手势。
- 探针：包住 `HTMLMediaElement.play`，记录每个 `<audio>` 的 play / playing / ended / pause / 被拒，用来判断两段峰哥语音有没有叠在一起。
- 场景（`--mix` 轮流跑）：
  - enter-listen：听完。
  - enter-walk：讲到一半开始走。
  - r2：按住 R2 关掉标题屏，直接开走，应该跳过导游。
  - reload：切世界后重载，不出标题屏、没有按过键。
  - inject：讲到一半插进一句峰哥事件（`/voice/last.wav`）、一句地标台词、一个事件气泡。
  - idle：没人动，进待机回到标题屏，下一位按 Enter，应该重讲。
  - estop：讲到一半急停，再上膛。
  - nowav：第 3 句的 wav 返回 404。
  - summit：走到山顶，回到山脚站住，下一位应该重讲。
- 机器负载在 100–470 之间（很多条线并行），页面加载 3–45 s，所以时间类的数字偏悲观。

## 第 1 轮 · 声道仲裁（af76810）

`voice_bus.js`：再包一层 `HTMLMediaElement.prototype.play`，按网址认说话的是谁：`/guide/<world>/` 是导游，`/guide/*_fx/` 是地标台词，`/voice/last.wav` 是峰哥事件。这层在 settings.js 管音量的那层外面，所以音量设置照旧生效。同一时刻只放一段：

- 高优先级打断正在放的低优先级。
- 低优先级排队：事件最多等 6 s，地标最多等 4 s，过期就丢。
- 导游讲解期间 `hold('guide')` 占住声道，句与句之间的停顿也算。这期间事件和地标台词一律丢掉，不会插进句缝里。

`fengge_hud.js` 加了 1 行：导游讲解期间，别的气泡不插进来。E 的 `lines.js`、V 的 `voice.js` 不用改。

- 单测 `tests/test_voice_bus.py`（node + 假 `<audio>`）：打断、排队、过期、占住期间丢弃、真正出声的顺序，全部通过。
- 压测 10 轮（旧版判定）：enter-listen、enter-walk、r2、estop 都正常。**查出我自己的一个 bug**：仲裁层自己记了一个「已解锁」标志，而这个标志要等静音片段放完才异步置上。负载高的时候，Enter 之后第 1 句 play 来得比它早，被仲裁层自己拦掉了（浏览器其实放行）。这个在第 3 轮改掉了。

## 第 2 轮 · 自动播放（38e80ad）

- 没解锁时导游**先不讲**：页面下方出「🔈 按任意键开启峰哥声音」，点这个提示本身也算。
- 第一次按键 / 点击 / 触摸时，在同一个事件里放一段 30 ms 的静音 wav 解锁，同时把导游和地标的片段静音 play 一下再停。这一步是「预热」：Safari / 严格策略下，只有在手势里 play 过的元素，之后才能不靠手势播。
- `lines.js` 加 1 行，把地标片段也登记预热。
- 峰哥事件在没解锁时直接丢掉，不让 voice.js 再弹一个自己的按钮。
- 压测发现：**Shift / Ctrl / Esc 这类键，Chrome 不算用户操作**，按了解不了锁（7 段预热全被拒）。所以展位上要按字母、空格或回车。

- 压测 10 轮：inject（插一句事件 + 一句地标台词）**不再叠着念**，气泡也还是导游那句；idle / estop / enter-walk / r2 都正常。仍失败的是 summit（问题 ⑥，第 4 轮修）和 reload（压测脚本按的 Shift 不算手势，脚本已改成按 K）。

## 第 4 轮 · 状态机（60a0bb5 → 修正 edea7d4）

`window.__guide.state()` 有三个状态：armed / playing / done。

- **变回 armed（来了新的一位）**：页面载入、出过标题屏或待机、换穿戴者、步数变小（登顶后回到山脚，或复位）。
- **armed → playing**：同时满足才开讲：
  - 「准备」界面稳定 0.6 s（防抖）；
  - 没开菜单，在山脚；
  - 没在走、没按 R2；
  - 预加载完、声音已解锁。
- **armed → done**：没听就走出了山脚（步数 ≥ 1），这一位跳过。在山脚走动或按着 R2，只是先不讲：登顶那一步走完回到山脚时人还在迈步，等他停下来再讲。
- **playing → done**：讲完；或者走动、按 R2、急停、开菜单、离开「准备」，立刻停，之后不重讲。
- body 的 class 一变就立刻判断（MutationObserver），打断不用等 5 Hz 轮询。
- `__camHold` 只交还自己拿的镜头。以前导游停下时会把标题屏 / 待机的航拍镜头一起放掉。

**两个事故，照实写**：

1. 60a0bb5 里状态变量和样式标签都叫 `st`，同一个作用域重复声明，整个 guide.js 加载失败，一次都没开讲。`node --check` 直接查 .js 查不出这个错，要按 ES 模块查。修正版 edea7d4：
   - `test_guide.py` 加了按 ES 模块查语法的测试；
   - engine.js 改成动态 `import('./guide.js')`，导游代码出错也拖不垮游戏；
   - voice_bus.js 改成静态 import，越早装越好。
2. 第 4 轮前两次压测打到了**别人的模拟器**。8862 端口已经有一个从主工作区起的 `--sim`，我起模拟器的脚本没查端口，我的模拟器没起来，压测就一直打在那台上：01:25–01:37 往它发过复位、换山、急停、`/hold`。那两次的数据全部作废，已向总指挥报告。现在的做法：
   - 起模拟器前先查端口，被占就不起；
   - 起完核对监听的进程是自己的；
   - 压测脚本开跑前查 `/state.sim.on`，不是模拟器就退出。

- 在自己的端口 8871 重跑 edea7d4，10 轮：**9/10**。剩下那 1 轮是 ⑥：登顶后模拟器多迈了 1 步，被判成「没听就走了」，导游跳过。
