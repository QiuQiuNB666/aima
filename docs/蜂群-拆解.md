## 1. 一句话

**球球只跟总指挥说话；总指挥把活拆成线，每条线是一个独立会话、一个 worktree、一条分支，按文件归属各改各的；线在指挥板回报，总指挥统一合并。能带走的是三样东西：骨架固定的派活单、人人能写的指挥板、一个只管合并的总指挥。**

## 3. 怎么搭、怎么派、怎么不撞车、怎么收

**角色**

| 角色 | 是什么 | 干什么 |
|---|---|---|
| 球球 | 人 | 定方向、拍板、纠偏；只跟总指挥说话（线阶段 106 : 8） |
| 总指挥 | 一个 Claude Code 会话（`c4d962c4`，9/19–9/25，1,689 次工具调用） | 拆活、写派活单、开线、往线里追加指令、读指挥板、合并 / 推送 / 部署、管共享资源；自己不下场干线上的活（球球 9/24 08:14：「不用你亲自来做呀…你是指挥啊」，08:34：「怎么都是你自己在跑，你再开个对话框啊」） |
| 线 | 独立桌面会话，字母代号（H/V/C/S/A2/L/P/J/M2/E/R/U/G/ART…） | 在自己的 worktree + `claude/…` 分支里干，只改名下文件，commit 不 push，指挥板留言 |
| 后台 Agent | 总指挥起的后台子 Agent（54 次） | 调研、重派、后台线；总指挥可以中途 `SendMessage` 追加指令 |
| 工作流 | 多 Agent 编排（总指挥 8 次启动、6 个 run、110 个 Agent） | 例：9/23 夜 `shellos-build-harden`：Build（6 线并行）→ Integrate → Attack（4 个对抗审查员）→ Fix → Attack2 → Fix2 → Wrap，258 分钟、30 个 Agent |
| 定时巡检 | `CronCreate`（4 个循环巡检 + 2 个一次性任务） | 「球球授权无人值守，不要问他、不要停」：定时合并、推送、部署，催停下的线；撞限额时什么都不做 |

**开线**：9/23 10:48 球球一句「你这样做太慢了 你分几个任务给其他对话框吧」，2 分钟后第一批 4 张卡片（H/V/C/S）。之后按波次开：13:20 A2/L，13:50 P/J/M2，15:14 E，15:39 R，15:53 U，17:24 G/ART；9/24 08:40 珠峰终验 / 展位彩排 / 评委彩排 / 视频精修，10:45 真机排障 / 白噪音。做法最早是球球 9/19 在另一个项目里提的（「再分几个对话框 我来同时指挥吧 然后你们最好有一个总指挥」），当场写进了记忆文件，EvoTavern 直接复用。

**派活单的骨架**（本片收到的那份就是例子）：① 你是哪条线；② 仓库在哪、先建自己的 worktree 和分支；③ 目标与产出（写成文件路径和验收标准）；④ 数字按哪份口径；⑤ 绝对不做的事（密钥不打印、开无头 Chrome 走信号量、展位 8765 不碰、端口先 `lsof`）；⑥ 怎么回报（commit、不 push、指挥板留言，9/25 起限 5 行）；⑦ 称呼「球球」。

**不撞车的三招**

1. **按文件归属拆**：指挥板上登记每条线名下的文件；要动别人的文件就在指挥板留言。共享文件只许最小改动（「engine.js 属于 M，你只加 import + 一行调用，合并冲突总指挥处理」）。结果：91% 的文件只被一个分支碰过。
2. **隔离 + 只有总指挥合并**：每条线一个 worktree、一条分支，只 commit 不 push；各线定期把 main 合回自己分支（分支 reflog 里 75 次「merge main」）。唯一人人都写的指挥板成了冲突重灾区（40 / 45），于是：9/23 12:06 写 `resolve_board.py`（只把该线那一行换进来）→ 9/24 00:25 合并链遇冲突即停 → 03:03 起 `/tmp/aima-merge.lock` 目录锁（总指挥、巡检、工作流合并者共用）→ 12:10 起 `flock`。
3. **共享资源上闸**：9/24 02:31 开发机 load 实测 728.8（约 40 个无头 Chrome），02:53 写 `with_chrome.sh`（全机最多 3 个，mkdir 原子槽）并广播给 6 条桌面线和 7 个后台 Agent；自测一律自起 `--sim`、先 `lsof` 找空闲端口、只杀自己端口的进程；展位 MacBook 8765 各线只读（「不许重启它、不许对它发任何 POST，那边可能有人穿着」）；`deploy.sh` 排除 `.git`（起因：C 线发现在 worktree 里部署会删掉 MacBook 上的 `.git`）。

**收活**：线在指挥板底部留言（做了 / 验证 / 没做到 / 要拍板）；总指挥读完转派（例：R 线 16:16 留言说 `/terrain/force` 没有超时，16:17 合进 main，16:20 总指挥加上 TTL，16:21 R 线同步，16:25 用上，前后 9 分钟）；一条线的规范可以扇出到多条线（ART 美术范式 18:00 合入，之后 R/J/P/E 的提交都引用它）；终验线、评委彩排线把问题逐条分派「归谁」。

**不跑偏**：教训沉淀在全局 `CLAUDE.md`（grok 事件的 6 条硬规则：原任务有答案就停、工具失败最多诊断一轮、「继续」有歧义要问、限频立刻收手、自下而上诊断）和记忆文件（「活多就拆对话框并行」「撞限频不停工」「别叫队长」），跨会话、跨上下文压缩（总指挥压缩过 3 次，每次约 97 万 token）照样继承。

## 4. 翻车与代价（照实写）

- **巡检没兑现**：6 个 cron 全是 session-only（不落盘）。9/24 03:13–03:20 撞会话用量上限，约 03:24 桌面应用重启，03:49 到 07:22 没有任何回合，05:41 的总结没发出，直到球球手动敲「Try again」。
- **重复劳动**：演示视频前后做了三遍；V 线和总指挥各做了一次 MiniMax 声音复刻（多扣约 19.8 元）；原提交物线没响应，另开新线接手。
- **路由断了**：珠峰终验 9/24 09:18 分派给 W/E/U/助理线的几处问题（如 `snow.js` 着色器编不过），git 里之后没有修复记录（11:00 提交冻结）。
- **撞车**：9/23 16:25 有线的测试脚本打到别人的 8877 模拟器；9/24 01:39 导游压测误打到 8862 发了复位 / 急停（都不涉及真机）；E 线在已合入后又改写自己的分支，下一次合并一次冲突 16 个文件。
- **worktree 建错仓库**：Agent 的 `isolation: worktree` 建在总指挥 cwd 所在的另一个仓库，之后派活单加了兜底；aima 至今残留 24 个 worktree。
- **防循环拦截**：一个会话没等到用户输入、连发 10 条跨会话消息后，后续会被拦下（S 线 9/23 22:55 被拦 2 条）。
- **本片自己返工**：派活单是总指挥转述的，写成了「拆解游戏里的 AI 蜂群」，球球要的是这套工作流。教训：线交活时写清「按什么理解做的」，拿不准就先问。

## 5. 和 EvoMap、Hermes Agent 比

| | **我们：一人 + 总指挥 + 线** | **EvoMap**（本届主办方） | **Hermes Agent**（Nous Research） |
|---|---|---|---|
| 编排单位 | 完整的 Claude Code 会话：各有上下文、工具、worktree、分支；人能直接跟任何一条线说话 | agent 节点（本地客户端 Evolver 做进化，Hub 做分发） | 一个主 agent；`delegate_task` 起子 agent（默认最多 10 个并发，上下文隔离，只把总结交回）；v0.21 起有多 agent 群聊 Bot Mode 和 agent 间私信 |
| 怎么通信 | 总指挥 → 线：跨会话消息（112 条）；线 → 总指挥：消息 + 仓库里的指挥板（markdown）；线 ↔ 线：少量直接消息 | A2A 协议：hello / publish / fetch / report 等 | 父子委派、群聊、peer 私信 |
| 结果怎么合 | git：各线分支，总指挥合并（116 次，45 次冲突） | 资产发布到 Hub，GDI 打分晋升，别人 fetch 继承 | 子 agent 的总结回到父 agent 上下文 |
| 隔离与安全 | worktree + 分支 + 文件归属 + 合并锁 + Chrome 信号量 + 真机只读 | 发布质量门槛、内容哈希、声誉、验证报告 | 命令审批、硬黑名单、容器沙箱 |
| 经验怎么传 | 本地、由人筛：指挥板、全局 `CLAUDE.md`、记忆文件 | 跨团队、自动筛：Gene（策略）+ Capsule（验证过的结果），「一个 Agent 学会，百万 Agent 继承」 | 单个 agent 的 `MEMORY.md` / `USER.md`、会话检索、自写技能 |
| 适合 | 一个人带一大群完整 agent，在一个仓库里赶工期 | 多团队 / 多 agent 生态复用已验证的解法 | 个人或团队的通用助理，一个 agent 带子 agent 干活 |

**接 EvoMap 的设想（未实现）**：把「无头 Chrome 全机信号量」「指挥板冲突只换本线那一行」这类踩坑经验打包成 Gene（`signals_match`: `multi-agent`, `git-worktree`, `headless-chrome`；`constraints` 写死上限）+ Capsule（本次的负载数据和效果），先 `/a2a/validate` 试发再 `/a2a/publish`；别人的 Agent 蜂群开工前按信号检索继承。难点：GEP 的 `validation` 只许 node / npm / npx，非代码经验要包一层校验脚本。

**Hermes 按哪个理解**：按 Nous Research 的 Hermes Agent（最新 v0.21.5，2026-09-24）。旁证：EvoMap 官方博客 2026-04-11 专门写过 Hermes Agent 和自家 Evolver 的相似性分析，主办方语境里的「Hermes」就是它。其它同名候选（Nous Hermes 大模型、Meta 的 Hermes JS 引擎、MIT Little HERMES 遥操作机器人等）与本题无关。
