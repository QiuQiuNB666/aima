## 1. 一句话结论

**EvoMap 管经验怎么在 agent 之间流动；Hermes Agent 管一个通用 agent 怎么越用越好；我们的蜂群管一句人话怎么安全地落到一台真机的髋关节力矩上——大模型只出提议，永远不在力矩的写路径上。**

## 2. 三方对比

| | **我们 · Agent 蜂群** | **EvoMap**（本届主办方） | **Hermes Agent**（Nous Research） |
|---|---|---|---|
| **定位** | 嵌在实时安全控制回路里的窄域蜂群：评委一句话 → 外骨骼髋力矩参数 / 一座能爬的山 | 「AI 自进化基础设施与 Agent 经验网络」：用 GEP 协议让 agent 跨模型、跨地区共享、验证、继承能力 | 开源（MIT）的通用自进化 agent 运行时：「The self-improving AI agent built by Nous Research」 |
| **谁能改什么** | 大模型只出**参数差值提议**（教练）和**路线草稿**（地形导演）；安全员放行后才进控制律参数；只有安全层 Guard 能写串口 | agent 把 Gene + Capsule 打包发布；Hub 质检、打 GDI 分，晋升后别的 agent 检索、继承、回报验证 | 大模型直接调工具、跑终端命令、写记忆、自己新建 / 修补技能 |

| **适用场景** | 会伤到人的实时物理控制：外骨骼、腿部力反馈外设 | 多 agent 生态里复用已被验证的解法（官方范例偏代码修复、IoT 设备控制） | 个人 / 团队的通用助理与自动化：20+ 消息平台、cron、子 agent、研究轨迹生成 |

## 3. 我们的蜂群：怎么用、怎么设计（代码事实）

四个角色写在同一条时间线上（`App.say()`，`shellos/main.py:162`；峰哥解说也写进这条线，所以时间线上实际有五种发言者）。

| 角色 | 谁来当 | 做什么 | 代码 | 大脑不在时 |
|---|---|---|---|---|
| 教练 | 大模型 | 一句话 → 参数差值提议。参数名只能从当前控制律里选、每个参数一次最多改它范围的 15% | `shellos/agent/interpret.py:69`（by_claude，15% 在 :81） | 规则表 `RULES`（interpret.py:12），卡片来源标 `rule` |
| 地形导演 | 大模型 | 一句话 → 路线草稿（路段、步数、地名、画面风格） | `shellos/worlds/gen.py:106`（generate） | 关键词模板 `by_rule`（gen.py:25） |
| 记忆员 | 代码 | 写卡时对照同步频段已有卡（同向几张、反向几张）；换人走满 6 步后检索、取平均套用；删卡回退 | `main.py:143`（auto_recall）、`:311`（delete_exp）、`shellos/memory/store.py:53 / :71` | 本来就是代码 |
| 安全员 | **硬代码，故意不交给大模型** | 超软限就裁；30 s 同一参数最多改 3 次；急停一律否决。造山：起步平地（不是就补 2 步）、台阶不过半（从后往前改成坡）、红灯 ≤ 2 且每个 1 步、单段 ≤ 20 步、总长压到 20–80 步、未知路段丢弃 | `main.py:168`（safety_review）、`gen.py:50`（build，常量在 :12） | 本来就是代码 |

**大模型永远不在力矩的写路径上。** 完整路径（swarm-code 核对员逐行追过）：`brain.call('/coach')` → 参数白名单 + 15% 幅度裁剪 → `App.feedback` 的前置检查 → 安全员 `safety_review` → 控制律 `set_params` 夹到参数范围 → 地形控制律按路段打固定形状的脉冲（造山草稿只决定路段类型、步数和标签，造不出新的力矩形状）→ `Guard.submit`（`shellos/safety/guard.py:81`：未上膛不发、急停 DISARM、死人开关 0 发 0、断流 0.2 s 立即发 0、步态置信度 < 0.5 目标归零（再经斜率限每拍 0.5 Nm 爬到 0）、裁到软限、死人开关深度缩放、斜率限）→ `send_torque`。另有看门狗（ACTIVE 时）100 ms 没控制拍发 0、1 s DISABLE。大模型调用都不在 100 Hz 控制循环里（HTTP 线程或后台线程）。

**评测与测试**（口径同提交表单）：大模型实连（MiniMax-M3，9/23 C 线）教练 23 句 23/23、p50 1.6 s；造山 10/10 由模型生成、p50 7.0 s。`tests/test_swarm.py` 9/25 实跑 6 passed（其中 4 条管蜂群：裁剪 / 限次 / 急停、假提议 +9.0 被裁到 +0.45、离线造山能走、离线解说用内置语录）。

**本片录屏实测**（9/25，本机模拟外骨骼 `--sim --force-deadman --ctl terrain --cap 4 --strength 3.0`，展位同参数）：

- 大脑离线（`SHELLOS_BRAIN=http://127.0.0.1:9`）：「重一点」3.0 → 3.5；「再重一点」→ 4.0；再「再重一点」想到 4.50 Nm 被裁到 4.00、不生效；「太陡了」→ 3.5（30 s 内第 3 次）；「还是太陡」被否决「30 秒内已经改了 3 次」；删掉 #3 卡参数回退到 4.0；急停后「轻一点」被否决「急停中，一律否决」；造山走规则模板，35 步，路线检查通过。
- 大脑在线（本机 8790，MiniMax-M3）：「太陡了，腿有点跟不上」→ 教练提议 strength −0.5，理由「嫌陡、腿累，是力度太大」；换人「评委-04」走满 6 步命中 #1 #2 #4 取平均；「先平路热身，然后全是台阶的天梯一百五十步，中间来五个红绿灯，最后冲顶」→ 约 4 s 出草稿「峰哥夜登十八盘」39 步，安全员删掉 3 个多余红灯、把 2 段台阶改成坡。

## 4. 主办方 EvoMap：是什么、和我们差在哪、怎么接

**身份更正**：EvoMap 是本届 EvoTavern（进化酒馆）的**主办方**——「由 EvoMap 发起的 Agent Builder 活动系列」，深圳是第 04 场、收官场。按选手指南，01 CYBERBODY 赛道原题来自 Seeed，Hypershell 是 03 赛道出题方兼外骨骼平台提供方。**「外骨骼是人与物理世界的可编程接口」不是 EvoMap 的人说的**，是 Hypershell（极壳）创始人孙宽的观点，而且是媒体转述（投资界 2026-05-18：「他认为外骨骼本质上是人与物理世界的'可编程接口'」）。

**EvoMap 是什么**（官方原文）：「EvoMap 是面向 AI 自进化的基础设施。通过基因组进化协议（GEP），Agent 可跨模型、跨地区共享、验证并继承能力。」口号「一个 Agent 学会，百万 Agent 继承」。背后是深圳 AutoGame 团队（创始人张昊阳），由 OpenClaw 插件 Capability Evolver 转型而来。

**机制**（任务里「agent 之间共享 Gene / Capsule 的进化网络」——属实，细节如下）：

- **Gene（基因）**：可复用的进化策略——响应哪些信号（`signals_match`）、按什么步骤做（`strategy`）、守什么约束（`constraints`）、怎么验证（`validation`，只许 node / npm / npx 命令）。
- **Capsule（胶囊）**：一次被验证过的成功进化——触发条件、用了哪个 Gene、置信度、影响范围（`blast_radius`）、结果（`outcome.score`）、环境指纹。
- **EvolutionEvent（进化事件）**：一次进化周期的审计记录，成败都记。社区叫它们「GEP 三件套」。
- **流程**：Gene + Capsule 必须打包发布（`POST /a2a/publish`，可先 `/a2a/validate` 试发）；资产 ID 是规范化 JSON 的 sha256；进 Hub 先是 candidate，按 GDI（基因期望指数：内在质量 35% / 使用 30% / 社交 20% / 新鲜度 15%）打分，达标晋升 promoted 才能被检索和 `/a2a/fetch`；用过的人 `/a2a/report` 回报验证结果；节点声誉 50 起算。协议标识 gep-a2a v1.0.0，HTTP + JSON；另有托管 MCP 和 OAuth 开发者平台。本地客户端叫 Evolver（官方比喻：Git 客户端 vs GitHub）。
- 9/25 实测：Hub 共约 503 万个资产、173 万个 promoted、38 万个节点；按信号检索 `signals=exoskeleton` **0 条**（语义检索能返回机械臂等相邻的机器人资产，比如 Gene「OpenArm」，但没有外骨骼专属的）。

**区别**：EvoMap 解决的是 **agent 之间经验怎么传播、怎么被选择**——它不管某一条经验落到物理世界时会不会伤人，质量门槛面向的是代码修复（validation 只许 node/npm/npx、blast_radius 按文件和行数算）。我们的蜂群解决的是 **一句人话 → 安全地改真机力矩**：经验卡是本地的、按步频检索、删卡即回退，所有进入参数的改动都要过硬代码安全员，力矩只有 Guard 能写。

**接入设想（未实现）**——评分项「闭环学习能力」和主办方「沉淀经验并被继承」的叙事都指向这里：

1. **发布**：一张经验卡被 ≥ 3 位不同穿戴者命中且没被删，就转成一个 GEP bundle——
   - Gene：`category: optimize`，`signals_match: ["exoskeleton", "hip_torque", "terrain_feedback", "cadence_80_100"]`，`strategy` 写「按步态相位在支撑期施加梯形脉冲；评委说太陡 → strength −0.5」，`constraints` 写死软限 4 Nm、30 s 同参数 ≤ 3 次、急停否决；`validation` 用 `npx` 调一个把卡片喂给 `--sim` 回放、断言 Guard 从未超软限的包装脚本。
   - Capsule：`trigger` = 控制律 + 步频区间，`content` 放原话、参数差值、命中次数（不带穿戴者名字），`outcome.score` = 命中后没被删的比例，`env_fingerprint` = Hypershell X MaxS / 固件版本 / 控制律 / 软限。
   - 先 `/a2a/validate` 试发，再 `/a2a/publish`。
2. **继承**：新展位或新设备开机时 `GET /a2a/assets/search?signals=exoskeleton,cadence_80_100` → `/a2a/fetch` 取 promoted 胶囊 → 转成本地卡（来源标 `evomap`、默认不启用）。**远端来的卡一律当成新提议重新过安全员**，这和本地检索直接套用不同。
3. **回报**：本地删掉一张来自 EvoMap 的卡，就 `/a2a/report` 一次 `passed: false`，让坏经验在 GDI 里被淘汰。

难点照实写：GEP 的 validation / blast_radius 是为代码设计的，非代码经验要靠包装脚本和 `content` 字段硬套。`@evomap/gep-sdk` 1.14.0 源码里有一个文档没写的 `reference_only` 胶囊（纯文本内容、blast_radius 为 0），形状最贴近经验卡，但 openapi 写明「blast radius 为 0 永远不分发」，大概率只存不晋升——要先用 `/a2a/validate` 试出 Hub 实际规则。发布只能用节点的 node_secret 走 GEP-A2A（OAuth token 和用户 ek_ key 会被拒）；开发者平台有 test_mode 沙箱，适合演示时不污染真实 Hub。晋升耗时从几分钟到几小时，现场演示继承只能按 asset_id 定向 fetch。

## 5. Hermes：按哪个理解、是什么、和我们差在哪

**按 Nous Research 的 Hermes Agent 理解。** 团队文档（aima-swarm 与 ~/黑客松-EvoTavern 共 1858 个文件）里搜不到 Hermes / 赫尔墨斯，无法从文件确认球球指的是哪个。支持这个理解的旁证：EvoMap 官方博客 2026-04-11 发过《Hermes Agent Self-Evolution System: A Detailed Similarity Analysis with Evolver》，认为 Hermes Agent 的自进化体系和 EvoMap 的 Evolver 结构高度相似且没有署名，并因此把 Evolver 从 MIT 改为 GPL-3.0；另有一篇 Hermes Agent vs EvoMap 的记忆对比。这是 EvoMap 一方的说法，我们不站队，但它说明在主办方语境里「EvoMap vs Hermes」指的就是这个 Hermes。其它叫 Hermes 的候选：

| 候选 | 是什么 | 和本项目的关系 |
|---|---|---|
| **Hermes Agent（Nous Research）← 本片按这个** | 开源自进化 agent 运行时 | 同为「带记忆、会学习的 agent」，最像球球要对比的对象 |
| Nous Hermes 大模型系列 | Nous 自家的 LLM（Hermes 4 / 4.3） | 是模型，不是 agent 框架 |
| Hermes 工具调用格式 | vLLM `--tool-call-parser hermes`、Qwen2.5 的工具调用模板 | 一种提示词格式 |
| Meta Hermes | React Native 的 JavaScript 引擎 | 无关 |
| MIT Little HERMES 双足机器人（MIT + UIUC） | 操作员穿背心全身遥操作，机器人要倒时操作员**背心上感到一股拉力** | 具身遥操作 + 力反馈，概念上最接近我们的硬件方向 |
| HERMES EXO（色萨利大学学生队） | 全驱动下肢外骨骼 | 外骨骼硬件项目 |
| 思岚 SLAMTEC Hermes | 服务机器人底盘 | 无关 |
| informalsystems/hermes | Cosmos IBC 中继器 | 无关 |

**Hermes Agent 是什么**：官方一句话「The self-improving AI agent built by Nous Research」，自带学习闭环：从经验里生成技能、用的时候改进技能、提醒自己沉淀知识、检索自己的历史对话、跨会话建立用户画像。MIT，Python。9/25 查 GitHub Releases：最新 **v0.21.5**（tag v2026.9.24，2026-09-24，补丁版）；上一个大版本 v0.21.0「The Pantheon Release」（2026-08-31：多 agent 群聊 Bot Mode、agent 之间互发私信、带记忆的 cron、子 agent 可实时改方向）。

- **记忆**：`~/.hermes/memories/MEMORY.md`（agent 自己的笔记，2200 字符上限）和 `USER.md`（用户画像，1375 字符）会话开头冻结注入 system prompt；历史会话存 SQLite，用 FTS5 全文检索（`session_search`）；另有 7 个外部记忆插件（Honcho、Mem0 等），默认不开。
- **技能**：`~/.hermes/skills/`，兼容 agentskills.io；agent 用 `skill_manage` 新建 / 修补 / 删除技能，每轮之后后台复盘也会写。
- **工具与安全**：模型直接调工具和终端（local / Docker / SSH / Modal 等 7 种后端）；危险命令审批默认 smart（辅助大模型判风险），cron 等无人值守场景默认拒绝，`--yolo` 也跳不过写死的硬黑名单；容器后端里跳过审批（容器即边界）。
- **其它**：一个 gateway 接 20+ 平台（含飞书、钉钉、企业微信、微信）；`delegate_task` 起隔离上下文的子 agent；支持 Nous Portal / OpenRouter / OpenAI / 自建端点和本地 llama.cpp。

**区别**：Hermes 是**通用 agent 运行时**——大模型是执行者，自己调用工具、自己写记忆和技能，安全靠审批、黑名单和沙箱把它的动作框住。我们是**嵌在实时安全控制回路里的窄域蜂群**——大模型只是提议者，关在「参数差值 / 路线草稿」这一层；能改参数的只有安全员放行的那一份，能写力矩的只有 Guard；安全员和 Guard 都是可预测、可测试、100% 复现的硬代码，不存在「让模型判断这条命令危不危险」。Hermes 的记忆是给大模型读的文本；我们的经验卡是给控制律套用的结构化参数差值，删一张就能精确回退。

## 8. 核对中发现的出入（没改代码，需要拍板）

1. **提交表单 `/tmp/intro.txt` 第 3 段「出题方创始人讲过『外骨骼是人与物理世界的可编程接口』」**：团队口径里「出题方」指 Hypershell（孙宽），但外部读者容易读成 EvoMap；而且原文是记者转述（「他认为外骨骼本质上是…」），我们加引号写成「讲过」说重了。建议改成「Hypershell 创始人孙宽认为（投资界报道），外骨骼本质上是人与物理世界的可编程接口」。`项目介绍.md:72`、`评委题库.md:99` 同理；项目介绍里的「终态是用户觉得眼前的山变矮了」在标注的极客公园原文里检索不到，需补来源或删。
2. **评测数字的出处**：「教练 23/23 p50 1.6 s、造山 10/10 p50 7.0 s」在 `项目介绍.md`（C 线 9/23），不在 `docs/大脑-评测.md`（那份是 60 句基准：MiniMax-M3 45/60，p50 1.7 s）。指挥板里还有更晚的第 3 轮（教练 p50 1.7–2.3 s，造山 p50 9.7 s、最长 32.7 s）。本片按任务要求用提交表单口径。
3. **单测条数**：`项目介绍.md:51` 和 intro.txt 写「tests/test_swarm.py 4 条」，现在是 6 条（9/25 实跑 6 passed）。
4. **记忆员的检索和删卡回退不上蜂群时间线**，只进仪表盘「事件」栏和经验卡面板；本片画面用的就是经验卡面板。
5. **安全员只拦 `/feedback` 这一条路**：换人后的自动检索套用、删卡回退、手动 `/param` 不经过安全员，只受控制律参数范围和 Guard 约束（卡片写入时已经过安全员）。造山 `make_world` 不查急停（此时 Guard 已 DISARMED，力矩照样为 0）。
6. **造山总长上限偶尔 81 步**：swarm-code 核对员随机草稿跑 5 万次 `gen.build`，113 次出 81 步（按比例压缩后每段至少 1 步、红灯固定 1 步）。
7. **删卡回退在多卡平均后会过冲（真实参数错误）**：两张 +0.5 的卡平均套用（1.5 → 2.0）后两张都删，强度变成 1.0，比缺省 1.5 还低——每删一张都减整张卡的差值，套用时只加了平均值（`main.py:317` + `store.py:76`）。单卡演示路线不受影响。
8. 安全员的软限裁剪只管 `TORQUE_PARAMS`，`impact`（下台阶落地冲击系数，也影响力矩）和 t_* / width 不裁，靠参数范围、脉冲 ±CAP 和 Guard 兜住。
9. 大脑失败后的 20 s 退避是所有角色共用的：一次 `/fengge` 超时也会让接下来 20 s 的教练 / 造山直接走规则表 / 模板，界面不提示原因。
10. 大脑提示词写「时机 ±5」，但 15% 幅度裁剪后时机参数最多 ±3；MiniMax 下教练最坏约 20 s（5 s 超时 × 重发 × 两轮），超过 ShellOS 的 12 s 就退回规则表。
11. 小口径：画面风格实际 7 种（文档写 5 种）；`/memory/enable` 恢复的卡要等换人或复位后的下一次检索才生效。
