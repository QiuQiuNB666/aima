一句话：现在的 VR、体感、跑步机游戏只有视觉反馈——画面加手柄震动，腿是空的，几乎没有人做物理反馈。我们做的就是登山走路的物理反馈：穿上一台量产的消费级髋关节外骨骼（Hypershell X MaxS）原地迈步，屏幕里的你在爬珠峰北坡，坡和台阶变成腿上真实的阻力和助力。游戏是载体，主角是我们自研的外骨骼控制软件 ShellOS——官方 App 禁用了这个型号，控制层从串口协议起全是自己写的。峰哥口吻版：「VR 只骗眼睛，这玩意儿骗腿，这是个好事儿啊。」

为什么是物理反馈：消费市场上的腿部触觉只有振动（bHaptics）、电刺激（Teslasuit）和位移平台 / 滑动鞋（KAT、Cybershoes），没有一款消费设备能在腿上给主动力矩。学术界的腿部地形力反馈（Holotron、Haptic Ankle Platform、PreloadStep）都挂在固定平台或地板装置上，不能穿着走。Hypershell 这类消费级髋外骨骼已经量产，本身就有两个电机、髋角编码器和腰部 IMU，它就是一台现成的「腿部力反馈外设」，只是没人这样用过——我们检索了中英文、GitHub、B 站 / 知乎，把消费外骨骼改成游戏外设：零结果。出题方创始人讲过「外骨骼是人与物理世界的可编程接口」，我们做的正是这个接口上的应用层和记忆层。三层同时成立才算新：穿戴式可走动、髋单关节按步态相位定时的力矩脉冲、消费级量产硬件当地形外设。我们不说「首个腿部力反馈」，蒙眼二选一实验没做到 ≥ 9/10 之前也不说「用户能分辨坡度」。

怎么做到：跑在笔记本上的 ShellOS 分五层。第 0 层设备：真机串口、模拟外骨骼、录制回放三者同一接口，上层无感。第 1 层安全层 Guard 是唯一能写串口的地方：软限 4 Nm（固件硬限 7.5 Nm 永远不用满，约 0.05 Nm/kg，低于文献扰动实验最低档）、斜率限 50 Nm/s、死人开关（手柄 R2 松开力矩归零）、步态置信度 < 0.5 出力为零、看门狗 100 ms 没控制拍发 0、1 s 直接 DISABLE、急停后必须手动重新上膛、所有控制类 POST 只认本机。第 2 层步态估计：从 183 Hz 髋角数据算极角相位，用 9/22 真机录制的 12 段数据扫了 1080 档门限，穿戴时坐 / 站假周期从 13 降到 0，走动段覆盖率 0.25 提到 0.44。第 3 层地形控制律：世界是一份 JSON（平地 / 上坡 / 下坡 / 上台阶 / 下台阶 / 红灯），控制律按路段在步态相位上打梯形髋力矩脉冲——上坡早支撑伸展「有人推」（文献 Lay 2006、Montgomery 2018），上台阶支撑期往屈曲拉「腿发沉」（9/23 球球穿真机后的反馈：上楼要阻力不是助力，摆动期故意不压腿防绊），下台阶脚跟着地一记落阶冲击再助力迈腿，红灯轻拉、站稳 2 s 放行。五种路段在软限 4 Nm 下自动核对全过，27 组参数边界扫描 0 组不过。第 4 层界面：登山游戏 /game（Three.js，离线可用）、选山 / 造山页、操作员仪表盘，大屏左下「腿上的力」画的是 Guard 实际发给电机的力矩指令，不是动画。

第 5 层是 Agent 蜂群，四个角色一条时间线：教练（大模型）把评委一句话翻成参数差值提议，参数名只能从当前控制律里选、单次改动裁到范围的 15%；地形导演（大模型）把一句话翻成路线草稿；记忆员（代码）对照同步频段已有的经验卡；安全员（硬代码，故意不交给大模型）力矩参数超软限就裁、30 s 内同一参数最多改 3 次、急停中一律否决，造山时起步必须平地、台阶不过半、红灯 ≤ 2、总长压到 20–80 步、不认识的路段直接丢。会伤到人的那道闸必须可预测、可测试、100% 复现：大模型负责听懂人话，安全员负责不管听成什么都不许越线；再往下 Guard 还有独立的软限和斜率限，大脑进程整个挂掉也不影响腿上的安全链路。大脑不在时教练走规则表、造山走模板、峰哥解说用内置语录，全部离线可跑。

一句话改手感、经验卡与影子：评委说「太陡了」，卡片滑入，下一步就变轻；经验卡记录穿戴者、控制律、步频区间、参数差值、原话和来源，换人后走满 6 步、步频稳定就按「同控制律 + 步频区间」自动检索套用；删掉一张已套用的卡，参数立即反向回退——这是「不是写死的剧本」最直接的证明。每圈登顶，这一圈每一步的时刻自动成为下一位的影子。再说一句「峰哥被追到泰山顶，一路狂奔上十八盘」，大模型出路线草稿、安全员硬裁剪、套现成画面风格，几秒后一座新山出现，马上能爬，用的是同一套路段和脉冲，没有新的力矩形状。

玩什么：展位主打珠峰北坡，67 步、海拔 5200 → 8848.86 m，惊险优先：大本营 → 东绒布冰川（牦牛驮队迎面让路）→ 北坳冰壁 → 北坳裂缝横梯（两架绑接的铝梯横跨冰裂缝，镜头压到腰高看脚下，走太快或站太久会晃，连续 2.5 s 失足黑场计一次）→ 北坳营地吸氧红灯 → 大风口刀脊（1 m 宽路面，两侧 60° 陡坡、左侧雪檐）→ 第一台阶 → 北壁贴壁横切栈道 → 第二台阶排队上梯红灯（前面的人一个个往上挪，轮到你时让一步）→ 中国梯 → 顶峰觇标红旗展开。腿上的力都有画面理由：冰川是上坡推一把，冰壁和中国梯是台阶阻力，北坳是吸氧停顿，横梯是平路不出力，惊险全靠画面和「慢点走」的规则。风雪、天色、缺氧暗角随海拔变，声景有风、冰爪、路绳、铝梯、喘气。其余地图：赛博东京攻壳致敬版（全部程序生成、致敬不复刻，5 个彩蛋：站定 3 s 光学迷彩、坂道故障字幕、登顶「2029」、贩卖机、四脚机甲抬头）、泰山十八盘、富士山吉田线、华山长空栈道、深圳梧桐山好汉坡，加两个训练场，共 8 个世界，一份 JSON 加一座山。跑酷模式：夜里城市屋顶三条道，步频就是跑速，高抬腿是跳、下蹲是滑铲、抬一条腿保持 0.3 s 免手换道，跳长按路程参数化正好滞空一个步态周期，一台程序生成的四脚机甲在后面追。

峰哥：化身是峰哥本人——低多边形身体、照片正投影的脸，进哪张图穿哪套（珠峰红色连体羽绒服 + 护目镜 + 氧气面罩 + 冰爪、华山冲锋衣 + 安全带、东京雨衣 + 反光条、泰山朱红短袖 + 遮阳帽等 7 套自动换）。进每张地图先听峰哥当导游讲这座山（固定话术、预生成峰哥音色，一迈步就打断）；登顶、遇红灯、过横梯、造出新山时，大模型按峰哥口吻现写一句「这是个好事儿啊」「恰恰相反」。声音是 MiniMax 快速复刻的峰哥音色，断网也有 11 句预生成语录能出声。峰哥的助理 NPC 走在你前面指路、在梯脚等你，只读状态、不碰任何控制接口。为什么是珠峰：峰哥 2020 年坐小飞机到卢卡拉、徒步七天到过珠峰大本营，游戏里那架只在大本营降落一次的直升机就是他的「亡命小飞机」梗。

验证数字（每条标来源）：真机 9/22——串口握手 PING → VERSION → ENABLE，183 Hz 数据流，力矩指令被接受，控制循环最大间隔 12 ms；两次 DISARMED 都是主机卡顿触发看门狗，安全层按设计工作。回放——步态假周期 13 → 0，覆盖率 0.25 → 0.44，12 段真机录制全栈回放 0 DISARM、0 Traceback，11 种故障注入 11 过。模拟——五路段脉冲核对全过、27 组边界扫描 0 不过，游戏 1080p 50–58 fps。单测——tests/test_swarm.py 4 条：强度推到软限后「再强一点」被裁成 0，30 s 内第 4 次改同一参数被否决，急停一律否决，假提议 +9.0 只剩 +0.45 且假参数被丢；恶意造山草稿（9 段各 999 步 + 4 个红灯 + 不存在的路段）被裁成能走的山。大模型实连（MiniMax-M3，9/23）——教练 23 句 23/23，p50 1.6 s；造山 10/10 由模型生成，p50 7.0 s；解说 0.9–2.2 s。导游稳定性压测 20/20 正常。真机 9/23——上台阶手感由助力改为阻力（1 人主观）。照实写的局限：真机录制只有 1 个人约 170 s，真人的步只被接住约 44%，上坡 / 下坡 / 跑酷的跳和滑铲还没穿在人身上试；蒙眼二选一（2AFC）实验 9/24 上午做，≥ 9/10 才对外说「能分辨」。

授权与开源：峰哥本人 9/23 在现场当面口头同意本次黑客松展示使用他的肖像、口吻和 AI 复刻声音（开源许可证管代码不管真人，所以另外当面问了他），他改主意一个参数就能把头像、贴脸、气泡和音色全关掉。峰哥照片、口吻、参考音频分别来自三个 MIT / Apache-2.0 仓库；助理 NPC、three-vrm、东京道具全部用可再分发许可的素材，捷风等无授权素材已弃用、不上展位不上海报；素材清单见仓库 docs/提交/素材授权.md。代码全部开源在 GitHub，依赖只有 pyserial / pygame / pynput / pytest，没有外骨骼也能 `--sim` 跑起整套游戏和蜂群，测试永远不打真大模型。我们不做医疗器械定位。
