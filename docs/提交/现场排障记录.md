## 10:58 外骨骼串口从 USB 上消失（当前主因）

**现象**：booth_check 两项红：串口 0 Hz（age 9999 ms）、控制环最大间隔 504 ms。

**数据**
- `ls /dev/cu.usbserial*`：没有；`system_profiler SPUSBDataType` 也看不到 USB 串口芯片 → 不是软件问题，是设备断电或线松了。
- 帧计数 `link.n` 卡在 16485。ShellOS 10:44:44 启动，按 age 反推**最后一帧约 10:47:17**（只连了 2.5 分钟）。
- `replies`：`SERIAL_LOST 1`、`SEND_FAIL` 持续涨（每 10 s +5，是每 2 s 一次的重新 ENABLE 打在死口上）；`reboots 0`、`last_err` 空、`enabled False`。
- 11:00:21–11:01:21 采样 7 次：n 全程 16485，safety ARMED / deadman 0 / sent 0,0，pad 在、R2 0，gait cadence 0 / strides 0 / moving False，terrain pos 0 flat，ctl terrain（没再被切）。

**判断**
- 症状①②此刻同源：设备没帧 → 没力矩；没关节角 → 步态识别不到步 → 人物不动。
- `reboots 0` 且之前没有 ERR 行：不是我们发的指令让它保护性复位（那种情况串口还在、会打开机日志）。
- 端口节点整个消失 = USB 桥掉电或线断。候选：电量耗尽、有人按了电源键、Type-C 线 / USB 口松、固件空闲自动关机。远程无法区分，要现场看灯。
- 协议里只有「100 ms 不续发 → 力矩清零」，文档里没有空闲自动关机的记录；R2 松开时 Guard 只发一次 `T,0,0` 之后什么都不发。若复电后在「没人按 R2」的空闲期又掉，才考虑加空闲心跳，先不改代码。
- 控制环 504 ms 是断线的副作用：主循环每 2 s 调一次 `recover()`，里面等 `OK,ENABLE` 0.5 s。复连后自然消失，不单独处理。
- ShellOS 重连逻辑本身没问题：读线程每秒扫 `/dev/cu.usbserial*`（端口号变了也认），接上后 2 s 内自动重新 ENABLE。

**处置（30 秒）**
1. 看外骨骼电源灯：不亮 → 充电 / 换电；亮 → 关机、数 3 秒、开机进工作态。
2. 顺手按紧两头 Type-C（设备端、MacBook 端）。
3. MacBook 上 `scripts/booth_recover.sh exo`，等「帧回来了」。
4. 按住 R2 原地踏两步，看力、看人物动。
40 s 还没帧：换线 / 换 USB 口，`ls /dev/cu.usbserial*` 看在不在。**不要**用 `--sim` / `--force-deadman` 重启。
