## 人设 A：Seeed 系硬件创业者

关心：能不能做成产品、成本、谁买单、硬件是不是真在动、团队执行力。

**A1. 一句话，你们做了什么？**
「峰哥亡命天涯」：用量产的消费级髋外骨骼做可走动的地形力反馈——你原地踏步，屏幕上在爬山，坡和台阶由按步态相位定时的髋力矩脉冲打到腿上；你说一句「太陡了」，蜂群改参数、存成卡传给下一个人；再说一句话，Claude 现场造一座山，安全员裁剪后马上能爬。【v3 §0、末节】

**A2. 硬件是你们做的吗？**
不是，一个螺丝没改。硬件是 Hypershell X MaxS + 黑客松专用固件 2.9.99.1，我们只通过 USB 串口发 `T,左,右` 力矩指令、读 183 Hz 数据帧。我们做的是主机端全部软件：安全层、步态估计、地形控制律、游戏、记忆层和 Agent 蜂群。【协议】【v3 §1】

**A3. 为什么不自己做一个便宜的腿部力反馈硬件？**
腿部要给主动力矩，需要电机、减速、绑缚和电池，这正是量产外骨骼已经解决的；市场上消费级腿部触觉只有振动（bHaptics）、电刺激（Teslasuit）和位移平台 / 滑动鞋（KAT、Cybershoes，后者 2025 年停业），没有主动力矩。用现成量产设备，软件就是全部增量。【先例 §2】

**A4. 谁会买单？**
三类，按近到远：① 已经买了 Hypershell 的户外用户——「山的记忆」是软件功能，不加硬件；② 健身 / 原地踏步爬名山，用时和影子天然有社交比较；③ VR / 游戏腿部外设。康复游戏化只作远期方向，我们不做医疗定位。【项目介绍 §3】

**A5. 市场有多大？有数据吗？**
我们只能引公开口径：Hypershell 2025 年全球出货 >3 万台、覆盖 70+ 国，2026 年 B 系列融资合计 1.2 亿美元。VR 腿部主动力矩这个细分，我们检索中英文、GitHub、B 站 / 知乎，把消费外骨骼改成 VR / 游戏外设的是零结果——所以没有市场规模数据，只有「空白」这个事实。【愿景 §1】【先例 §3】

**A6. 真的能动吗，还是只是演示动画？**
能动。9/22 在真机上握手、183 Hz 数据流、力矩指令被接受（`OK,T` 应答 323 条），控制循环最大间隔 12 ms。今天展位就是评委自己穿、自己按扳机。【v3 §1.3】【架构 v2 §9】
（「脉冲穿在身上的手感」9/22 还没验证，**待真机验证**，上午验过后改成实际结果。）

**A7. 一个陌生人从穿上到开始爬要多久？**
**待真机验证**（9/24 上午掐表，目标 ≤30 s）。流程设计上只有一个人工动作：按住手柄右扳机。换人时操作员点一下「换人」，步态估计重来、走满 6 步重新检索经验卡，影子保留。【v3 §4 第 10 项】

**A8. 延迟多少？玩游戏会不会跟不上？**
控制在主机上跑 100 Hz，一拍计算 <1 ms，真机实测循环最大间隔 12 ms；串口 3 Mbps。游戏屏只读状态、10 Hz 轮询 + 60 fps 插值，不在控制回路里——画面慢了不影响力矩时机。【v3 §1.3、§2.6】

**A9. 游戏屏会不会拖慢控制？**
测过（模拟模式，开发机 i5-7400 核显）：不开游戏 loop_ms 中位 14 / p95 16 ms；开 1080p 游戏中位 15 / p95 21–22 ms，p95 正好在我们定的 +5 ms 线上。展位机是 MacBook M2 Pro，**还没测**；兜底是游戏放第二台设备或 `?aa=0` 降画质。【指挥板 G 节】【v3 §6】

**A10. 这台外骨骼多少钱？做成外设太贵吧？**
调研口径约 ¥8k 级（不到 1 万）。我们的论点不是让人为了游戏买外骨骼，而是已经有几万台在用户身上，软件让它多一个用途。【先例 §4】【架构 v2 §0】

**A11. 电池够展位一下午吗？**
不确定。协议只说「插 Type-C 不会切到充电态」，没说怎么充；9/22 疑似低电复位过一次。预案：上午充满、中午补电；复位后控制栈自动重新使能；最后兜底是模拟模式 + 录屏，并且明说是模拟。【协议】【v3 §6】【架构 v2 §6】

**A12. 有没有用到 Seeed 的硬件？**
没有。现在的系统只用外骨骼 + 手柄 + 笔记本（+ 一块大屏）——少一个设备就少一个现场故障点。【v3 §1】

**A13. 开源吗？别人能复现吗？**
仓库公开：github.com/QiuQiuNB666/aima。ShellOS 是 Python 3.9 + 标准库，依赖只有 pyserial / pygame / pynput / pytest，前端 Three.js 放在本地 vendor 里、离线能跑；Claude 只在单独的大脑进程里调（要 anthropic SDK，独立 venv），不接大脑也能完整跑。没有设备也能用 `--sim` 模拟外骨骼或 `--replay` 回放 9/22 真机录制跑完整栈。【README】【蜂群】

**A14. 下一步三个月做什么？**
① 多人真机数据：现在只有 1 个人、约 170 s 像样的走动；② 蒙眼二选一（2AFC）感知实验做到能报数字；③ 把「世界」开放成 JSON——加一座山只要一份文件，已经有 6 个。【步态 §0】【v3 §2.6.1】

**A15. 最大的风险是什么？**
脉冲在身上感觉不明显。文献说步行时触觉分辨阈值比静止大 3 倍以上。预案：强度调到 2.0（上台阶峰值 2.4 Nm；真机 `--cap 2.5`，再高会被裁）、台阶优先（最短促）、口径改成「腿上的触觉提示」，不硬说「感到地形」。【阈值 §1】【v3 §6】

## 人设 B：Hypershell 工程师

关心：协议用得对不对、安全、控制律依据、对他们产品的价值、会不会误伤品牌。

**B1. 力矩正方向你们怎么确定的？**
数据推断，**待真机验证**：+3 Nm 时双髋角同向正漂，推断正 = 髋伸展。右腿原始读数是镜像（平放 L −78.8° / R +77.5°），`convention.py` 里右腿取反。今天上午第一件事就是 +1 Nm 看方向，反了改一个符号。【v3 §2.1、§4】

**B2. 协议写 200 Hz，你们说 183 Hz？**
183 Hz 是 9/22 真机实测到的帧率。我们不依赖固定帧率：控制线程 100 Hz 取最新一帧，数据流 200 ms 没更新就发零。【v3 §2.1、§2.2】

**B3. 100 ms 不续发清零，你们的看门狗有什么意义？**
固件那一道是底线，我们在上面再加两道：控制循环 100 ms 没提交就主动发 `T,0,0`，1 s 就 DISABLE；数据流 200 ms 陈旧也发零。9/22 两次 DISARM 都是主机卡顿触发的，之后把 DISABLE 门限放宽到 1 s（发零仍是 100 ms）。【guard.py 文件头】【架构 v2 §9】

**B4. 松开扳机为什么不 DISABLE？**
DISABLE 会停数据流，步态估计就断了。所以松手只发 `T,0,0` 回 ARMED、数据不断；急停、看门狗 1 s、退出、异常才 DISABLE，而且急停之后必须手动重新上膛。【guard.py】【v3 §1.4】

**B5. 软限 3 Nm 的依据？**
约 0.04 Nm/kg（按 75 kg），是文献髋外骨骼扰动实验最低档 0.08 Nm/kg 的一半，远低于防跌研究的 0.2 Nm/kg。固件 ±7.5 Nm 永远不用满。另外斜率限 50 Nm/s（文献建议 ≤150）。地形控制律自己也把输出裁在 ±3 Nm，不全靠安全层。【v3 §2.2】【遥控 §2】【阈值 §4】【手感 §1】

**B6. 相位怎么估的？没有足底压力。**
只用髋角：极角相位 φ = atan2(−k·ω, θ−θ̄)，置信度 = 相图半径 / 8°，置信度 <0.5 力矩直接归零。周期接受加了半周期锁存（支撑期平台上相位会抖，一步被切两段）和两腿同相检查（坐站时两腿同相）。回放 9/22 录制：穿戴坐站假周期 13 → 0，走动段接住的步 25% → 44%。【v3 §2.3】【步态 §2】

**B7. 脚跟着地在你们相位的哪里？**
暂定估计器相位 0.5，**证据不够、待真机验证**。唯一够长的一段像原地踏步，腰部 az 冲击左右腿差 0.14。今天让 3 个人向前走各 ≥30 s 再跑 `gait_audit.py --hs`，3 人差 <0.05 才改。猜错的后果我们算过：错 0.2 以内伸展脉冲仍在支撑期，要错 0.45 以上才会进摆动期。【步态 §0】【手感 §2】

**B8. 为什么上坡在早支撑推伸展？**
文献：上坡支撑力矩增量主要来自早支撑髋伸肌矩（Lay 2006）；+9° 坡髋正功比平地翻倍以上（Montgomery 2018）；早支撑髋伸脉冲能改变推进冲量（McGrath & Sergi, ICORR 2019）。所以上坡 = 11% 周期处 +1.5 Nm 梯形脉冲，上台阶 = 6% 处 +1.8 Nm 加 68% 处帮抬腿的 −1.2 Nm。【阈值 §3】【v3 §2.4】

**B9. 下坡为什么用制动？**
这是推断，我们标了。文献说下坡主要是膝在吸能，髋的方向没验证过。所以演示以上坡和台阶为主。【阈值 §5】【v3 §2.4】

**B10. 脉冲会不会绊人？**
自动核对了五种脉冲（`scripts/pulse_plot.py`）：梯形、底宽 10–20% 周期、30–90% 不出伸展（抗屈）力矩、正负之间必经 0、峰值 ≤3 Nm；27 组参数边界扫描 0 组不过，参数范围也收紧到推不进摆动期。站着不动、置信度低一律 0 力。全是模拟上的核对，**穿在人身上待真机验证**。【手感 §2】

**B11. 这和我们的 HyperIntuition 是什么关系？会不会说我们的算法不行？**
不替代。黑客松固件把助力换成了直接力矩接口，所以今天腿上只有我们的指令；放到产品里，我们是它上面的应用层和记忆层：它识别「当下是什么动作」，我们加「这座山、这个人喜欢多大力」。孙宽说过外骨骼是「人与物理世界的可编程接口」，我们做的就是这个接口上的一个应用。【技术栈 §6】【愿景 §2、§6】【协议「镜像裁剪说明」】

**B12. 一句话怎么变成参数？大模型乱输出怎么办？**
教练（Claude，结构化输出）只能从当前控制律的参数名里选，输出差值；ShellOS 再把每个参数一次的改动裁到它范围的 15%，不认识的参数丢掉。然后安全员（硬代码）再过一道：力矩参数超软限就裁、30 s 内同一参数最多改 3 次、急停全否。大脑不在 / 超时（12 s）/ 拒答 → 规则表（陡 / 累 → 强度 −0.5；没感觉 → +0.5；早 / 晚 → 峰时 ∓5%），同一种结构、同一套裁剪，卡片上标来源 `claude` / `rule`。单测里假装 Claude 提议强度 +9.0 加一个不存在的参数，结果只剩 +0.45。大模型永远不在 100 Hz 循环里。【interpret.py】【swarm】【v3 §1.1 铁律】

**B13. 共驾（别人推摇杆动我的腿）安全吗？**
满杆 2 Nm、300 ms 缓升（约 7 Nm/s）、松开也缓降，R2 仍是死人开关；单段 ≤10 s 是操作规程（代码没强制）；被控者只能是队友，评委只拿手柄不被控。文献里人控人的实验都有知情同意和安全带，所以我们不对评委做。【puppet.py】【遥控 §4】

**B14. 录制数据怎么用的？隐私？**
9/22 录了 12 段（其中 7 段可用），都是球球本人。只有髋角、角速度、腰部 IMU 和气压，没有图像、没有身份信息，文件名只有时间和代号。用途是离线扫步态门限：1080 档网格。【步态 §1、§3】

**B15. 如果我们给你们开放产品 API，你们最想要什么？**
两样：① 一个带死人开关语义的力矩叠加接口（在你们的助力上叠一个短脉冲，而不是接管）；② 足底或脚跟着地事件——这样我们最大的不确定（HS_PHASE）就没了。**这是我们的建议，不是已有接口。**【v3 §2.3】

## 人设 C：跨赛道终审评委（看 Agent、完整度、现场）

关心：Agent 是不是真的、闭环学习看不看得见、全程稳不稳、为什么是这个方向。

**C1. Agent 在哪？是不是硬编码脚本？**
是一个四角色的蜂群，仪表盘时间线上每一步都看得见（提议 / 同意 / 裁剪 / 否决 / 生效）：教练（Claude）把一句话翻成参数差值；地形导演（Claude）把一句话翻成一条路线；记忆员（代码）对照经验卡库；安全员（硬代码）裁决。记忆 = 经验卡库；规划 = 教练和地形导演；工具调用 = 改控制律参数、注册并切换世界；幻觉控制 = 参数白名单 + 幅度裁剪 + 安全员 + 兜底。最直接的反证：删掉一张已套用的卡，参数立刻反向回退；评委随口说一座山，就多出一座没人见过的山——剧本做不到。【蜂群】【v3 §2.5】

**C2. 规则表兜底，不就是硬编码吗？**
规则表是兜底，不是主路。它和 Claude 输出同一种结构、走同一个安全员和存卡；存下来的卡按步频检索给下一个人，这部分不管来源都是学出来的记录。现场大脑离线时仪表盘蜂群标题会写「大脑离线 → 规则兜底」，卡片显示 `rule`、造的山写「规则模板」、峰哥那句标 `canned`——这时主动说「今天现场走的是兜底」，别等评委翻卡片。【interpret.py】【gen】【展位脚本「9/24 上午要回填」】

**C3. 学习前后差异在哪里看得见？**
三处：① 大屏力矩条下那行直接写着强度 1.5 → 1.0（力矩条是近 1.5 s 峰值，上台阶从 1.8 变 1.2）；② 仪表盘力矩曲线脉冲变矮；③ 删卡后回到强度 1.5（演示完点「恢复」，卡片留给下一位）。下一位步频相近的人走满 6 步，事件流出现「命中经验 #n」，参数自动套用。【展位脚本 1:50】【main.py auto_recall】

**C4. 「下一个人继承」凭什么是步频？**
故意简单、可解释：同控制律 + 步频落在卡片的 ±10 步/分区间 + 卡片启用。步频是换人后走 6 步就能稳定估出来的唯一特征；更复杂的相似度在这点数据量下没法验证。【store.py 文件头】

**C5. 影子是什么？预录的动画吗？**
不是。每登顶一圈，这一圈每一步的时刻记下来，下一位爬的时候影子按这些时刻前进——领先还是落后是真实比较。换人和演示复位都不清影子。【v3 §2.4】【main.py demo_reset】

**C6. 全程会不会崩？**
今晚的验证：模拟模式连续 5 圈登顶、红灯 / 影子 / 登顶 / 复位全通；全套单测全过；9/22 真机上录了 1 小时多数据，期间两次 DISARM 都是主机卡顿触发看门狗、按设计断使能。已知会出问题的地方我们写出来了：无头截图工具会把主循环卡 1.5 s 触发看门狗（所以展位机不跑）；设备复位会自动重新使能。【指挥板 G 节】【v3 §6】
故障注入（模拟，11 种 × 3 次）：断流、ERR,NOT_ENABLED、设备复位、坏帧等 **10 种故障结束后 ≤0.09 s 恢复**，断流时 Guard 0.20 s 内力矩归零；主机卡顿 1.2 s 会触发看门狗 DISARMED，要人工重新上膛——这是故意的。12 段真机录制全栈回放：**0 异常退出、0 DISARM、0 Traceback**。都是模拟故障，真机拔线没测过。【指挥板 F 节、整合节】

**C7. 为什么选外骨骼，不选机械臂这类设备？**
评分表要「设备现场真正动起来 / 戴上」。在主办方可借的设备里，外骨骼是唯一穿在人身上、力直接作用在人身上的；用它的人就是评委本人，现场自举最直接。【评分 §1】

**C8. 创新点一句话，和先例比？**

**C11. 游戏是怎么和腿连起来的？**

**C12. 为什么化身有时候一顿一顿？**

**C13. 红灯停是干什么的？**

**C14. 这个项目离真实用户有多远？**

## 9/23 新增必答（蜂群 / 造山 / 峰哥 / 安全 / 先例）

**D1. 断网了、Claude 不可用怎么办？**

**D2. 安全员为什么不用大模型？**
因为它是会伤到人的那一道闸，必须可预测、可测试、每次结果一样。大模型负责「听懂人话、出主意」，安全员负责「不管听成什么都不许越线」：力矩参数超软限就裁到软限；30 s 内同一参数最多改 3 次（防几个人来回拉锯）；急停中一律否决；造山时起步必须平地、台阶不过半、红灯 ≤2、总长压到 20–80 步、不认识的路段丢掉。这些全是单测覆盖的确定规则，交给大模型就测不全了。再往下还有 Guard 的软限 3 Nm 和斜率限，所以就算安全员有 bug，腿上也过不了 3 Nm。【main.py safety_review】【gen】【swarm】

**D4. 外骨骼会不会伤人？**
我们把安全放在第一层：只有一个模块能写串口；软限 3 Nm，约 0.04 Nm/kg，是文献扰动实验最低档的一半，固件硬限 7.5 Nm 永远不用满（官方标称峰值扭矩 22 N·m）；斜率 ≤50 Nm/s，只打梯形脉冲；不按扳机就没有力，松手立刻归零；步态置信度低（站着、坐下、乱晃）一律 0 力；控制循环卡 100 ms 发零、1 s 断使能；急停后必须手动重新上膛。共驾时被推的只能是队友，评委不被别人推。9/22 真机上看门狗触发过两次，都按设计断了使能。**还没在人身上验过的**：力矩方向和脉冲手感，今天上午第一件事就是 +1 Nm 验方向。【v3 §2.2、§4】【项目介绍 §6】

**D5. 和 Holotron 这些先例有什么区别？**
Holotron（德，2020）最接近：主动力矩渲染楼梯和斜面，但人挂在 Stewart 平台上、150 Nm、没量产。其它先例：Level-Ups（CHI 2015）是电动高跷靴，改的是脚下高度、不是髋上的力；踝平台、地板和龙门架（PreloadStep、Haptic Ankle Platform、HaptX ForceBot）都不能穿着走；Kinethreads（UIST 2025）能走但没做地形；McGrath & Sergi（ICORR 2019）的相位髋脉冲用在康复不在游戏。我们新在三层同时成立：穿着可走动、只用髋单关节按步态相位打脉冲、消费级量产设备。上面再加一层 Agent：一句话改手感、一句话造关卡、经验传给下一个人。**不说**「首个」。【先例 §4】【项目介绍 §4】

**D6. 一句话造山是怎么做的？Claude 造一座全是台阶的山怎么办？**
地形导演（Claude，结构化输出）出草稿：路段类型只能从 6 种里选，画面风格只能从 5 种现成的里选。草稿里的数字一个都不信：安全员硬代码裁剪——起步不是平地就补 2 步，台阶过半就从后往前改成坡，红灯多于 2 个删掉，单段 ≤20 步，总长压到 20–80 步。自检里喂过一份恶意草稿（9 段各 999 步台阶 + 4 个红灯 + 一个不存在的「lava」路段），出来的是一座能走的山。造出来的山用的是同一套核对过的脉冲，没有新的力矩形状；只在内存里，最多留 8 座。Claude 造山的质量和用时**待 9/24 上午实测回填**。【gen】【swarm】

**D7. 为什么叫「峰哥亡命天涯」？蜂群又是什么梗？**
峰哥（B 站 UP 主峰哥亡命天涯）的口头禅是辩证反转：坏事先说「这是个好事儿啊」——爬山腿酸、遇红灯、输给影子，都能被他说成赢，正好当登山解说。他本人今天也在现场。「蜂群」是四个 Agent 角色的名字，巧的是峰哥当年合伙的公司就叫「蜂群文化」。控制软件还叫 ShellOS。【队友跟进】【claude_brain.py】

**D8. 大模型慢，会不会拖累腿上的控制？**
不会。Claude 在单独的大脑进程里、按需秒级调用，永远不在 100 Hz 控制循环里；峰哥解说在后台线程调，不卡循环；造山、改参都是「生成 → 裁剪 → 一次性生效」。真机上控制循环最大间隔 12 ms，一拍 <1 ms。Claude 各环节延迟**待 9/24 上午实测回填**。【v3 §1.3、末节】【fengge.py】
