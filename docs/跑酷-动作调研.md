# 跑酷动作调研：为什么僵硬、怎么改（R 线，9/23 晚）

球球看了 `/parkour` 的原话是「人物动作太僵硬了」。这份文档先找僵硬的原因，再列出能用的做法，最后排 5 轮，每轮做一个看得见的改进。

## 0. 现在为什么僵

跑酷直接调用了登山游戏的 `av.animate()`（A2 的 `anim.js`）。那套动作是给**走路爬山**调的，放到 35 km/h 的屋顶狂奔上，问题一眼就能看出来：

| 现象 | 原因（代码位置） |
|---|---|
| 跑得飞快，腿却像散步 | 腿直接用真实髋角：模拟器是 ±20°，真人走路大约 30° 峰峰值。跑步需要 55–70°（下面 §1）。膝盖摆动时最多屈 55°（`KIND.flat.kSw`），跑步要 90° 以上 |
| 身体像一根竖着的棍 | 躯干前倾是固定的 3°（`KIND.flat.lean`），和速度无关。跑步应该前倾 8–15° |
| 手臂小幅度晃 | 摆臂只跟对侧髋角差走，系数 0.9，肘常弯 4°。跑步要肘弯 80–90°，前后猛摆 |
| 起跳 / 落地没有过程 | 起跳时整个 group 只转 −0.12 rad、滑铲转 1.05 rad，是硬转；身体姿态从地面到空中完全不变，落地也没有压缩 |
| 滑铲像整个人被推倒 | 只转了根节点，腿、手、头都还是跑步的姿势 |
| 没有跟随和过冲 | 身上没有任何会甩的东西。换道时身体直接平移，不会先倾斜 |

一句话：**骨架层没问题（A2 的骨骼约定、零点校准、头部稳定都是对的），缺的是「跑」这一层，还有起跳、落地、滑铲这些动作阶段。**

## 1. 调研：三件事

### 1.1 程序化跑步循环

**参考**：跑步生物力学综述 Novacheck 1998（*The biomechanics of running*，Gait & Posture 7）；动画实践 Williams《The Animator's Survival Kit》里的跑步循环；David Rosen 在 GDC 2014 的演讲 *An Indie Approach to Procedural Animation*（Overgrowth 用很少的关键姿态加弹簧插值，做出全程序化的跑跳）。

跑步和走路的关键区别（数字取中速跑，约）：

- **有腾空期**：两只脚同时离地，所以重心起伏比走路大（6–10 cm，走路约 3–4 cm），最低点在支撑中期（膝盖压得最弯的时候），最高点在腾空。一步起伏一次，也就是髋角周期的 2 倍频。
- **髋**：屈大约 +45°，伸大约 −15°，峰峰值 55–70°，速度越快越大。
- **膝**：摆动期屈 90–110°（脚跟往屁股收），支撑中期还有 35–45° 的缓冲屈曲，落地时不是直腿。
- **躯干**：前倾 5–15°，随速度增大（Rosen 的做法：前倾 = 加速度 + 速度的函数，加速时多倾）。
- **手臂**：肘弯 80–90°，和对侧腿同相、和同侧腿反相，前摆时手到胸口高度。
- **骨盆**：绕竖直轴转（跟着前摆腿转 ±5–8°），摆动侧下沉；左右晃动比走路小，跑起来脚落在身体中线附近。
- **头**：抵消躯干的所有转动，视线水平。人眼会去稳定地平线，头一晃就像机器人。A2 已经做了，保留。

**怎么在这个项目里做**：**步点对真人，幅度按跑速放大。** A2 的原则是「腿忠实于真实髋角」，跑酷不能把它扔掉：穿外骨骼的人迈哪条腿，屏幕上就迈哪条腿。办法是以真实髋角的均值为中心，放大它的摆幅：

```
髋_画面 = 均值 + g · (髋_真实 − 均值)，   g = clamp(目标峰峰值(跑速) / 真实峰峰值, 1, 2.2)
```

这样相位、节奏、停步都跟真人一样，只有幅度是「跑」的。膝、骨盆、躯干、手臂在 A2 算出来的基础上**叠加一层跑步修正**。修正的大小由两样东西决定：跑步程度 r（按速度 0→1），和每条腿的摆动程度（髋前屈的角速度，A2 也是这样判摆动期的）。

**three.js 里怎么接**：只用现有依赖（`three.module.js` + `GLTFLoader` + `BufferGeometryUtils` + `STLLoader`，vendor 里没有 IK 插件，也不需要）。挂钩点是 `av.body.update`：`avatar.js` 每帧调 `body.update()` 拿到姿态表 `P`（度数和米，约定都在 `anim.js`），然后套到骨骼上。跑酷把这个函数包一层，**在 `P` 套到骨骼之前改它**。骨骼轴向、父子换算、手臂的 Rx·Rz 顺序这些 A2 量过的约定一个都不碰，也不用改 `avatar.js` / `anim.js`。

### 1.2 起跳和落地：预备、缓冲

**参考**：迪士尼 12 条动画原则里的 *anticipation*（预备）、*squash & stretch*（压缩与拉伸）、*follow-through*（跟随）、*slow in / slow out*；跳远 / 跑酷的落地缓冲（屈膝 40–60°、0.1–0.2 s 吸收冲击，再回弹）。

一次跳跃分 5 个阶段：

| 阶段 | 时长 | 身体 |
|---|---|---|
| 预备（蓄力） | 起跳前约 2 帧（≈ 0.07 s），要跳的障碍很近时从 0.25 s 前就开始往下沉 | 骨盆下沉 8–12 cm，双膝屈，躯干前倾加大，双臂往后拉 |
| 蹬伸 | 起跳后 0.1–0.15 s | 支撑腿伸直（拉伸），摆动腿高抬，双臂往前上甩 |
| 腾空收腿 | 到最高点 | 双髋屈、双膝收（团身），手臂张开保持平衡 |
| 落地前伸腿 | 下落段 | 腿往下伸去「找地」，膝微屈 |
| 落地压缩 → 回弹 | 0.1 s 压、0.25 s 回 | 骨盆下沉 10–15 cm、膝屈 40–60°、躯干前倾；用欠阻尼弹簧回到跑姿（有一点过冲）。落地那帧镜头跟着下沉 5–10 cm |

**现在的物理不能动**：`logic.js` 里按下跳（或高抬腿被识别出来）那一帧 `vy` 就给满，`/terrain/force` 的 lift 窗口（前方 0.9 s 内要跳就发 lift）一个字都不改。所以预备只能靠两个来源：① 画面层**预判**：前方下一个要应对的是「跳」，而且离得很近，就提前开始下沉；② 起跳后前 0.07 s 在画面上做一次「压 → 伸」，模型相对物理位置往下偏一点，物理不改。

### 1.3 次级运动：跟随和过冲

**参考**：Rosen GDC 2014（身体每一节都用弹簧追目标，天然有滞后和过冲）；Jakobsen 2001 *Advanced Character Physics*（Hitman 用的 Verlet 质点 + 距离约束，布料、绳子十几行就能写完）。

- **衣角 / 背包带 / 围脖尾巴**：一条 4–5 个点的 Verlet 链，根部钉在骨骼上（胸口 / 腰后），受重力、空气阻力，加上奔跑的迎风（往后吹），段长约束迭代 2–3 次。画成一条跟着链子走的细带，一次绘制。跑的时候往后飘，急停往前甩，起跳时往下拖，落地往上弹，过冲是自己出来的。
- **转向先倾**：换道时，身体先往新车道那边倾（按横向加速度，绕前后轴转 group），脚再过去。反过来就像被平移。用弹簧，回正时有一点过冲。
- **头部滞后**：头盔 / 峰哥头对躯干的加速度有一点延迟（阻尼弹簧），幅度要很小，要不然像点头娃娃。

**写法**：弹簧统一用临界阻尼或欠阻尼的二阶弹簧（`x'' = ω²(目标 − x) − 2ζω x'`），用半隐式欧拉。时间步大于 1/60 s 时切成小步，这样 `?fx=low` 或掉帧时也不会炸。

### 1.4 过渡

所有「阶段姿态」（跑步程度、预备、腾空、落地、滑铲、转向）都是**权重**，不是开关。权重用指数趋近（τ ≈ 0.07 s，0.2 s 到 95%）或弹簧追目标，所以走 → 跑 → 跳 → 落 → 跑之间没有硬切。要求 0.15–0.25 s 混合，τ = 0.05–0.08 正好落在这个范围里。

## 2. 5 轮计划（每轮一个看得见的改进）

新代码都放在 `static/parkour/runner.js`（新文件），`main.js` 只改调用。`logic.js` 的物理和 `forceKind`（lift 窗口）不动。

| 轮 | 做什么 | 看得见的改进 | 验收（关键帧 / 连拍） |
|---|---|---|---|
| 1 跑步循环 | 包一层 `body.update`：髋摆幅按跑速放大（相位跟真人）；摆动期膝屈到 90°+、支撑期缓冲屈；骨盆 2 倍频上下起伏 + 左右晃 + 竖轴转；躯干前倾 = f(速度)；手臂肘弯 85°、反向大摆；头抵消，保持水平 | 侧面看像在跑，不像在走 | 侧面镜头一个步态周期 8 张连拍，和改之前的对比 |
| 2 起跳落地 | 预备下沉（近障碍预判 + 起跳后 2 帧压 → 伸）、腾空团身、下落伸腿、落地压缩 → 欠阻尼回弹；落地那帧镜头下沉；滑铲改成真正的滑铲姿态（前腿伸、后腿折、手臂后撑） | 跳有「蓄力 → 飞 → 落」 | 起跳前 / 空中 / 落地 3 张关键帧（侧面 + 跟拍） |
| 3 次级运动 | 围脖尾巴 + 背后衣角两条 Verlet 带；换道先倾；头部微滞后 | 身上有东西在飘、转向有重心 | 急停 / 起跳 / 换道各 1 组，看带子的过冲 |
| 4 过渡 | 所有阶段权重统一做平滑（τ 0.05–0.08 s），检查走 → 跑 → 跳 → 落 → 跑、跑 → 滑 → 跑、站 → 起跑、撞 → 减速 → 再加速有没有跳帧；每帧关节角速度加上限，拿来抓硬切 | 没有一帧突变 | 连续 2 s 连拍 + 每帧最大关节角变化的曲线（给出最大值） |
| 5 手感校准 | 起跳的画面节奏和 lift 对上：lift 在摆动期 68% 出力，画面上「那条腿高抬」的那一帧就是起跳帧（自动驾驶 / 键盘起跳吸附到最近的摆动期，最多等 0.1 s；高抬腿识别用 A2 外推后的髋角，少 ~50 ms 延迟）；整体调时长和幅度，fx=low 复测 | 腿上的助力和画面上的抬腿是同一拍 | lift 出力时刻 vs 起跳帧的时间差分布；fx=low / 正常各跑一局看 fps |

**评估方法**（为了能一轮一轮比较）：加一个确定性的动作预览 `?demo=1`：不连 ShellOS、不发任何请求，髋角用 A2 的 `synthHip` 合成（人跑步的曲线），时钟由截图脚本一帧一帧推进，固定种子、固定自动驾驶，外加 `?cam=side` 侧面镜头。每轮用同一段时间、同一个镜头拍，改之前和改之后可以逐帧对比，不受机器负载影响（这台机器负载经常 60–99）。最后一轮再回到 `--sim` 真跑，测 fps。

## 3. 不做的

- 不引外部动画文件（mixamo 之类）和新依赖，不做全身 IK（vendor 里没有，这个视角也用不上脚锁地）。
- 不改 `avatar.js` / `anim.js` / `logic.js` 的物理和 lift 逻辑；要改也不是在这里改，而是写留言给 A2。
- 捷风的动作（`npc_jifeng.js`，J 线的）不在这 5 轮里。它在跑酷里大多数时候不在镜头里。
