## 1. 系统架构

### 1.1 分层与文件归属

```
┌──────────────────────────────────────────────────────────────────────┐
│ 6 提交物    README · 演示视频 · 海报 · 提交表单 · 评委题库               │ docs/提交/
├──────────────────────────────────────────────────────────────────────┤
│ 5 记忆·Agent 经验卡 store · 检索 · 大模型/规则解释 · 换人 · 演示复位       │ shellos/memory/ agent/
├──────────────────────────────────────────────────────────────────────┤
│ 4 界面      4a 登山游戏  /game  game.html · game/*.js                  │ shellos/ui/static/game*
│             4b 操作员仪表盘 /   index.html · body3d.js                  │ shellos/ui/static/
│             server.py（标准库 http，/state 10 Hz）                      │ shellos/ui/server.py
│             输入：gamepad.py · hotkeys.py                              │ shellos/input/
├──────────────────────────────────────────────────────────────────────┤
│ 3 控制律    terrain(主) · puppet(开场) · dofc · phase · constant · transparent │ shellos/control/
├──────────────────────────────────────────────────────────────────────┤
│ 2 步态估计  相位 · 周期门控 · 步频 · 对称 · 活动度 · 置信度 · 走动中       │ shellos/gait/
├──────────────────────────────────────────────────────────────────────┤
│ 1 安全层    guard.py ★ 唯一写串口的地方                                  │ shellos/safety/
├──────────────────────────────────────────────────────────────────────┤
│ 0 设备      serial_link(真机) · sim(模拟) · replay(回放) · recorder · frame · convention │ shellos/device/
└──────────────────────────────────────────────────────────────────────┘
   装配：shellos/main.py（App = 所有层的挂点）  脚本：scripts/  测试：tests/
```

**铁律**：只有 Guard 写串口；大模型永远不在 100 Hz 循环里；游戏和仪表盘只读 `/state`、只发动作，不碰控制；每层能单独砍。

### 1.2 三种设备模式（同一接口，上层无感）

| 模式 | 启动 | 用途 |
|---|---|---|
| 真机 | `./run-mac.sh --ctl terrain --cap 2.5` | 明天 |
| 模拟 | `--sim`：空格/网页按住走、松开停，步频可调；力矩会让髋角轻微偏移作视觉反馈 | 今晚所有线的开发和验收；展位断电兜底 |
| 回放 | `--replay 录制.csv` | 用 9/22 真机数据调步态、做压测 |

### 1.3 线程与数据流

```
设备线程 183/200 Hz ──► 环形缓冲 ──► 控制线程 100 Hz ──► Guard ──► T,l,r
                                     gait.update → ctl.step → guard.submit
                                     每 0.5 s：auto_recall · 状态行 · loop_ms
手柄线程 100 Hz ──► deadman("gamepad") · puppet 摇杆 · 按键动作
HTTP server ──► /state（游戏屏 + 仪表盘各 10 Hz 轮询）· POST 动作 → App 方法
Agent 按需（秒级）──► interpret(quote) → ctl.set_params + store.add
录制随设备线程 ──► data/recordings/<时间>-<人>.csv + .marks.csv
```

实测（真机）：控制循环最大间隔 12 ms；一拍计算 <1 ms。**游戏屏的 3D 渲染在浏览器进程里，会抢 CPU**——验收项里必须看 `loop_ms` 不上升。

### 1.4 状态机

```
Guard:   CONNECTED → ARMED ⇄ ACTIVE   （deadman 松开 → T,0,0 回 ARMED，数据流不断）
                      └ estop / 看门狗 1 s / 退出 → DISARMED（DISABLE）→ rearm → ARMED
Link:    enabled ← OK,ENABLE / OK,DISABLE / ERR,NOT_ENABLED / 开机日志；断流 >1 s 或未使能 → 每 2 s 重发 ENABLE；检测到设备复位 → 立即重发
         拔线 → 每秒重开串口，最多 60 s
Gait:    静止 ─conf>0.5 连续 0.3 s→ 走动中 ─conf<0.5→ 静止
Terrain: 每个被接受的周期 pos+1；到顶 → laps+1、记用时、这一圈成为影子；force 覆盖路段
Memory:  换人 → 参数缺省、影子保留 → 走 6 步 → 检索套用
```

## 2. 各层规格

### 2.1 设备层

- **真机**（已验证）：`/dev/cu.usbserial-*`（CP2102N），3 Mbps，`timeout=0.05`；握手 PING→VERSION→ENABLE；应答计数、使能状态、复位计数、断流恢复、拔线重连（重连**未真机验证**）
- **恢复**（`main.recover_tick()`）：检测到设备复位立即重新 ENABLE，否则每 2 s 重试；`reboots` 只在已使能时 +1；`_wlock` 为 RLock（信号处理里的 DISABLE 不会和 send 死锁）。**回放故障注入验证**：复位后 ≤0.04 s 重新使能；真机未验
- **模拟**：`sim.py`，200 Hz，正弦髋角（左右反相，摆幅 20°），走停 0.25 s 过渡，步频 60–140；`/sim {"walk":bool,"cadence":n}`（只认本机 POST）
- **回放**：绝对时刻步进；12 段真机录制在 `data/recordings/`（不进仓库）；CSV 坏行跳过并计数（181327 有 1 行）；故障注入 `SHELLOS_FAULTS="gap@t:dur,noten@t,reboot@t:dur,bad@t:dur,stall@t:dur"`，回放模式同样走恢复逻辑
- **录制**：frame / torque 两种行都是 19 列，写入加锁（9/22 的粘行就是没加锁造成的）。今晚 `--sim` 录 8 s 读回 0 坏行（模拟）
- **全栈压测**：`scripts/stress.py stack`（回放 + /state 采样）、`stress.py matrix`（11 种故障 × N 次）
- `convention.py`：右腿 `R_SIGN=-1`（真机：平放 L −78.8 / R +77.5）；正力矩 = 髋伸展（**数据推断**，+3 Nm 时双髋角正漂，待穿上验）

### 2.2 安全层（真机 + 单测）

| 规则 | 值 | 来源 |
|---|---|---|
| 软限 | 展位 4 Nm（启动参数 `--cap 4`，不带参数 3 Nm；≈0.05 Nm/kg） | 低于文献扰动实验最低档 0.08 Nm/kg |
| 斜率 | 50 Nm/s | 文献 ≤150 Nm/s |
| 死人开关 | 多来源取最大；按压深度缩放 | |
| 置信度门控 | conf<0.5 → 0 | |
| 看门狗 | 100 ms → T,0,0；1 s → DISABLE | 固件 100 ms 自清零兜底 |
| 断流 | 200 ms → 0 | |
| 退出 / 急停 | 必 DISABLE；急停要重新上膛；DISARMED 时 `arm()` 拒绝，只能 `rearm()` | 单测 |
| 控制来源 | 所有 POST 只认 127.0.0.1 / ::1，局域网一律 403（只能看 /state、/game）；全局键盘热键默认关（`--hotkeys` 才开，且没有「R = 上膛」） | 今晚实测 |
| 地形自裁 | terrain 输出自己先裁到 ±3 Nm，再过 Guard | 单测 |

今晚验证（单测 + 回放故障注入，**非真机**）：Guard 锁改 RLock 后 SIGTERM 30 次 0 次卡死（原来约 1/12 死锁、DISABLE 发不出去）；断流 / 坏帧 0.20 s 归零（立刻 T,0,0，不走斜率）；10 种故障结束后 ≤0.09 s 恢复；主机卡顿 1.2 s → 看门狗 DISARMED、不会自己恢复（按设计）；12 段回放 × 20 s 0 次 DISARM。**以上规则今晚一条都没有放宽。**

### 2.3 步态估计（真机录制回放验证）

- 极角相位 `φ = atan2(−k·ω, θ−θ̄)`；置信度 = 相图半径 / 8°（`--stepping` 时 4°）
- 周期接受（9/23 新默认）：0.8–2.2 s、半周期锁存（一步不再切两段）、活动度 ≥15°、两腿必须反相（同相 = 坐站弯腰，拒）；去掉了整周期最低 conf。**回放**：穿戴坐站假周期 13 → 0；走路段只接住约 1/3–1/2 的步（181327 覆盖率 0.44），**地形前进约为实际步数的一半**
- 走动中：conf>0.5 连续 0.3 s，且没有「某腿 0.3 s 相位不推进」、没有「两腿同相」。**回放**：非走路时误判走动中 162 → 3 s（穿戴）；走→坐以后最长连续出力 ≤0.41 s（原来 4.9 s）
- 步频 = 最近周期中位数（回放中位 108 步/分，P10–P90 77–125）；对称比 = 两腿活动度比（1 = 对称）
- **HS_PHASE = 0.5 仍未验证**（证据不够，唯一够长的走路段像原地踏步）：明天 3 人向前走各 ≥30 s 后 `gait_audit.py --hs --rec`
- **原地踏步**：`--stepping`（活动度 ≥8°、置信参考半径 4°）。**模拟**：±8° 以上 100% 接住，不规整 ±6° 走动中只 23–35%，±4° 接不住；**回放**安全项和默认一样（最长连续出力 0.41 s、穿戴假周期 0）。真人踏步**没有真机数据**；「坐着两腿交替晃 ±6°」踏步模式会接受，靠死人开关

### 2.4 控制律

**terrain（主）**：相位按文献约定（脚跟着地 = 0%）

| 路段 | 脉冲 | 峰值 (strength 1.5) | 中心 | 半宽 | 依据 |
|---|---|---|---|---|---|
| up | 伸展 | +1.5 | 11% | 12% | 文献（Lay 2006；Montgomery 2018） |
| down | 制动 | −1.2 | 10% | 12% | 推断 |
| stairs_up | **阻力**：支撑期往屈曲拉；摆动期不出力（防脚尖勾台阶） | −1.8 | 6% | 12% | 9/23 球球真机反馈（上楼要阻力） |
| stairs_down | **助力 + 落阶冲击**：脚跟着地屈曲冲击 + 早支撑伸展助力 + 摆动期帮迈腿 | −1.5 / +1.5 / −1.2 | 0% / ≥12% / 68% | 冲击 10%（底宽），其余 12% | 同上 |

梯形；摆动中段不加抗屈；参数范围 `t_push/t_brake/t_step` 0–20、`width` 10–20；输出自裁 ±3 Nm。**模拟**实测峰值（strength 1.5）：up +1.5、红灯 −0.75 Nm，和表一致；台阶两行 9/23 按真机反馈反过来后由 `terrain.pulse()` 算（stairs_up −1.8；stairs_down −1.5 / +1.5 / −1.2），落阶冲击经 Guard 斜率限制是约 60 ms 的顿挫。展位启动参数 `--cap 4 --strength 3.0 --width 16`，峰值翻倍（上台阶 −3.6 Nm）；**手感全部未真机验证**（正力矩 = 伸展仍是数据推断）。
**红灯（wait）**：走着被 −0.75 Nm 轻拉、pos 不前进；放行 = 没有新接受的步 + 两腿角速度 RMS < 20°/s 连续 1.5 s（`wait_need`），距上一步 6 s 无论如何放行。**回放**复算停步→放行中位 2.2 s（1.8–4.7 s）；**模拟** 2.0 s。
每圈计时，登顶后这一圈成为影子；**每个世界各存各的影子 / 最佳**（`Terrain.memory`，换世界、换人都不丢）；`status()` 给游戏：`preset, world, pos, total, laps, segment, label, next{label,kind,in}, wait_still, wait_need, altitude, force, segments, profile[], elapsed, best, last_lap, ghost_pos, ghost_who`。

**puppet（开场共驾）**：摇杆 → 力矩，2 Nm 满，缓升 ≥300 ms；单段 ≤10 s；被控者只能是队友。
**dofc / phase / constant / transparent**：备用与调试。

### 2.5 记忆与 Agent

经验卡（JSON 行）：`id, ts, wearer, controller, trigger{cadence}, delta, quote, confidence, hits, enabled, source`。解释：Claude（经大脑进程 `brain/claude_brain.py`，见下文「大脑与蜂群」）→ 规则表（早/晚/轻/重/左/右/陡/累/没感觉/反了；否定和「更/再/还」优先，同一参数只取第一条，差值 0 不存卡；「轻一点」−0.5、「重一点」+0.5；23 句写在 `tests/test_interpret.py`）；步频还没估出来时不写卡、不改参；检索：同控制律 + 步频区间，已套用的卡不再叠加，多卡同一参数取平均；删卡回退（仪表盘可「恢复」）；换人参数回缺省、影子 / 最佳保留；强度阶梯可 `POST /memory/add` 写卡。大脑没开 / 断网 / 超时 → 规则表（卡片 source=rule）；规则仍是关键词匹配（「不累」会算 −0.5）。

### 2.6 登山游戏（新，4a）——今晚最重的一条线

**目标**：评委不看任何曲线，只看这一屏就懂"我在爬山、腿被推了、上一个人在我前面"。

| 模块 | 规格 |
|---|---|
| 页面 | `/game`，全屏，暗色，1080p 与 4K 投屏都清楚；Three.js 本地（离线可用），`pixelRatio=1`、不开阴影，保 60 fps |
| 山与路 | 由 `terrain.segments` 程序生成：每步水平 0.5 单位；坡每步升 0.08（≈9°）；台阶每步升 0.12，用方块成阶；两侧高度场山体 + 远山剪影 + 雾；起点营地、山顶旗帜 |
| 化身 | CesiumMan，身体动画用**真实髋角**（复用 body3d 骨骼映射）；位置 = `pos` + 周期内进度（由相位插值），平滑跟随；朝向沿路径切线 |
| 影子 | 半透明第二个化身（或发光剪影），位置 = `ghost_pos`，头顶标"上一位：{ghost_who}"；领先/落后几步 |
| 镜头 | 第三人称侧后方跟随，上坡时略抬、台阶时拉近；登顶环绕一圈 |
| HUD | 海拔（米，虚拟高度 × 系数）· 第 n/N 步 · 当前路段 · **前方预告**（"2 步后：台阶"）· 左右腿力矩条（脉冲时闪）· 用时 / 最佳 · 登顶次数 · 穿戴者 · 安全状态小灯（ACTIVE 才有力） |
| 事件动效 | 脉冲 → 脚下波纹 + 路段高亮；登顶 → 旗帜、彩带、用时、"已写入山的记忆"；经验卡命中 / 新卡 → 侧边滑入卡片 |
| 输入 | 模拟模式：按住空格走、松开停，`1/2/3` 慢/中/快；真机模式由步态驱动；`R` 回山脚（= 演示复位） |
| 数据 | 只读 `/state`（10 Hz），60 fps 插值；动作只发 `/sim`、`/demo/reset`、`/terrain` |
| 验收 | `--sim` 下完整爬一圈 → 影子出现 → 第二圈影子在跑；1080p 截图 3 张（山脚 / 台阶 / 登顶）；浏览器 FPS ≥50；同时 `loop_ms` 不高于不开游戏时 +5 ms |
| 今晚结果（模拟） | 圈 / 影子 / 红灯 / 登顶 / 共驾画面都过；截图在 `/tmp/shellos-shots/G/`、`fixG/`；开发机（i5-7400 核显）1080p 50–58 fps；loop_ms 中位 +1 ms 达标，**p95 +5–9 ms 在线上或略超**；无头 swiftshader 截图会把主循环卡到 DISARM——展位机别跑 `shot.sh` / `stress.py --game`；**MacBook M2 Pro 和真机驱动都没测** |

### 2.6.1 世界（主题）——数据驱动，加一个世界只要丢一份 JSON

`shellos/worlds/*.json`，地形控制器和游戏共用同一份。字段：`id, name, subtitle, story, note（真实性说明）, alt[起,终], route[{kind, steps, label, turns?}], summit{name,text}, theme{style, sky, fog, ground, path, accent, props}`。路段类型新增 **wait（红灯）**：走着会被轻拉、位置不前进，站稳 1.5 s 放行（6 s 兜底，见 2.4）。

| 世界 | 路段构成（步） | 画面 | 为什么 |

## 大脑与蜂群（9/23 加，跨赛道加分层）

**为什么单独一个进程**：anthropic SDK 1.x 要 Python ≥3.10，展位 MacBook 是 3.9；ShellOS 零新依赖；MacBook 直连 api.anthropic.com 返回 403。
所以 Claude 只在大脑进程里调（`brain/claude_brain.py`，官方 SDK，`claude-opus-5` + adaptive thinking + 结构化输出 + `fallbacks: "default"`），
跑在能连上 Anthropic 的那台机器；MacBook 走 SSH 反向隧道访问 `127.0.0.1:8790`。腿上的安全链路（Guard）完全不经过大脑。

```
本机：  export ANTHROPIC_API_KEY=…
        brain/.venv/bin/python brain/claude_brain.py          # 首次：python3 -m venv brain/.venv && brain/.venv/bin/pip install anthropic
        ssh -N -R 8790:127.0.0.1:8790 zhongrenfei@100.112.252.66
MacBook：./run-mac.sh …（SHELLOS_BRAIN 默认 http://127.0.0.1:8790，不用设）
```
