# 游戏主题接口（`shellos/ui/static/game/themes/`）

给今晚做地图精加工的人看的。引擎（`game/*.js`、`game.html`）负责路面、台阶、红灯、化身、影子、镜头、HUD；**主题只负责"这条路周围是什么世界"**：天空、雾、光、地面、远景、道具、动效。

- 世界 JSON（`shellos/worlds/<id>.json`）里 `theme.style` 决定加载哪个主题：`themes/<style>.js`。现有 5 套：`cyber_night`（东京）、`dawn_mountain`（泰山）、`night_to_dawn`（富士山）、`subtropical`（梧桐山）、`grid`（两个训练场）。
- 主题加载失败会退回 `grid`；`build` 抛错时场景照常起（只是缺东西），`update` 抛错后引擎不再调用它。三种情况都写进页面的 errlog，用 `scripts/dom.sh` 能读到（见文末）。

## 1. 文件与子模块

```
themes/
  kit.js                 公用小工具（天空、雾、高度场地面、远山剪影、噪声、网格贴图）
  cyber_night.js         主题入口（引擎只 import 这个）
  cyber_night/           可选：这个主题自己的子模块
    signs.js
    rain.js
```

- 子模块用相对路径 import：`import { buildSigns } from './cyber_night/signs.js';`
- 可以直接 `import * as THREE from 'three'`（页面有 importmap，指向 `static/vendor/three.module.js`，r160），也可以用 `ctx.THREE`，是同一个对象。`three/addons/` 下只有 `GLTFLoader.js`、`BufferGeometryUtils.js`、`OrbitControls.js`。
- **单个主题（入口 + 子目录）≤ 200 KB**。不从网上拉模型、贴图、字体；运行时不连外网。纹理全用 Canvas 画（`ctx.util.canvasTexture` / `textTexture`）。
- 只改自己主题的文件。缺帮手函数就写在指挥板上，由引擎维护人加进 `game/util.js`，别加进主题里。

## 2. 导出

```js
export function build(scene, ctx) { … }          // 必须。场景搭建，只调一次
export function update(dt, st) { … }             // 可选。每帧调用（60 fps），做动效
export function pathMaterials(ctx) { … }         // 可选。在路面/台阶建出来之前调用，返回 { road?, stairs? } 替换缺省材质
```

调用顺序：`import 主题` → `pathMaterials(ctx)`（此时 `ctx.meshes === null`）→ 引擎建路面/台阶/红灯/营地/旗 → `build(scene, ctx)` → 加载化身与影子 → 每帧 `update(dt, st)` → 渲染。

## 3. `ctx`（`build` 和 `pathMaterials` 拿到的）

| 字段 | 内容 |
|---|---|
| `THREE` | three.js 模块 |
| `scene` | 场景（同 `build` 的第一个参数） |
| `world` | 整份世界 JSON（`id, name, route, summit, alt, theme…`） |
| `theme` | `world.theme`：`style, sky[顶, 底], fog, ground, path, stairs?, accent[3], props[], ghost?, ghostOpacity?, ghostLat?, avatar?`。引擎在 `build` **之后**才读 `ghost* / avatar`，所以主题也可以在 `build` 里直接改 `ctx.theme.avatar = {…}` |
| `route` | 路线几何（见 §4） |
| `steps` | `route.steps` 的简写：每步的世界坐标 / 朝向 / 路段（见 §4） |
| `meshes` | 引擎建好的路面对象（见 §5）；`pathMaterials` 里是 `null` |
| `lights` | `{ hemi: HemisphereLight, sun: DirectionalLight }`，主题可改颜色和强度；太阳位置引擎已摆在路线中心上方 |
| `camera` | PerspectiveCamera（fov 52，near 0.1，far 1200）。**位置由引擎每帧设**，主题只读 |
| `camRig` | 镜头参数（`game/camera.js` 的 `defaultRig()`），镜头每帧读，**主题可以在 `build` 里改数值**（见 §5.2） |
| `renderer` | WebGLRenderer。pixelRatio=1、阴影关，**主题别改**这两个 |
| `kit` | `themes/kit.js`：`sky, fog, terrain, ridge, gridTexture, noise2, fbm, hash2, mixHex, routeCenter` |
| `util` | `game/util.js` 引擎帮手（见 §6） |
| `preview` | 是否离线预览（`/game?preview=…`） |
| `rand` | 按世界 id 播种的随机数（mulberry32），**摆道具一律用它**，同一世界每次打开一样 |

## 4. 路线：`ctx.route`

坐标：y 向上；起点在原点，大致朝 +X 走；**left = 行进方向左手边**；1 步水平 `STEP = 0.5`；路宽 `ROAD_W = 2.2`；起点前、终点后各有 `APRON = 8` 单位平台（营地、登顶平台）。模型朝向用 `obj.rotation.y = -heading`。

| 字段 / 方法 | 内容 |
|---|---|
| `N` | 总步数 |
| `steps[i]` | `{ i, kind, label, seg, h0, h1, top, p0, p1, mid, heading }`：`kind` ∈ `flat / up / down / stairs_up / stairs_down / wait`；`h0/h1` 起止高度；`top` 踏面高度（台阶 = 顶面，坡 = 中点）；`p0/p1` 本步起止的路中心（Vector3，只读别改）；`mid` 踏面中心；`heading` 朝向（弧度） |
| `segs[j]` | `{ kind, label, start, steps, turns }`：第 j 段从第 `start` 步开始 |
| `P[i]` | 第 i 步起点的路中心（`P[N]` = 终点），`H[i]` = 第 i 步朝向 |
| `at(s, lateral = 0, out?)` | 连续步数 `s`（可以 < 0 或 > N，落在两端平台）处的 `{ pos, dir, left, heading, i, kind }`；`lateral` = 向左偏移（负 = 右）。高度 = 化身脚下高度（台阶取顶面） |
| `heightAt(s)` / `headingAt(s)` | 同上，单取高度 / 朝向 |
| `poly` | 每步一点的折线 `[x, z, y]`（含两端平台），地面高度场用 |
| `center` | 细采样中心线 `[[x, z], …]`（每步 8 点） |
| `hmax` | 最高点高度 |

路中心线是平滑的（朝向积分），路沿不会在步边界折。化身在路中心左 0.35，影子在右 0.5（`theme.ghostLat` 可改，引擎把它夹在离路沿 ≥ 0.4 以内，身体不会碰栏杆）。

## 5. 引擎建好的路面：`ctx.meshes`

| 字段 | 内容 |
|---|---|
| `group` | 全部路面对象的父节点 |
| `road` | 连续路面（平地/坡/红灯段/两端平台），Mesh，缺省 `MeshLambertMaterial(theme.path)`。**带 `uv`（世界单位）**：`u` = 横向，左沿 +1.1 → 右沿 −1.1；`v` = 沿路距离 `s × STEP`（起点 0，营地平台为负）。贴图设 `RepeatWrapping` + `repeat` 调密度；要按世界 xz 贴就自己覆盖 `uv` 属性 |
| `stairs` | 台阶方块，InstancedMesh；第 n 个实例 = 第 `stairIndex[n]` 步。几何带顶点色（踏面 1.0、立面 0.6），和 `instanceColor`（缺省 `theme.stairs ‖ theme.path`，隔级 ×0.88）相乘 |
| `stairIndex` | 台阶实例 → 步号 |
| `lines` | 每步刻度线，LineSegments + 顶点色：第 i 条（顶点 `2i`、`2i+1`）= 第 i 步起点，`i = 0…N`；缺省 accent[1]×0.55，台阶 accent[2]。不想要：`lines.visible = false` 或降 `lines.material.opacity` |
| `edges` | 两侧路沿，LineSegments，**材质色**（缺省 accent[0]、不透明度 0.45）：改色 `edges.material.color.set('#…')`，关掉 `edges.visible = false`。线恒为 1 px（WebGL 限制），3 米外看不清——要醒目的路沿/步点用路面 `uv` 画色带 |
| `startLine` | 起点横线（Group，accent[1]），不要就 `visible = false` |
| `signals[]` | 红灯：`{ seg, group, stop, red, green, state, set('red'/'green') }`；`group` = 路右侧的车用灯杆，`stop` = 停止线。引擎按位置自动切 `state`，主题别改状态。**换成自己的信号灯**：`build` 里 `sig.group.visible = false`，`update` 里每帧读 `ctx.meshes.signals[k].state`（`'red'`/`'green'`）驱动自己的灯；站定进度读 `st.terrain.wait_still / wait_need`（预览里用 `&still=秒` 模拟） |
| `camp` / `flag` / `cloth` | 起点帐篷 / 山顶旗 / 旗面（旗面会飘）。旗在终点后 2.2 步、**路右沿外 0.3**（不在行进中线上）。城市主题可以 `camp.visible = false`、`flag.visible = false` |
| `acc` | `theme.accent` 转成的 3 个 Color |

### 改路面 / 台阶的样子（暗色主题台阶太暗就在这里修）

三种办法，从轻到重：

1. **世界 JSON 加 `theme.stairs`**：台阶踏面颜色，例如 `"stairs": "#6a6f86"`。不写代码。
2. **`build` 里改实例色 / 材质属性**：`meshes.stairs.setColorAt(n, color)` 后 `meshes.stairs.instanceColor.needsUpdate = true`；或 `meshes.stairs.material.emissive.set('#221a33')` 给一点自发光（东京现在就是这么做的）。
3. **`export function pathMaterials(ctx)` 整个换材质**：

```js
export function pathMaterials({ THREE, theme }) {
  return {
    road: new THREE.MeshLambertMaterial({ color: theme.path, emissive: '#0c0a18' }),
    stairs: new THREE.MeshLambertMaterial({ color: '#ffffff', emissive: '#1a1030' }),   // 颜色仍按 instanceColor × 顶点色
  };
}
```

引擎会在你给的 `road` 上补 `side: DoubleSide` + `polygonOffset`（防止地面穿出路面），在 `stairs` 上开 `vertexColors`（踏面/立面明暗）。别用 `transparent`，台阶会和化身排序打架。

**台阶和坡必须一眼看出来**：踏面要比立面亮、比地面亮；坡的刻度线别被道具盖住。

### 5.2 镜头 `ctx.camRig`、化身配色 `theme.avatar`

`ctx.camRig`（缺省值；`build` 里改，镜头每帧读）：

```js
follow: { back: 4.6, backStairs: 3.7,      // 在化身后多远
          side: 1.4, sideStairs: 1.2,      // 向左偏（镜头在化身左后方）
          height: 2.1, upBonus: 0.45, stairsBonus: 0.25,
          clear: 1.7,                      // 离镜头正下方那段路面至少多高（下台阶走完不贴踏面）
          ahead: 1.6, lookY: 0.95, lookUp: 0.25,   // 看点：化身前 ahead、离地 lookY（上坡 +lookUp）
          slopeLook: 0.6 },                // 看点跟前方路面起伏：上台阶略仰（看到整段台阶）、下台阶略俯
summit: { center /* = route.at(N + 1.2).pos */, radius: 5.2, height: 2.3, lookY: 1.1, speed: 1.0 /* rad/s，6 s ≈ 一圈 */,
          face: null }                     // Vector3：环绕开始时镜头正对着看的点（太阳、山门），缺省从化身背后开始
```

跨路的门、牌楼要离环绕中心 > `radius`；高地标落在 HUD 上沿下面时，可以加大 `follow.lookY`（看点抬高 → 地标下移）。

`theme.avatar`（世界 JSON，或 `build` 里 `ctx.theme.avatar = {…}`），缺省：

```js
{ leg: '#39424f', body: '#eef2f6', head: '#cfd8e2',   // 三块纯色：腿 = 外骨骼深色、躯干 = 浅色衣服、头盔
  rim: '#8ff0ff', rimK: 0.9,                          // 不吃场景光的轮廓光（fresnel）；浅色场景可以给深色 rim
  self: 0.22, headScale: 0.86 }                       // 自发光比例（夜里不被染成深蓝）、头盔缩放
```

## 6. 引擎帮手：`ctx.util`（`game/util.js`）

| 函数 | 用途 |
|---|---|
| `canvasTexture(w, h, draw(g, w, h), { repeat })` | 任意 Canvas 画的贴图（窗户格、路面纹理、噪点）。`repeat: true` 可平铺 |
| `textTexture(text, o)` | 文字贴图，`tex.userData.aspect` = 宽/高。`o`: `size`(px, 缺省 96) `weight` `font` `color` `bg` `border` `glow`(0..1 霓虹光晕) `pad` `vertical`(竖排) ；`\n` 换行 |
| `textPlane(text, height, o)` | 一块文字板 Mesh（高 `height` 世界单位）。一块一次绘制，**多块招牌用下面这个** |
| `textSigns(items, { fog, size, width })` | 很多块招牌合成 1 张图集 + 1 个网格 = **1 次绘制**。`items: [{ text, p:[x,y,z], ry, h, color, bg, glow, vertical… }]` |
| `instanced(geo, mat, items)` | 同形状摆很多份 = 1 次绘制。`items: [{ p, ry 或 q, s(数或[x,y,z]), color? }]` |
| `merged(parts)` | 不同形状合成 1 个 BufferGeometry（带顶点色）；配 `vertexColors: true` 的材质 = 1 次绘制。`parts: [{ geo, p, ry, s, color }]`；不给 `color` 而 `geo` 自带 `color` 属性时保留它的顶点色 |
| `alongRoute(route, { every, side, offset, from, to, jitter, rand })` | 沿路摆放点：每 `every` 步一个，`side` 1 左 / -1 右 / 0 两侧，`offset` 离路中心距离。返回 `[{ p, ry, heading, dir, left, s, i, kind, side }]` |
| `offRoad(route, x, z, margin = 0.3)` | 离路沿 ≥ margin 才 true。摆随机道具先过一下 |
| `nearestRoute(route, x, z)` | 最近路线点 `{ d, side(左正), y, s }` |
| `gridHeight(mesh)` | 给 `kit.terrain()` 返回的地面，返回 `(x, z) => y`：网格双线性插值，比 `groundAt` 快两个数量级，**撒树撒石头用这个**。读当前顶点，主题改过地面后取也对 |
| `groundAt(mesh, x, z, fallback)` | 往任意 mesh 打射线取高度（每次扫全部三角形，慢，只适合少量） |
| `stats(renderer)` / `sceneStats(scene)` | 预算：当前视角绘制次数/三角形；整场景三角形/对象数（InstancedMesh 和普通 Mesh + InstancedBufferGeometry 都乘实例数） |

`kit.js` 的常用函数：`sky(scene, top, bottom, { exponent })` 返回 `{ mesh, uniforms, set(top, bottom) }`；`fog(scene, color, near, far)`；`terrain(ctx, { amp, drop, rough, reach, seed, color, flatTo, map, uvScale })` 返回地面 Mesh；`ridge(ctx, { color, radius, height, seed })` 远山剪影；`mixHex(a, b, t)`。

## 7. `update(dt, st)` 的 `st`

| 字段 | 内容 |
|---|---|
| `t` / `dt` | 秒（performance.now） / 本帧间隔（≤ 0.1） |
| `s` | 化身连续步数（插值后的，登顶时到 `N + 1.2`） |
| `progress` | `s / N`，0..1（富士山用它从星空过渡到日出） |
| `pos` / `total` | /state 的整数步 / 总步数 |
| `avatar` | 化身脚下世界坐标（Vector3，只读） |
| `heading` / `kind` | 化身所在处朝向 / 路段类型 |
| `ghost` | 影子世界坐标（Vector3）或 `null`（没有影子） |
| `terrain` | 整个 `/state.terrain`（`segment, label, next, laps, wait_still, ghost_pos…`） |
| `summit` | 是否在登顶 6 s 画面里（镜头环绕） |
| `preview` | 是否离线预览 |
| `camera` | 相机（只读） |

`update` 里别 new 对象、别重建几何（每帧 60 次）；雨、霓虹闪烁之类改 uniform / 顶点缓冲。

## 8. 规矩（明天评委在 3 米外看大屏）

- **预算（每个主题）**：三角形 ≤ 500k，draw call ≤ 250。重复物件一律 `instanced` / `merged` / `textSigns`；不开实时阴影；pixelRatio 引擎定死 1。
- **别挡路和人**：路面 ±(1.1 + 0.3) 内不放东西；化身在路左 0.35、影子在路右 0.5。镜头在化身**左后上方**（后 3.7–4.6、左 1.2–1.4、高 2.1–2.8 且离正下方路面 ≥ 1.7，看向前方 1.6；数值见 `ctx.camRig`）：路左侧 3 单位以内别放高过 1.5 的东西，会糊在镜头上。
- **影子必须看得见**：影子是半透明浅青色（`theme.ghost`，缺省 `#bff3ff`）不写深度的材质，背景太亮太青会看不见；路右侧别放大块亮青色。
- **HUD 不能被压住**：HUD 是 DOM，永远在 3D 上面（影子头顶标签也是 DOM，不会被招牌挡，只会叠在上面——所以它有深色不透明底）；上沿（0–190 px）和四角有面板（底色不透明度 0.76），这些位置别放最重要的地标（鸟居、南天门），或者调 `camRig.follow.lookY` 让地标下移。影子标签引擎会自动避开面板。
- **登顶卡**在画面下三分之一（底边 9%），登顶 2 秒后才淡入：前 2 秒是给观众看的「登顶构图」，画面中上部别被挡。
- **版权**：攻壳只取"赛博未来日本"的气质，不出现任何角色、标志、原作画面；真实地名的招牌文字可以（涩谷、爱宕神社…）。
- 同一世界每次打开要一样：随机数用 `ctx.rand`，不用 `Math.random`。

## 9. 看效果、自检

起模拟（端口自选，用完 kill）：

```sh
SDL_VIDEODRIVER=dummy .venv/bin/python -m shellos.main --sim --ctl terrain --no-record --no-input --http 8801 --force-deadman &
```

- 离线预览：`http://localhost:8801/game?preview=<world_id>&pos=<n>&ghost=<n>`，可加 `&who=名字`、`&summit=1`（山顶画面）、`&still=0.8`（红灯段的站定秒数）、`&aa=0`（关抗锯齿）。不轮询 /state，按 pos 摆静态画面。
- 截图：`scripts/shot.sh "<url>" out.png 1920 1080 10000`（无头 Chrome 软件渲染，慢、吃 CPU，一次一张）。
- 自检：`scripts/dom.sh "<url>"` 打印

  ```
  ready=1  calls=19  tris=59668  scene-tris=59668  scene-objs=19
  errlog: (空)
  ```

  `ready=1` = 第一帧画完；`calls/tris` = 这个视角的绘制次数/三角形；`scene-tris/scene-objs` = 整场景（和视角无关，对照预算看这个）；`errlog` = 页面上所有 JS 报错、未处理 Promise、加载失败的文件。退出码 0 = 就绪且无报错。有 node（≥22）时走 DevTools 协议按真实时间等（`scripts/dom.mjs`，缺省最多等 60 s，一般 8–10 s）；没有 node 退回 `--dump-dom` + 虚拟时间，偶尔会在贴图解码时就到点（`ready=0` 且 errlog 空），脚本自动重试 3 次。
- 浏览器里调试：`window.__game`（`route, scene, camera, camRig, renderer, stats()…`），`window.__camHold = true` 后可以手动摆镜头。
