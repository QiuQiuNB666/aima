# 7 分钟内让评委亲眼看到"它学会了"——做法清单（EvoTavern 深圳站 · 具身/消费硬件赛道）

下面的论文和仓库链接我都实际打开过。例外有四处：OLAF 项目页（只在搜索结果里见到，没打开）、GEP 的具体字段格式、Hackster 获奖名单、LeRobot 获奖 Space，已在对应位置标注。

**推荐做法**
- 现场的学习机制用"语言/示教纠正 → 蒸馏成可检索的经验条目 → 下次检索后改参数或改计划"，也就是 DROC 加 TidyBot 的路线。不训练神经网络，秒级生效，评委能亲手触发。
- 要训练的机制（HIL-SERL、DAgger、ACT）只放录屏和曲线，不要现场跑。
- 把经验条目存成主办方 EvoMap 的 Gene/Capsule/EvolutionEvent 形态，直接呼应"经验继承"主题。Evolver 的审计日志是 `events.jsonl`，具体字段我没细查。

## 1. 分钟级生效、不训练神经网络的学习机制

| 机制 | 原理 | 出处 | 硬件上怎么用 | 7 分钟内能否演出前后对比 |
|---|---|---|---|---|
| 纠正→经验检索 | 大模型把人的纠正蒸馏成可泛化的知识，下次按文本/视觉相似度检索 | DROC https://github.com/Stanford-ILIAD/droc （有无机器人的 dummy 模式，机器人控制部分要自己写）；ARMAR-6 增量学习 https://arxiv.org/abs/2309.04316 | 评委说"再高 2cm""轻一点"，写入技能参数或计划规则 | 能，最稳 |
| 偏好记忆 | 少量样例交给大模型总结成文本规则 | TidyBot https://tidybot.cs.princeton.edu/ （未见物体 91.2%，真机 85.0%） | 评委摆两件物品 → 生成"浅色放左"之类规则 → 第三件新物品自动放对 | 能，还能展示泛化 |
| 技能库 | 把成功的代码存成技能，可检索、可组合 | Voyager https://github.com/MineDojo/Voyager ；机械臂版 LRLL https://arxiv.org/abs/2406.18746 | 新任务成功后入库，下次直接调用，步数和耗时下降 | 能，屏幕上对比"规划步数/耗时" |
| 反思记忆 | 失败后写一条语言反思，存起来供下一轮使用 | Reflexion https://github.com/noahshinn/reflexion ；ExpeL https://github.com/LeapLabTHU/ExpeL | 需要自动判定失败的信号，例如舵机电流或视觉 | 勉强，自我反思现场不可控，建议作辅助 |
| 参数自整定 | 贝叶斯优化或简单 bandit，由人打分 | Optuna 的 ask/tell 接口 https://optuna.readthedocs.io/en/stable/tutorial/20_recipes/009_ask_and_tell.html ；哈佛穿戴设备实验约 5 次迭代、10–12 分钟收敛 https://pmc.ncbi.nlm.nih.gov/articles/PMC5604949/ | 穿戴设备的震动强度、提醒时机；机械臂的速度和力度 | 7 分钟内收敛不了；预置 3–5 个候选加评委一次打分才可行 |
| 示教一次即复用 | 手把手示教或录制回放，存成原子技能 | ROS-LLM https://arxiv.org/abs/2406.19741 ；`lerobot-replay` https://huggingface.co/docs/lerobot/il_robots | 评委用主臂（leader）带一遍 → 存成技能 → 大模型改参数后复用 | 能，但纯回放不会泛化，要说清边界 |

## 2. 需要训练的机制：提前做，现场只演对比

- **HIL-SERL** https://huggingface.co/docs/lerobot/hilserl
  - 官方说法是"几个小时"。需要 NVIDIA GPU、URDF 文件、手柄或主臂，任务限制在 5–10 秒的短动作。
  - 对人工干预策略很敏感，"需要跑几次才会"。
  - 适合展示的素材：干预率下降曲线加训练延时摄影。
  - 现场风险高，光照和背景一变就可能失效。
- **DAgger 式人工接管纠正** https://huggingface.co/docs/lerobot/hil_data_collection
  - 用 `lerobot-rollout --strategy.type=dagger`，要求带电机的主臂（SO101 可以）。
  - 文档示例是 50 回合加 2 万步微调，每一轮按小时计。
- **ACT 增量数据再训练**
  - 官方教程只写"几个小时"。实测帖 https://huggingface.co/blog/sherryxychen/train-act-on-so-101 的数据：3080 显卡约 4 小时；分布内成功率从 60% 提到 90%。
  - 相机位置或标定一变，成功率就掉。
- 共同建议：保留 v0 和 v1 两个 checkpoint，现场切换模型各跑一次，同时放曲线。展位相机必须固定，否则不要用这条路线。

## 3. 已有公开项目，以及它们怎样设计"前后对比"的瞬间

1. **DROC**（https://sites.google.com/stanford.edu/droc ）：以"需要纠正的次数"为指标。第二轮减半，换一个新抽屉或新物体接近零纠正。
2. **TidyBot**：把学到的规则用文字显示出来，再让机器人处理没见过的物体。
3. **YAY Robot**（https://yay-robot.github.io/ ）：实时口头纠正加迭代微调，各阶段成功率平均提升 20%，同时展示失败案例。
4. **HIL-SERL**（https://hil-serl.github.io/ ）：训练延时摄影加 100 次评测，干预由多到少。
5. **OLAF**（https://ut-austin-rpl.github.io/olaf/ ）：口头纠正后更新策略，成功率提升 20%。此项仅在搜索结果中见到，项目页未打开。

**获奖作品没查实**：Seeed 具身智能黑客松的获奖名单（Hackster 页面 403）和 LeRobot Worldwide Hackathon 的获奖 Space（内容未加载）都没读到；搜索摘要里它们以一次性的 ACT/Pi0 模仿学习为主。没找到主打"现场从反馈中变好"的获奖作品，闭环学习可能是差异化点，但这不算核实过的结论。

## 4. 「学习前后对比」演示脚本模板（4 分钟）

1. **0:00** 评委从 3–4 个物体中任选一个和一个位置，下指令。现场随机性由评委自己制造。
2. **0:30** 第一次执行。屏幕显示"检索经验：0 条命中"。设备按默认参数跑，出现真实偏差，比如位置偏了或不合偏好。
3. **1:15** 评委用一句话纠正，或手扶示教。屏幕实时弹出新写入的经验条目，包括：
   - 触发条件；
   - 参数差值；
   - 来源原话；
   - 置信度。
4. **2:00** 评委换一个相近但不同的物体或位置。屏幕高亮"命中经验 #7，相似度 0.83 → 参数 A→B"。第二次执行成功。
5. **3:00** 评委点击删除该条经验，再跑一次，设备回到原来的错误。
6. **3:30** 展示跨评委累计的曲线。

**监控界面应显示的内容**：
- 记忆/技能库列表，每条带时间、来源和命中次数；
- 本次检索的 top-k 结果和相似度；
- 规划步骤和工具调用的时间线；
- 纠正次数、成功率、耗时随回合变化的曲线；
- 上下文 token 用量条；
- 学习前后的参数差异，以及 Gene/Capsule 的导出和审计日志。

## 5. 防翻车：既是真学习，又足够稳

**怎样证明不是写死的剧本**：
- 物体、位置和纠正措辞都由评委决定。
- 经验库可以当场清空、删除、编辑。
- 删除那条经验后，设备回到原来的错误，这是最有力的证明。
- 每条经验带原话和时间戳。
- 多位评委的经验累积保留在库里。

**怎样保证确定性**：
- 大模型只输出结构化的参数差值。
- 底层动作用预先校准好的原语加运动学，不要用端到端策略。
- "第一次出错"来自真实缺省值，例如不知道评委的偏好、没见过这个物体的高度。不要靠随机失败来制造错误。
- 检索设相似度阈值，加上离线缓存兜底。
- 每位评委开始前，把物理状态一键复位，但不清空经验库。
- 备一段录屏，现场出故障时顶上。
