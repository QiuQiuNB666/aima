## 1. Hypershell X MaxS 髋关节外骨骼

来源：
- 主办方文档《hypershell 原生 Agent 赛道 技术支持文档｜髋关节外骨骼开发平台简介》 https://autogame.feishu.cn/docx/L49jdUGenooxdxx3ci9cB94Fnle
- 附件《深圳黑客松2026串口协议.docx》（3 页，在上面文档里点开能在线预览）
- 同名在线文档在 Hypershell 自己的飞书租户里（hypershell.feishu.cn/docx/GAwQdUweboMf77xnVYpcXaeknne），要登录才能看；内容应与附件相同，未核对

平台：Hypershell X MaxS，黑客松专用固件 **2.9.99.1**。开放机身传感器数据和电机力矩控制，通过串口和电脑通信。

### 连接

- **USB CDC**（插 Type-C 就是一个串口），波特率 **3000000**，8N1
- 一行一条命令，以 `\n` 结尾（`\r\n` 也可以）
- 推荐上位机 VOFA+（支持 3 Mbps）：https://www.vofa.plus/ 。SSCOM 5.13 上限 921600，不能用
- **左腿 = 主板 CAN ID 21，右腿 = 从板 CAN ID 20**
- 单位：力矩 Nm，角度 °，角速度 °/s，陀螺仪 °/s，加速度 g，气压 kPa

### 频率与范围

| 项目 | 规定 |
|---|---|
| 数据流 / VOFA+ 画图 | 固定 200 Hz |
| 力矩下发 T | 建议 200 Hz，允许 10–500 Hz |
| T 超时 | **100 ms 未续发则力矩清零** |
| 力矩范围 | **±7.5 Nm**（超出限幅） |
| 串口波特率 | 3000000 |

画图（数据流）和下发力矩互相独立。IMU / 编码器约 200 Hz 更新一次，所以数据流固定 200 Hz。

### 命令

| 发送 | 应答 | 说明 |
|---|---|---|
| `PING` | `PONG` | 连通性 |
| `VERSION` | `OK,VERSION,2.9.99.1` | 固件版本 |
| `ENABLE` | `OK,ENABLE` | 使能力矩，并开始 200 Hz 数据流 |
| `DISABLE` | `OK,DISABLE` | 力矩清零，停止数据流 |
| `T,<left>,<right>` | `OK,T,<left>,<right>` | 左右解耦力矩，范围 ±7.5 Nm |

错误应答：未 ENABLE 时发 T → `ERR,NOT_ENABLED`；格式错 → `ERR,T_FORMAT`；未知命令 → `ERR,UNKNOWN`。

**插 USB 后先开机进入工作态，再发 ENABLE。本固件插 Type-C 不会切到充电态。**

### 数据流（ENABLE 后固定 200 Hz）

VOFA+ 协议选 **FireWater**，帧头必须是 `S:`（冒号）。

```
S:<ms>,<pitch>,<roll>,<yaw>,<gx>,<gy>,<gz>,<ax>,<ay>,<az>,<kPa>,<Ldeg>,<Rdeg>,<Ldps>,<Rdps>
```

| 字段 | 含义 |
|---|---|
| ms | 主板时间，ms |
| pitch, roll, yaw | 穿戴系欧拉角，° |
| gx, gy, gz | 腰部陀螺仪角速度，°/s |
| ax, ay, az | 腰部线性加速度，g |
| kPa | 气压 |
| Ldeg, Rdeg | 左右髋关节输出轴角度，° |
| Ldps, Rdps | 左右髋关节输出轴角速度，°/s |

### 最小流程

```
PING
ENABLE
T,1.5,-1.5
T,1.5,-1.5
...
DISABLE
```

### 镜像裁剪说明（原文照录）

- 左右力矩走广播 CAN_SET_ETE_FORCE（dest 255），不再由主机经 HYPER_FORCE 耦合从机
- FOC、编码器、IMU、气压、CAN、USB 串口保留
- 力矩环是独立电流随动：iq = torque / HYPER_A_TO_NM_RATIO，限幅 ±7.5 Nm

### 用之前要知道的（我的解读，不是原文）

- **充电**：原文只说「插 Type-C 不会切到充电态」，没说怎么充。开发时一直插着 USB 也在耗电池，去 Hypershell 展位问清楚怎么充、满电能用多久。
- **安全**：这是穿在人身上的力矩。协议自带两道保险——100 ms 不续发就清零、±7.5 Nm 限幅。自己的代码再加一道：先从 ±0.5 Nm 这种小值试起，程序退出、异常、断开时都先发 `DISABLE`。
- **读数据不用上位机也行**：它就是一行一行的文本，Python 用 pyserial 按行读、按逗号拆就能拿到 15 个字段。VOFA+ 在 macOS 上能不能用我没核实。
- 数据帧里**没有电机电流或实际输出力矩的回读**，只有角度和角速度。

- 开放的是**荣耀 YOYO 智能体的「技能」**，不是 Android SDK。开发形态是一个技能包：`SKILL.md` + `scripts` / `references` / `assets`

- 真机测试：开放平台建技能 → 安全检测 → 把测试账号加进测试名单，不用过审

没查到的（到展位问荣耀或 Seeed 的人）：样机固件版本是否满足 MagicOS 10 / YOYO 版本要求；测试名单要绑谁的荣耀账号；有没有绕过 YOYO、从自己的程序直接驱动云台的路径。

## 3. AI 眼镜：Luma（球球 9/22 给的 SDK）

飞书上没有任何眼镜资料（指南只在赛道题面提到「AI 眼镜」，Seeed 清单和展位名单里都没有）。资料来自球球发来的仓库：

- **SDK**：https://github.com/metastable-lab/luma-core （MIT，2026-09-07 建，README 开头写着「If you are here for a hackathon」，是专门给黑客松准备的）
- 读的时候开着两份：`docs/GUIDE.md`（接入指南）和 `PROTOCOL.md`（逐字节协议，每条命令标了验证状态）
- 眼镜型号：Luma，E09 平台（项目名 T1）。SDK 在固件 **bt 1.4.8 / isp 1.3.1 / hw 2** 上验证过——拿到眼镜先读一下版本，对不上的话以下结论可能有出入

### 它能做什么

| 能力 | 走哪条路 |
|---|---|
| 拍照、录短视频 | 蓝牙发命令；原图要走 Wi-Fi 拉 |
| **拍完照 ~1 秒推一张约 11 KB 的小 JPEG** | 蓝牙直推，专门给视觉大模型用，不用 Wi-Fi |
| **麦克风 + 眼镜端唤醒词** | 唤醒后蓝牙推 Opus 音频，约 50 包/秒，16 kHz 单声道 |
| 触摸板手势（单击/双击/三击/滑动） | 状态通过蓝牙上报，可以绑成自己的动作 |
| 扬声器、媒体与通话控制 | 蓝牙命令，三路音量 |
| 实时画面 | 眼镜开热点 + RTSP，H.264 1600×1200 约 25 fps |
| 相册（照片、语音、视频） | 眼镜开热点 + 小型 JSON HTTP 接口 |
| 电量、固件版本、佩戴检测 | 蓝牙读取和主动推送 |

蓝牙是控制通道，Wi-Fi 只在搬运媒体时按需打开。

### 三种接法

- **笔记本直连（不用手机）**：Rust 自带完整蓝牙客户端，`luma scan / info / photo --ai look.jpg / voice out.wav / wifi gallery`；也有 Python 版（bleak）
- **iPhone**：自带 SwiftUI 演示 App，要真机，模拟器没有蓝牙；先跑 `./ios/build-core.sh`
- **Android**：生成 Kotlin 绑定

### 9/22 在球球的 Intel Mac（macOS 13.7）上实测

- `cargo test`：**194 项全过**，离线协议部分可用
- 带蓝牙 + Opus + Wi-Fi 的电脑端客户端（`--features ble,opus,wifi-client`）：**编译通过**，`luma` / `gallery` / `live` 三个程序都生成了
- 蓝牙扫描 8 秒：**没发现眼镜**。原因没确认——多半是眼镜不在这台电脑旁边，也可能是 macOS 没给终端蓝牙权限（SDK 文档说权限被拒的表现和"没找到眼镜"完全一样）。**连真机还没验证过**

### 文档里点名的坑

- **语音不会自己停**：唤醒后音频流一直推，必须自己跑两个计时器（1.2 秒没新包 = 说完了；单次最长 30 秒），到点发 `0x56` 关掉
- **热点不稳**：眼镜热点密码固定 `12345678`，眼镜地址 `192.168.169.1`；收到 SSID 后要**再等约 2 秒**才能连；系统常出现 25 秒超时、iOS 会跳回原来的 Wi-Fi，要准备重试。**现场几百人、禁开手机热点，眼镜自己开的热点在人群里能不能稳，没有任何依据，要现场试**
- 相册接口里的 `size` 单位是 KiB 不是字节，拿来比下载大小会误判"下载不完整"
- 读全部设置不是回一帧，而是连续回十帧
- 实时画面开头可能是灰的，要等到关键帧
- 蓝牙上**拿不到原图**，原图只能走 Wi-Fi

### 对打法的意义（我的判断，没核实）

- 「看一眼 → 问大模型」这条路**只用蓝牙**：拍照带 AI 标记，1 秒后拿到 11 KB 小图喂视觉模型。不碰 Wi-Fi，现场最稳
- 语音在 Livehouse 80–85 dBA 下，眼镜端唤醒词和收音效果都没有依据，要现场实测；触摸板手势可以当兜底触发
- 11 KB 的小图分辨率有限，看电视菜单小字够不够清楚要实测

## 4. PS5 手柄（DualSense，球球自带）

不是主办方设备，飞书上自然没有资料。能用上的地方（我的判断，没实测）：

- **外骨骼的安全开关**：按住扳机才发力矩、松手就发 `DISABLE`。穿在人身上的力，比键盘可靠得多，评委试穿时也放心
- **扳机当力矩旋钮**：扳机是连续量，可以直接映射成 0 到几 Nm 的助力，评委一按就懂
- **机械臂遥操作**：LeRobot 自带手柄遥操作，可以替代没借到的主臂
- **展位控制器**：一键复位演示、切换演示态/累积态，不用碰电脑
- 手柄自带六轴陀螺仪、触摸板、自适应扳机和震动，可以当一个现成的「可穿戴/手持输入 + 触觉反馈」件

接法：macOS 原生支持（USB 或蓝牙配对都行）。这台电脑已装 pygame 2.5.7，按键、摇杆、扳机能直接读；陀螺仪、自适应扳机、灯条要走 macOS 自带的 Game Controller 框架，pygame 能不能用没核实。9/22 检查时手柄没接在这台电脑上。

## 5. Seeed 小件（9/22 球球拍照）

照片里能认出三件，都在 Seeed 设备清单上（清单里各 5 块），第一轮调研已经查过，以下是已核实的要点：

### reSpeaker Flex XVF3800 Circular-4（环形四麦）

- XMOS XVF3800 芯片，4 个麦，360° 拾音，标称最远 5 m；板载回声消除、降噪、波束成形、去混响、声源方向（DoA）、人声检测（VAD）；12 颗灯环；3.5 mm 和喇叭接口
- 分体式：核心板 + 排线连接的麦克风板
- **最省事的用法：当 USB 麦克风直接插 Mac**，免驱。不要在比赛里花时间给它刷固件接 XIAO
- **先分清是哪个版本**：看板子上有没有焊一块 XIAO
  - 没焊 XIAO（型号以 -0 结尾）：出厂就是 USB 固件，插上 Mac 应该直接出现一个声卡
  - 焊了 XIAO（-C4-1）：出厂是 I2S 固件，插电脑**不会被识别**，要按住静音键上电进安全模式，用 `dfu-util` 刷回 USB 固件
- 读声源方向：`python xvf_host.py DOA_VALUE`（要 pyusb），返回 0–359° 和是否有人声
- Livehouse 里别指望它远场收音和追声源（官方 demo 自己写了 DoA 要安静环境），按住说话 + 近讲更稳

### 0.96 寸屏整机（Powered by XIAO nRF52840 Plus）

- 盒子标签确认是 **nRF52840 版**，这解决了之前「是哪一版」的疑问
- 这不是扩展板，是**一台完整的小设备**：80×160 屏、六轴 IMU、麦克风、2 个按键、电池口，自带主控
- **只有蓝牙，没有 Wi-Fi**，跑不了小智，只能通过蓝牙连手机或电脑当前端
- 适合做**可以递到评委手里的徽章 / 挂件 / 遥控器**
- 文档：https://wiki.seeedstudio.com/getting_started_0.96_inch_display_nrf52840/

### 6×10 RGB WS2812 灯阵（for XIAO）

- 60 颗可编程彩灯的小板，**本身没有主控，要插一块 XIAO 才能亮**
- 屏幕那台的 XIAO 是焊死的，挪不过来。要用灯阵得另拿一块 XIAO（现场有 XIAO ESP32-S3 ×10、ESP32-C5 ×5）
- 文档：https://wiki.seeedstudio.com/cn/rgb_matrix_for_xiao/
- 在暗场里很显眼，适合当表情 / 状态灯

### XIAO ESP32-S3（那个灰色圆盒子就是它的包装）

- 9/22 照片确认：盒子侧标签「Seeed Studio XIAO ESP32S3，SKU 113991114」，板子丝印 `Model: XIAO-ESP32-S3`
- 标签没写 Sense，盒子里也没有摄像头扩展板，按普通版处理：**没有摄像头和麦克风**（普通版和 Sense 版 SKU 的对应关系凭记忆，没查实）
- 有 2.4G Wi-Fi + 蓝牙，Type-C 供电和刷写，带外接天线座
- **正好补上灯阵缺的主控**：把 6×10 灯阵插到这块 XIAO 上就能亮。附带的排针要焊上
- 连电脑建议走 USB 串口，别依赖现场 2.4G Wi-Fi
