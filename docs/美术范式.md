# 美术范式 · 峰哥亡命天涯

> ART 线（9/23 晚）。目的：十几条线同时在改画面，让评委 9/24 13:00 在展位大屏上看到的是**一个完整的作品**，而不是 6 张图、3 个人、2 套 HUD 拼在一起。
> **数值都在 `shellos/ui/static/game/style.js`**，各线直接 `import { SEG, WHO, UI, TYPE, MOTION, LIGHT, MAT, PALETTE } from '/game/style.js'`，不再各写一份。本文讲为什么和怎么用，附录 A 是逐页审查清单（具体到文件和数值），附录 B 是证据截图。
> 守门测试：`tests/test_style.py`（路段色两两分得开、HUD 强调色 / 影子 / 捷风不撞路段色、三个人不撞色）。改 `style.js` 先跑它。

## 1. 风格定位：低多边形 + 电影感光影 + 霓虹描边

一句话：**积木感的世界，电影的光，发光的线告诉你腿上正在发生什么。**

为什么这么定——不是新方向，是把现有素材已经在走的路写成规矩：

| 支柱 | 现有素材里已经是这样 | 为什么适合这个作品 |
|---|---|---|
| **低多边形**（平面着色、少面数、纯色块，不贴照片纹理） | 泰山松 / 梧桐林冠 / 珠峰冰塔全是二十面体和挤出体；岩石平面着色；化身是 CesiumMan；所有贴图都是 Canvas 现画（主题接口 §1 规定不从网上拉贴图）；三角形预算 ≤ 500k / 主题 | ① 一晚上十几个人能做完 6 个世界，只有低多边形做得到风格统一；② 展位 M2 Pro 要稳 60 帧，光影管线已经吃掉一大块；③ 版权干净——没有一张扒来的纹理；④ 评委 3 米外看大屏，大色块比细节更能读 |
| **电影感光影**（ACES 色调映射、冷暗暖亮、泛光、光束、暗角） | L 线 `lighting.js` 已经给 5 个主题配好：半浮点 + ACES + 每主题白点、太阳 PCF 软阴影、泛光按最亮通道、泰山 / 富士光束、冷暖分离 + 暗角 | 低多边形最大的风险是「像教学 demo」。同一套几何，打上有方向的光、冷暖对比和雾，立刻像游戏截图。这是「作品感」的主要来源，而且已经做完了，只差收口（珠峰没预设、跑酷没接） |
| **霓虹描边**（发光的线和轮廓：人物菲涅尔轮廓光、路段色条、招牌） | 化身 / 影子 / 捷风都有菲涅尔描边；东京台阶黄亮条、训练场路段色路沿和箭头、东京霓虹招牌、跑酷车道线 | 这是**信息层**：「腿上的力」是这个作品的核心，评委得一眼看出哪段是台阶、哪段是坡。发光线条在白天和夜晚都读得出来，也和低多边形的平面色块天然对比。白天主题不需要霓虹招牌——「描边」在白天 = 人物轮廓光 + 路段色条 |

三条的分工：**低多边形管形，光影管情绪，描边管信息。** 情绪可以每张图不同（东京冷夜、泰山拂晓、珠峰刺眼的白），信息层全作品一模一样。

## 3. 路段色语义（硬规则，主题不许改）

| 路段 | 色 | `style.js` | 腿上 |
|---|---|---|---|
| 上坡 | 绿 `#3ddc84` | `SEG.up` | 助力 |
| 台阶（上 / 下同色，方向用 ▲ ▼） | 黄 `#ffd54f` | `SEG.stairs_up` / `SEG.stairs_down` | 脉冲 |
| 下坡 | 蓝 `#4fc3f7` | `SEG.down` | 阻尼 |
| 红灯 / 站定（吸氧、排队也是它） | 红 `#ff4d4f` | `SEG.wait` | 拉住 |
| 平地 | 灰 `#8a95a3`（= 不标） | `SEG.flat` | 无 |

用在哪儿（都用上面这个十六进制，**不许**用主题 accent 近似）：
- **3D**：台阶每级前缘亮条（`MeshBasicMaterial`，宽 0.04–0.08，白天主题取窄、夜晚取宽，**颜色不变**）；坡面人字箭头；训练场路段门、路沿、脚印；
- **HUD**：顶部路段标签、「腿上的力」曲线和图例、`N 步后：…`、红灯 / 站定面板、峰哥气泡的 red 事件；
- **跑酷**：起跳障碍前沿 = 台阶黄（起跳前给的是 `lift`，和台阶同一类脉冲），斜板 = 上坡绿，落地 = 下坡蓝。

主题可以决定**标多少**（白天可以只有台阶沿条，训练场可以满地箭头），不能决定**标成什么色**。每张有台阶的图，台阶必须有 `SEG.stairs_up` 亮条——这是评委理解「腿上的力」的唯一视觉入口。

现状：这套色在代码里有 **3 份拷贝且互相不一致**（`hud.js:7` 下台阶是橙 `#ff8a65`、红灯是品红 `#ff2e88`；`hud_force.js:8` 下台阶黄、红灯 `#ff4d4f`；`grid.js:10` 又一份；`game.html:52` 红灯大字 `#ff4d6d`），东京坂道箭头是青色，泰山 / 富士 / 珠峰台阶没有黄条。见附录 A。

## 4. 光照基调

**色温：冷暗暖亮**。暗部偏蓝（`grade.lo` 的 B > R），亮部偏暖（`grade.hi` 的 R > B）。夜景主光冷、点光源暖；白天太阳暖、天光冷。唯一例外：训练场（中性，暗部整体提亮）。

上下限（`style.js` 的 `LIGHT`；`lighting.js` 的 PRESET 要落在里面）：

| 参数 | 下限 | 上限 | 说明 |
|---|---|---|---|
| 曝光 `exp` | 0.75 | 1.25 | 夜景 1.2–1.25，白天 0.75–0.95 |
| 泛光强度 `bloom[0]` | 0.2 | 0.8 | 白天 ≤ 0.3，霓虹夜 ≤ 0.8 |
| 泛光阈值 `bloom[2]` | 0.9 | — | 按最亮通道算；低于 0.9 白衣服和影子会糊成一团光 |
| 饱和度 `grade.sat` | 1.0 | 1.12 | 低多边形的色块靠饱和度撑，但 > 1.12 霓虹会溢色 |
| 暗角 `grade.vig` | 0 | 0.4 | 高亮雪地给 0（主题自己有缺氧暗角） |
| 雾起点 `fog.near` | 6 | — | 世界单位。镜头到化身约 4.8，雾起点比它近 = 峰哥被雾吃掉 |
| 化身轮廓光 `rim` | 暖色 | — | 峰哥的轮廓光**永远是暖的**（`WHO.fengge.rim` 一带），冷青色留给影子 |

现有 PRESET 对照：东京、泰山、梧桐、训练场全部在范围内 ✅；**富士夜段 rim `#9fdcff` 是冷青**（峰哥会像影子）❌；**珠峰没有 PRESET**，落到 grid（暗部 ×1.2 提亮，雪地发灰发白）❌；富士夜段雾起点 2.5 ❌；跑酷没接光影管线（没有色调映射 / 暗角，和登山游戏两种画风）⚠️。

## 5. 材质规则

- **默认一律 `MeshLambertMaterial`（哑光，等效粗糙度 1.0，金属度 0）**：地形、岩石、建筑、植被、衣服。低多边形靠平面着色读形状，高光会把面打碎。
- **光泽只给两处**：东京湿路面（Phong + 环境图，`reflectivity ≤ 0.55`，L 线做的）、峰哥的脸（Standard，`roughness 0.72`，P 线做的）。冰、铝梯、铁链都不用金属材质，靠颜色和轮廓表达。
- **自发光的使用场合——只给「光源本身」和「信息」**：
  - 光源本身：灯、窗、招牌、日轮、头灯 → `MeshBasicMaterial` / 满格自发光，允许进泛光；
  - 信息：路段色条、训练场路沿、HUD 同源的地面标记 → `MeshBasicMaterial`，允许进泛光；
  - 人物：自发光打底 `self` 0.2–0.3（夜里不被染成深蓝），再加菲涅尔轮廓光（`pow(1-N·V, 3)`）；
  - **大面积（单块占画面 > 5%）自发光 ≤ 0.35**（训练场围墙 0.15、门框 0.25 都在范围内）；大面积表面过泛光阈值 = 满屏泛光，禁止。
- 不写深度的半透明只给：影子、雨雪、光晕、雾团。别给台阶和路面开 `transparent`（主题接口 §5 已写）。

## 6. 人物：比例、轮廓光、三人一眼分开

三个人同高（`AVATAR_H = 1.46`，头顶），同一个画面里常常同时出现。**评委 3 米外必须 0.5 秒内分清谁是谁**，靠三个通道同时区分（任何一个通道单独失效，另外两个还能认）：

| | 峰哥（玩家） | 影子（上一位） | 捷风（追兵） |
|---|---|---|---|
| **实 / 虚** | 实体 | 半透明（0.4–0.6），不写深度 | 实体 |
| **识别色** | 琥珀外骨骼 `#ffb03a`——**全作品唯一穿琥珀的人** | 冰青 `#bff3ff`（雪地 / 高亮场景用深青 `#12b5a5`，**不许换成蓝**） | 钴蓝外套 `#2f7fe0` + 白发 |
| **轮廓光** | 暖 `#ffd9a8`–`#ffe2b8`，强度 0.9–1.3 | 影子色和白混 55%（引擎已做） | 白 `#f2f6ff`，**不用青** |
| **动效签名** | 腿忠实于真实髋角 | 跟着录像走，离远淡出 | 离地飘行 + 风白拖尾 `#eaf2ff` |
| **HUD 标签** | 左上圆头像，琥珀框 | 深底 + 冰青边「上一位：…」 | 蓝底白字「捷风」 |
| **站位** | 路中心左 0.35 | 路中心右 0.5 | 见下 |

比例：峰哥头 0.25 m（身高的 1/5.8，P 线为正面镜头 2.4 m 外看清脸放大的，**保留**）；捷风雕像缩到同身高、脚底落地；影子 = 化身同一个模型。

**构图铁律（新）**：捷风**不许进入镜头 → 峰哥之间的视锥**（跟拍镜头在化身身后 4.6、左 1.4 世界单位，1 步 = 0.5，所以镜头在身后约 9 步；捷风走左侧 `LAT 0.85`，正好在这条线上）。她要么和峰哥并肩（落后 ≤ 0.3 步）——「追到肩膀旁边了」最有压迫感；要么在镜头后面（落后 ≥ 10 步，出画，用 HUD「在身后 x 步」表达）；**中间那段不停留**，快速穿过。现在的截图里她常常整个挡住峰哥（附录 A · J）。

现状主要问题：**青色太多**——峰哥衣服胸前 V 字条纹是青 `#27a9b8`、富士夜里峰哥轮廓光是青、捷风拖尾和描边是青、珠峰的影子是饱和蓝（和捷风外套同色相）。改法见附录 A。

## 7. UI：字体、字号层级、面板

**字体**：系统字体，不加载网络字体（展位不连外网）：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Noto Sans CJK SC", sans-serif`（`UI.font`）。数字一律 `font-variant-numeric: tabular-nums`（跳动的数字不抖）。字重：数字 / 大标题 900，标题 800，正文 700，说明 600。标题字距 0.08–0.18 em。

**字号层级**（`TYPE`，rem；`html { font-size: clamp(13px, 1.04vw, 44px) }`，1080p 下 1 rem = 20 px）：

| 级 | rem | 1080p | 用在 |
|---|---|---|---|
| display | 5 | 100 px | 待机大标题「峰哥亡命天涯」 |
| hero | 3.4 | 68 px | 海拔、跑酷距离、登顶用时——**一屏最多一个** |
| h1 | 2.5 | 50 px | 路段名、步数、「腿上的力」峰值、红灯大字 |
| h2 | 1.7 | 34 px | 世界名、面板标题 |
| body | 1.3 | 26 px | 峰哥气泡、AI 卡正文、N 步后 |
| small | 1.0 | 20 px | 标签、按钮、图例 |
| caption | 0.85 | 17 px | 次要说明。**3 米外最小就到这里**，更小的只给 `?debug=1` 的帧率行 |

现在登山 HUD 用了 25 种字号（`game.html` + `hud*.js` + `fengge_hud.js` + `npc.js`），加上跑酷 28 种，从 0.75 到 5 rem 几乎每 0.1 一档。新写的就近取上面 7 级；旧的不用逐个改，合并到下一轮时顺手收。

**面板**：底 `rgba(8,10,16,.86)`、1 px 边 `rgba(255,255,255,.12)`、圆角 1 rem、内边距 .8rem 1.1rem、字影 `0 1px 3px rgba(0,0,0,.6)`。**不用 `backdrop-filter`**（R 线实测：盖在 WebGL 上每帧重新模糊，34 → 60 fps 就差它；不透明度 .86 看起来一样）。强调面板（红灯、AI 卡当前行）只改边框色和左侧 0.3 rem 色条，不改底色。

**HUD 颜色**：
- 通用强调色**全局固定 = 霓虹紫 `#b48cff`（`UI.acc`）**，不再跟主题 accent 走——主题 accent 会撞路段色（泰山黄 = 台阶、训练场 `#4fc3f7` = 下坡、梧桐青绿 = 上坡、东京青 ≈ 下坡）。用在：进度条、「N 步后」的数字、按键提示、待机标题的光、AI 卡里「提议」这类中性标签。紫色不属于任何路段、任何人，是这个作品 HUD 的品牌色；
- 峰哥相关（头像框、气泡、名牌）用 `WHO.fengge.tag` 琥珀；
- 状态色（AI 卡「生效 / 裁剪 / 否决」、安全灯）：`UI.ok` 绿、`UI.warn` 橙 `#ff9f1a`、`UI.danger` 红——和路段色同一个红绿，都是「放行 / 拉住」的意思，不冲突；
- **不许**：用路段色当装饰（例如「新纪录」徽章用台阶黄）、用蓝色表示「中性 / 信息」（撞下坡）。

用法：页面启动时 `applyCssVars()`，CSS 里写 `var(--seg-up)`、`var(--who-fengge)`、`var(--acc)`。

## 8. 道具密度与正面镜头构图

两种镜头：**跟拍**（化身左后上方，看前方）和**正面**（V 键 / `?cam=front` / 待机轮播，站在化身前方回看来路）。正面镜头是评委看峰哥脸的时候，也是最容易被道具糊住的时候。

**跟拍**（主题接口 §8 已有，重申）：路面 ±1.4 内不放东西；路左侧 3 单位内不放高过 1.5 的东西；地标别放在 HUD 上沿 0–160 px 和四角。

**正面（回看来路）——新规则**：
1. **前景留空**：化身前方 2.5 米以内（正面镜头站在这一侧，这里就是画面近处）、路中心两侧 ±2.5 米以内，不放高过 0.8 米的道具（灯笼、立柱、护栏柱头、门柱）。现在东京鸟居下的石灯笼、泰山升仙坊红墙、富士东洋馆、梧桐木栏柱都在这个范围里，占了画面边缘 15–30%。
2. **三分构图**：峰哥站在画面中线；来路消失点落在他肩膀高度附近；**画面左右各留一个中景地标**（鸟居 / 牌坊 / 山小屋），不要两边都塞满。
3. **景深分层**：近景（离镜头 0–3 米）只有路面和化身；中景（3–15 米）地标和道具；远景（> 15 米）天际线 / 远山 / 云海。近景出现大块深色 = 糊镜头。
4. **画面边缘 8% 内**不能出现被切掉一半的高对比物体（半根红柱、半个灯笼）——评委的眼睛会被边缘吸走。
5. 登顶卡在左下（`summitCard: 'left'`）时，卡片不能压住峰哥：卡片右边缘到峰哥脚之间至少留 5% 画宽（珠峰登顶现在压住了，附录 A · U/E）。

**密度**：跟拍视角画面里同时可见的「有名字的道具」（招牌、牌坊、石刻）≤ 6 个；同类小道具（石头、草、灯）用实例化，密度往远处加、近处减。

## 9. 动效节奏

`MOTION`（秒）：

| 名字 | 值 | 用在 |
|---|---|---|
| fast | 0.15 | 数字变色、力值颜色 |
| base | 0.35 | 面板 / 气泡进出、标签出现 |
| slow | 0.8 | 场景级淡入淡出、造山过场、登顶卡延迟 |
| stagger | 0.65 | AI 卡一行一行亮出来 |
| hold | 4.5 | AI 卡停留 |
| summitHold | 8 | 登顶成绩卡最少停留 |

- 缓动一律 ease-out 进、ease-in 出；不用弹跳 / 回弹（和低多边形的硬朗不搭，且会显得像手游）。
- **闪烁 ≤ 2 Hz**（安全灯急停 0.6 s 一周期 ≈ 1.7 Hz ✅；东京航空障碍灯 ≈ 0.4 Hz ✅）。霓虹招牌**常亮**，不做故障闪。
- 镜头旋转 ≤ 1 rad/s（登顶环绕 6 s 一圈正好）；镜头切换用 `#cut` 黑场 0.35 s，不硬切。
- 3D 里的持续动效（雨、雪、经幡、呼吸、飘行）振幅小、频率低于 2 Hz；化身腿的动作不受这条限制（它是真实数据）。
- 撞击 / 被抓：一次性的屏幕边缘红晕 + 0.5 s 轻微震动（跑酷现在就是这样）✅；**不做整屏闪白 / 闪红**。

## 10. 禁忌清单

1. **纯黑大色块**：画面里任何 > 10% 面积的区域 RGB 都 < 12（近景深色墙、夜里不打光的山体）。最暗的地方也要有辅色的影子——用雾色、天光（hemi）、`grade.lo` 抬起来。
2. **高频闪烁**：> 2 Hz 的闪、随机故障闪、整屏闪白 / 闪红。
3. **满屏泛光**：大面积表面过泛光阈值（雪地、白墙、自动售货机正面这种大块亮面）；泛光强度 > 0.8；阈值 < 0.9。
4. **主题自己改路段色**，或用主题 accent 近似路段色。
5. **HUD 强调色跟着主题变**。
6. **第四种人物主色**：新 NPC / 路人不能穿琥珀、冰青、钴蓝；路人一律低饱和中性色。
7. **影子变成实体色**：影子不透明度 > 0.6、或饱和蓝 / 紫色的影子。
8. **角色被挡**：捷风 / 道具 / 登顶卡挡住峰哥超过他身体的 1/3。
9. **照片 / 扒来的纹理**进 3D 场景（峰哥的脸是唯一授权例外）；任何游戏 / 动画的标志、原画。
10. **网络字体、CDN 资源**（展位断网就开天窗）。
11. **新字号**：3 米外 < 0.85 rem 的正式文字。
12. **半透明台阶 / 路面**、给低多边形表面加高光金属材质。
