## 1. 方法

**参考标签（和估计器门限无关）**：设备没穿（文件名带 table）→ 整段不是走路；穿戴的 → 3 s 窗口里左右髋角**反相**（相关 ≤ −0.3）且两腿活动度都 ≥ 8° 算走路。坐下、站起、弯腰是两腿**同相**，这一条物理上最能区分。走路段前后 1.5 s 算边界不计分。

**估计器喂法**和主循环一致：100 Hz 取最新一帧（不是 183 Hz 全速）。**候选周期**（相位绕回一圈）的产生和门限无关，所以每段只跑一遍、记下每个候选的时长 / 最低置信度 / 活动度 / 与另一腿相位差，门限离线套——1080 档网格几秒钟扫完。

**指标**：
- 穿戴假周期 = 穿着、不在走路时被接受的周期（坐 / 站 / 坐站 / 单腿晃）——任务里的「坐/站段假周期」
- 桌上假周期 = 没穿、被手摆弄时被接受的周期
- 覆盖率 = 走路段里被接受周期的时长之和 ÷（走路时长 × 2 腿），1.0 = 一步不漏
- 「稳」= 这一档和网格上所有相邻档的穿戴假周期都是 0

**参考标签的毛病**：0922-175524 / 174946 里有几段被标成走路的其实是 0.2–0.3 s 的小幅快抖（活动度 4–7°），不是走路。它们拉低了总覆盖率（总 0.32，只看 181327 是 0.44）。**判断时以 181327 为准**。

## 2. 发现

### 2.1 一步被切成两段（→ 半周期锁存）

真人髋角在支撑相有**平台**（腿停住不动 0.4–1.2 s），平台上 d≈常数、ω≈0，相位贴着 0/1 分界抖：0.97 → 0.05 → 0.98 → 0.01，每抖一次算一次绕回。9/22 录制里一个 1.0 s 的步常被切成 0.8 s + 0.2 s。锁存：相位先要走到 0.35–0.65（髋角另一头）才允许下一次绕回。

效果：候选周期数降到 1/5–1/11（181327：4350 → 392），走路段接受数 71 → 75（同门限），不影响正弦步态的任何测试。

### 2.2 坐/站假周期来自两腿同相（→ 同相检查）

9/23 前门限下 13 个穿戴假周期，**全部**在 0922-174946 第 85–100 s，与另一腿的相位差 0.87–1.00（= 同相）。锁存后它们依然在（它们本身就是完整的大幅周期）。同相检查：本腿绕回时，另一条腿相位差离 0 至少 `sync_tol`、且置信度 >0.5（另一条腿不动 → 置信度 ≈0 → 单腿晃也拦住）。

注意：真人走动时两腿相位差集中在 **0.2–0.3**，不是 0.5（髋角有平台，估计器相位不匀速）。所以不能写成「相位差 ≈ 0.5」，只能写成「不是 ≈0」。`sync_tol`：0.1 → 3 个假周期，0.15 → 0，0.2 → 0（取 0.2，留余量）。

### 2.3 漏步主因是「整周期最低 conf>0.6」（→ 去掉）

平台期 d 只有 3–5°，相图半径 / 8° 掉到 0.45–0.6，**一瞬间**低于 0.6 整步就被拒。有了同相检查后，这个门限对坐站已经没有额外作用（单维度扫描：最低 conf 从关到 0.7，穿戴假周期都是 0），只剩下漏步：

| 整周期最低 conf | 关 | 0.3 | 0.4 | 0.5 | 0.6 | 0.7 |
|---|---|---|---|---|---|---|
| 覆盖率（7 段合计） | **0.32** | 0.26 | 0.23 | 0.20 | 0.15 | 0.12 |
| 桌上假周期 | 15 | 12 | 11 | 9 | 9 | 7 |

**力矩不受影响**：Guard 的 `conf<0.5 → 0` 照旧按每一拍的置信度卡力矩，这里只是「这一步算不算步」（地形前进、步频、经验卡检索）。安全层一行没动。

### 2.4 周期区间

0.6 / 0.7 / 0.8 s 下限：穿戴都是 0，桌上 20 / 19 / 15，覆盖率 0.33 / 0.33 / 0.32 → 取 **0.8**（最快 150 步/分，快走够用，跑不算）。上限 1.8 / 2.0 / 2.2：覆盖率 0.30 / 0.31 / 0.32 → 取 **2.2**（最慢 55 步/分，给慢踏步留余地）。活动度 10–20° 几乎不影响（0.33 → 0.28），保持 **15°**。

两个问题，都是**没改默认**、只给了开关：
1. **走路时只有 44% 的时间是「走动中」**：原因和 §2.3 一样，平台期置信度掉到 0.5 以下。这也是 Guard 的门（conf<0.5 → 0），**属于安全层语义，不放宽**。后果：真人踏步时地形脉冲大约一半时间给不出来。踏步模式（§5）能把它提到 0.66，代价是误判也翻倍。（这是修复 A 之前的数；修复后默认 0.24、踏步模式 0.33，误判 3 / 13 s → 9 / 22 s，见 §5.2。）
2. **站着晃也会「走动中」**：非走路段 250 s（其中穿戴 162 s，这是参考标签的上界，有些可能是没标上的小走动）。`GaitEstimator(recent_s=1.5)` 可以砍到 10 s，但起步要多等 2 s、走路时脉冲时间再砍一半。要不要开由 B 线 / 总指挥定，我不建议今晚开。

### 4.1 修复（第 ② 轮审查后）：相位停滞 + 两腿同相 → 不算走动中

审查发现：停步/坐下后髋角停在离慢均值（τ≈2 s）很远的地方，相图半径 = |θ−θ̄| 撑着 conf≥0.5，相位钉在 0.5（坐着晃腿时在 0.4–0.6 来回抖），地形把一个约 0.13 s 的脉冲变成持续力矩。
改法（`estimator.py`，conf 本身不动）：
- **相位停滞**：某条腿最近 0.3 s 相位净推进 < 0.05 圈 → `LegState.stalled`，走动中为假（参数 `prog_s` / `prog_min`）
- **两腿同相**：相位差 < 0.1（`inphase_tol`）→ 走动中为假。坐下/站起是慢速同相动作，相位在走但不是走路
- 两条都**不重置 0.3 s 保持计时**，条件一消失走动中立刻回来

试过、没用的：停滞时把 conf 置 0 / 慢均值换快均值 —— 真人走路相位不匀速，也会短暂停滞，走路段走动中占比 0.45 → 0.07～0.13。

9/22 回放（地形强制 stairs_up，统计 conf≥0.5 时任一腿 |力矩|>0.05 的最长连续段；缺省 / width=20 / t_step=3）：

| 录制 | 修前 | 修后 |
|---|---|---|
| 175524 | 1.34 / 4.95 / 4.94 s | **0.23 / 0.29 / 0.23 s** |
| 174946 | 0.82 / 2.96 / 2.95 s | **0.12 / 0.24 / 0.18 s** |
| 181327 | 0.79 / 4.12 / 4.10 s | 0.36 / 0.41 / 0.39 s（1115 s、1178 s 一条腿慢慢停下，相位还在以约 0.2 圈/s 推进，停滞门 0.3 s 后才判） |

代价：审计口径下非走路段误判走动中 162 / 87 s → **3 / 13 s**（穿戴 / 桌上），走路段里走动中占比 0.44 → 0.24；但 181327 走路段里实际发出的脉冲数 301 → 267（−11%），丢掉的大多是停滞期被拉长的那部分。周期接受、覆盖率、假周期数都不变（conf 没动）。

1. 先用默认档让评委原地踏步，看 `pos` 涨不涨
2. 腿上有脉冲、化身不走（§5.1 的现象）→ 重启加 `--stepping`，死人开关照旧按住
3. 还是断断续续 → 请评委抬高点腿（活动度 ≥ 15°，约 ±8°）；再不行改慢走

局限：踏步模式的收益全来自模拟（真人小幅踏步只有 181327 一段近似）；「坐着两腿交替晃 ±6°」和原地踏步在髋角上分不开，踏步模式会接受，靠死人开关。

## 6. HS_PHASE（`--hs`）

方法：参考走路段里，按每条腿自己的相位叠加平均腰部 az；每个接受周期里分「前半周」（0.25–0.75，本腿在前）和「后半周」（0.75–0.25，本腿在后）各找 az 最大那一拍。腰部 IMU 分不出冲击是哪条腿的（一个周期里两次触地），所以要按步态类型选半周：向前走 → 前半周、且不早于髋最屈；支撑平台占比 >0.3（髋角在支撑相停住 = 原地踏步样）→ 后半周。选定的半周要左右一致（差 ≤0.08）、逐周期集中（R ≥0.6）、每腿 ≥20 周期才给数。

0922-181327（170 s，唯一够长的一段）：

| 腿 | 前半周 az 峰 | 后半周 az 峰 | 髋角最屈 | 支撑平台占比 |
|---|---|---|---|---|
| L | 0.36（R 0.83） | 0.91（R 0.78） | 0.42 | 0.44 |
| R | 0.36（R 0.84） | 0.05（R 0.64） | 0.44 | 0.46 |

判定：**证据不够**，HS_PHASE 保持 0.5。
- 支撑平台占比 0.44：这段更像**原地踏步**（向前走时支撑腿髋角是持续伸展的，不会停住）。
- 按踏步看后半周：L 0.91 / R 0.05，左右差 0.14，不对称；最大的那个冲击只出现在左腿落地时（右腿落地的冲击小得多），像是腰部 IMU 偏一侧。
- 前半周左右倒是一致（0.36），但**早于**髋角最屈 0.07 周期；向前走时脚跟着地不会早于髋最屈，所以这不是触地，更可能是抬腿/蹬地。
- 其他两段走路太短（接受周期 <20）。

**方法本身验过**：在模拟步态的已知相位 0.6 放 az 冲击，`--hs` 找回 0.6 ± 0.06；只在一条腿放冲击时判「证据不够」（`tests/test_gait.py::test_audit_reference_and_hs_detector`）。

**明天怎么定**：3 个人各**向前走** ≥30 s（有走廊的话）录下来，跑 `gait_audit.py --hs --rec <新录制>`；判定给数且 3 人差 <0.05 才改 `terrain.py` 的 HS_PHASE。给不出数就按脚感调（B 线的 2AFC）。
