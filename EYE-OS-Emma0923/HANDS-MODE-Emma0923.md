# 双手模式 · Emma0923 · v0.4

## 当前交付

用户希望将腿部支撑解绑后改为双手握持，先自动抬起到握持位置，再实现双杆阻尼、射击游戏反馈或挖掘机交互。照片说明了产品交互意图，不能证明机械行程或手持承载已获验证。

本轮交付为 **浏览器内、无量纲、无硬件输出的交互模拟器**。它在画面中演示解绑、校准、抬起、双杆操作和反馈，不修改 ShellOS、Guard、真实串口或控制律；勾选握持/解绑不是读取真实传感器。

运行现有 `node server.mjs`，打开 `/hands.html`，或从设备页点击“双手模式预览”。不需要连接外骨骼。

1. 勾选模拟已松开腿绑带。
2. 校准模拟中位，再勾选模拟双手已握住。
3. 点击抬起到握持位置，等待一次抬起完成。
4. 拖动左右滑杆，或用 A/D、J/L 操作。靶场按 F/点击触发脉冲；挖掘机左右输入分别控制动臂和铲斗。
5. 取消握持、暂停、Esc、窗口失焦或隐藏都会中止模拟。重新握持后仍需主动点击就位，旧输入不会恢复动作。

默认是“抬起就位后双手推拉”，不是持续自动上下摆动；该产品偏好仍待用户确认。数值、动画时间、杆件尺寸与姿态仅用于交互预览，不是物理模型、硬件参数或安全限值。

## 三种反馈应分别设计

| 功能 | 模拟器行为 | 真机需要补充 |
| --- | --- | --- |
| 抬起就位 | 画面中的一次位置变化 | 手持独立位置闭环、位置/速度限位、握持与固定检测、机械行程和符号校准 |
| 阻尼 | 与虚拟杆位移速度相反的反馈指示；静止为零 | 验证速度与力矩正方向、控制延迟、能量约束及握持释放响应 |
| 游戏脉冲 | 有冷却、自动衰减的无量纲视觉反馈 | 单独的主动反馈限幅和持续时间验证，不得当作被动阻尼 |

现有 `Frame` 提供左右髋角、角速度及腰部 IMU，串口输出 `T,左,右` 两路力矩。因此可先映射每手一个旋转通道：挖掘机的升降和铲斗，更多动作需额外输入或模式切换。它不等于双手 6DoF 跟踪，不提供已验证的手柄三维位置。

`convention.py` 的右侧符号按原腿部布局定义。改变握点、转轴姿态、固定方式后，零位、方向、力臂与受力部位都需重测。不能将腿部默认限值标为手部安全限值。现有 Guard 保留为未来唯一硬件命令路径，但本模块没有接入它。

## 实现与合并边界

- `hands-core.js`：纯内存 `createHandSimulation()`，无 import、网络、串口、进程、文件或可注入输出回调。
- `dispatch(action)` / `tick(dtSeconds)` / `snapshot()` 均返回独立快照；`hardwareOutput` 固定为 `false`。`tick` 将单步时间限制为 0–0.05 秒，防止后台积压导致动画跳跃。
- 状态：`legs → released → calibrated → raising → ready`；松手/暂停进入暂停状态。非法数据清输入和反馈，无法绕过就位条件。
- 动作：`set-release`、`calibrate`、`hold`、`raise`、`input`、`scene`、`damping`、`fire`、`reset`、`suspend`。左右输入 -1..1，视觉阻尼 0..1；动臂/铲斗位置 0..1。没有 Nm、真实电机目标或硬件 enable 字段。
- `hands-controller.js`：只响应本页鼠标、触摸、键盘和生命周期；不调用 `/api`、Web Serial 或设备连接。
- `hands.html` / `hands.css`：独立响应式预览页，保持 Emma0923 标记。页面不会自动切换真实外骨骼模式。

未来真机适配应为独立模块：硬件能力声明和手持配置 → 模式互锁 → 校准/限位验证 → 控制律 → 原有 Guard → 设备。必须由台架测得参数和真实握持/固定状态驱动，不得将本页勾选框当作安全输入，不得直接把无量纲动画信号发送成力矩。

## 尚缺的硬件依据

1. 厂家或机械伙伴确认手持固定方式、可用行程和机械限位。
2. 解绑、双手握持、失去握持的可靠检测，以及急停入口。
3. 手持零点、左右符号、速度方向与专用限值；位置信息是否在抬杆范围内有效。
4. 空载台架、受控握持、失联/松手/卡阻等测试证据。

官方佩戴资料描述的是腰部及腿部固定；本次未找到可证明此手持改法已受支持的厂家材料。参考：[Hypershell 佩戴调整](https://support.hypershell.tech/en-US/how-do-i-adjust-my-hypershell-product-for-the-best-fit-1228062)、[官方手册入口](https://hypershell.tech/pages/tutorials)。照片设备的具体型号/开发固件仍应由硬件伙伴核对。

## 验证

`node --test hands.test.mjs`：13 项状态、反馈、时间和输出边界测试；受限环境使用 `--test-isolation=none`。独立无 I/O VM 流程也已验证 `hardwareOutput:false`。

浏览器已验证解绑→校准→握持→抬起→触发脉冲，场景切换与左右杆独立操作；取消握持立即暂停并归零输入，挖掘机位置冻结。完整模块自动测试 75/75 通过。当前结果只证明软件预览行为，不包含真实电机、握持体验或硬件安全验收。
