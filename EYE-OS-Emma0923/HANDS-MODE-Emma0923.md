## 产品结构

两套外骨骼共同参与游戏：腿部一套负责行走；另一套松开腿带、抬起两根支撑杆，以双手握持，成为有力反馈的左右操作杆。用户已向现场工程师确认支持手持玩法。本版实现角度输入与画面试玩，真实抬杆、保持、阻尼及射击反馈仍需专用手部控制器。

```text
腿部外骨骼 → 原腿部控制器 / 行走游戏
手部外骨骼 → 独立只读角度源 → 三点校准 → 左杆 / 右杆
                                             ↓
                                   左右双枪 / 动臂与铲斗
                                             ↓
                                   无量纲画面反馈（本版）
                                             ↓ 后续开发
                              本机手部控制器 → Guard → 手部设备
```

两根杆各提供一个旋转输入，不等于双手三维定位。左右枪暂以“前推触发、回拉重新准备”作为交互试验；完整挖掘机的回转、行走等还需要模式切换或额外输入。两台设备的固定、活动空间和同时佩戴体验尚待实测。

## 直接试玩

需要 Node.js 22+，无需 npm 依赖。在本目录运行 `node server.mjs`，打开 `http://127.0.0.1:4177/hands.html`，也可从设备页进入。

1. 默认开发试玩使用键盘/滑杆，无需设备。
2. 模拟解绑 → 校准中位 → 勾选模拟握持 → 主动点击抬起就位。
3. A/D 控制左杆，J/L 控制右杆；前推超过 65% 触发同侧枪，回到 20% 以下才重新准备。持续推住不会连发；两侧各有 400ms 冷却。F / H 或页面按钮也可独立触发左右枪。
4. 挖掘机场景：左杆升降动臂，右杆收放铲斗，中位停止；此时前推不会开枪。
5. 暂停、取消握持、Esc、失焦、页面隐藏或超过 250ms 的动画停顿会清空输入并暂停。重新握持不自动恢复，需主动就位。

画面抬起是一次就位动画，并非持续摆动。解绑和握持勾选是模拟流程，不是传感器检测。视觉阻尼和脉冲没有真实力矩单位。

## 连接独立手部角度源

前提：硬件伙伴已提供针对手部设备验证过的只读遥测服务，或使用模拟器。接口应兼容 ShellOS `GET /state`。本模块不启动上游、不打开串口，也不发送 ENABLE、DISABLE 或力矩指令。

现有 `SerialLink.handshake()` 会发送 ENABLE，原腿部控制器也会运行腿部控制逻辑。因此，不要仅为获得手部角度而把普通腿部控制器直接启动在第二套设备上。手部数据源和专用运动控制应由硬件伙伴明确配置。

确认已有服务后，在启动 EYE OS 的 PowerShell 中设置：

```powershell
$env:SHELLOS_PORT = '8765'        # 腿部既有服务
$env:SHELLOS_HANDS_PORT = '8766'  # 已验证的独立手部只读数据服务
node server.mjs
```

- 两个端口必须不同；不设置手部端口时，页面提示缺少配置，不会回退到腿部数据。
- 配置只声明服务角色，不能自动识别设备佩戴位置，也不能证明两个服务背后连接了不同硬件。现场需核对串口/设备身份。
- 页面读取同源 `GET /api/hands-telemetry`，后端仅向固定回环地址发送 `GET /state`。不接收页面传入的端口或远程地址。
- 手部采样间隔目标 100ms，请求不重叠、无历史状态缓存、不执行慢 USB 枚举；同一时刻的请求可共享上游读取。帧龄连同传输/等待时间必须不超过 200ms。这个频率仅用于游戏输入，不是电机控制频率。
- 设备在 SSH 远程电脑时，应在那台电脑运行相应本机服务，浏览器可通过经过配置的同端口 SSH 转发访问。当前电脑的 localhost 不会自动指向远程设备。

页面选择“手部外骨骼角度 · 只读”并开始读取后：

1. 双手保持舒适中位约一秒，记录中位。
2. 分别保持舒适后拉、舒适前推，记录两端；无需触碰机械极限。
3. 每次记录需至少 5 个连续采样、跨越至少 400ms、角度波动不超过 2°，且角速度不超过 5°/s。每侧前后观测点必须在中位两边，跨度各至少 3°。这些仅是画面校准质量条件。
4. 回到中位，模拟解绑、应用校准、勾选握持并主动画面就位。超出舒适点时只夹紧画面输入，不作为真实电机限位。
5. 映射按两边跨度分别归一化，自动学习前推方向；右侧已由 ShellOS 归一化，不再额外翻转。8% 死区和轻度平滑降低中位抖动。

真机、模拟器与回放在页面中明确区分。来源串口/模式改变、源时间倒退、错误数据、停止读取或离开页面会清除校准；断流导致画面暂停。恢复数据不会自动开始游戏。角度模式切场景也会暂停，避免把挖掘时推住的杆突然解释为开枪。

可导出三点观测 JSON，含来源、采样数和源时间，标记 `hardwareOutput:false` 与 `motorLimits:false`。不自动恢复旧校准，不把观测范围当作厂家限位。

## 文件与集成契约

| 文件 | 职责 |
| --- | --- |
| `hands-core.js` | 无 I/O 的游戏内核；dispatch、tick、snapshot 返回独立快照 |
| `hands-input.js` | 时效/来源检查、稳定采样、三点校准、归一化与平滑 |
| `hands-reader.js` | 固定 GET 读取；停止中断、超时及迟到响应隔离 |
| `hands-controller.js` | 生命周期、角度/开发输入、左右枪和画面绑定 |
| `server.mjs` | 独立手部端口、请求边界、只读上游桥接 |
| `hands*.test.mjs` | 状态、输入、读取与页面回归；全部使用软件测试数据 |

内核保留 `legs → released → calibrated → raising → ready` 状态；这里的 legs 只表示这一套待切换外骨骼的画面状态，不会切换另一台腿部设备。输入为 `dispatch({type:'input',left,right})`，每轴 -1..1。显式射击支持 `side:'left'|'right'|'both'`，省略 side 保留旧版双侧行为。

快照包含独立 shotsLeft / shotsRight 计数。lastShot 是最新一条反馈预览意图，带 `role:'hands'`、左右通道、持续时间和 `unit:'normalized-preview'`，不是可靠事件队列或硬件命令。同一帧两侧输入可各触发一次，计数分别累计，lastShot 只保留最后一次。当前画面按两侧计数更新；正式游戏可根据计数变化产生事件，或增加明确的事件队列。所有状态的 hardwareOutput 固定 false。

目前没有将手部输入并入主项目 Three.js 行走页面，没有双设备运动命令路由，也没有电机执行端。应先整合游戏输入，物理输出另经本机专用适配器和 Guard；不得直接把动画反馈值换单位写入串口。
