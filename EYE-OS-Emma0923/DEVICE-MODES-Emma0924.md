# 外骨骼可选配置与控制隔离 · Emma0924 · v0.7

一套和两套都是可选配置，不把第二套作为手部游戏的前提。单套同一时刻只负责一种用途；双套同时使用时，每套拥有独立角色、端口、控制器和握持信号。

| 配置 | 腿部 | 手部 | 设备数 |
| --- | --- | --- | --- |
| `single-legs` | 行走 / 原腿部游戏 | 关闭 | 1 |
| `single-hands` | 关闭 | 原腿杆解绑后用作左右操作杆 | 1 |
| `dual` | 一套负责行走 | 另一套负责双杆 | 2 |

## 页面与服务如何选择

`hands.html` 顶部新增「试玩配置」。切换时立即停止只读采样、取消未完成请求、清空两轴/握持/脉冲/三点校准。返回手部配置后需要重新准备，不自动继续。单套腿部会禁用本页手部操控；设备页中的腿部入口保持独立。

这个页面选择只改变试玩配置，不会改变正在运行的硬件服务或驱动电机。读取角度时，页面选择必须与服务声明的配置完全一致。服务在启动时固定配置，不能通过网页请求修改：

```powershell
# 在 EYE-OS-Emma0923 目录，以下三组选其一。

# 一套用于腿部：即使残留手部端口环境变量，也不会读取手部。
$env:EXOSKELETON_MODE='single-legs'
$env:SHELLOS_PORT='8765'
node server.mjs

# 一套用于双手：8765 必须是经过核验的手部只读服务。
# 允许复用单套的 HTTP 端口，但必须先关闭原腿部控制进程。
$env:EXOSKELETON_MODE='single-hands'
$env:SHELLOS_HANDS_PORT='8765'
node server.mjs

# 两套同时用：各自的只读服务与实体串口均须不同。
$env:EXOSKELETON_MODE='dual'
$env:SHELLOS_PORT='8765'
$env:SHELLOS_HANDS_PORT='8766'
node server.mjs
```

这些命令只启动 EYE OS，不创建手部硬件服务，也不打开串口。手部硬件服务和游戏的最终接线仍需现场联调；不能通过把普通腿部 ShellOS 的端口填进 `SHELLOS_HANDS_PORT` 冒充手部服务。未指定模式时，保持兼容：没有手部端口则单套腿部；有手部端口则双套。推荐部署时总是明确写模式。

`GET /api/exoskeleton-layout` 可查看只读配置。手部 `/state` 必须明确包含 `link.role: "hands"`，缺失或为 legs 会拒绝；新版原腿部服务声明 legs。双套还检查另一侧的有效腿部数据及实体串口是否重复。另一侧数据缺失时本页暂停双套角度试玩，不发任何停机/切换命令；本机两个控制器的故障与停止互不借用。

## 已实现的防争用

1. **同一串口只允许一个持有者**：新版 `SerialLink` 与只读 capture 在打开串口前申请操作系统文件锁。同一系统账户的合作进程不能重复占用；COM 名大小写、前导零和 Windows 别名统一处理。锁文件不要删除，进程退出或崩溃由系统释放锁。
2. **同一连接只允许一个 Guard**：拒绝第二个控制器，拒绝手部 Guard 接腿部连接、腿部 Guard 接手部连接。关闭后的 Guard 不再接受 arm / rearm / deadman / submit / estop；旧看门狗和退出回调也不能干扰新会话。
3. **连接角色固定**：原入口默认 `SerialLink(..., role='legs')`；手部适配必须明确 `role='hands'` 和串口。改变角色须停止并关闭旧连接，再新建连接，不允许原地修改角色。手部连接拒绝原腿部握手/自动 ENABLE 恢复路径。
4. **断线不寻找另一套替身**：重连固定原端口，并核对枚举到的 USB 序列号、VID/PID。身份缺失、改变或暂时无法确认即要求显式重新绑定，不能因为串口号相同就自动继续。两台都在时，多候选自动发现会拒绝猜测。
5. **独立输出状态**：每个 Guard 的 deadman、力矩、故障和看门狗独立。关闭腿部 Guard 不会给手部连接写 DISABLE。网页来源、角色或配置不匹配时停止读取，禁止继承上一次校准。

文件锁是本项目同账户进程之间的合作约束，不替代串口驱动独占，不能管住未升级旧进程或厂家软件。现场换模式时仍要关闭旧控制进程。USB 序列号来自串口桥，不是外骨骼身份的密码学认证；固件、线缆和物理设备标签还需核对。停止指令失败不等于设备已经停止，失力支撑仍由机械方案保证。

## 单套换用途的接线顺序

先停止游戏事件和控制循环 → 旧 Guard shutdown → 关闭旧串口并释放占用 → 按已确认的机械方式改为腿部/手部 → 用明确角色和端口新建连接 → 验证设备身份和对应参数 → 重新采样校准 → 本机主动开始。

任何步骤失败都不自动转到另一角色。用同一套设备先玩行走、再玩双杆是受支持的产品配置；一套设备不能同时承担腿部行走和手部双杆。

## 合并与验收边界

这版已修改公共 `shellos/device/serial_link.py`、`shellos/safety/guard.py` 和 `/state` 的角色字段。请将 `ownership.py`、两处手部适配改动、网页/服务及测试一起合并。不要只复制 `hands.html`，否则没有底层独占保护。

已做模拟设备、跨进程占用和原腿部流程回归。没有连接、使能或驱动真实外骨骼；双套实际同时佩戴、物理握持传感器、角色切换台架流程及力反馈仍待现场验收。工程参数要求沿用 `HAPTICS-Emma0924.md`，不能只用三点角度观测代替。
