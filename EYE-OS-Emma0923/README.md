## 直接运行

需要 Node.js 22 或更新版本；无需安装 npm 依赖。在此目录打开终端：

```sh
node server.mjs
```

打开 <http://127.0.0.1:4177>。也可以使用 `npm start`。终端按 `Ctrl+C` 停止服务。

在 Windows 上，请先在系统蓝牙设置连接 **E06-003B**。本机服务通过 PowerShell 读取音频端点，并仅在用户点击测试时向目标眼镜播放提示音。程序不会自行配对、切换系统默认音频设备或调整系统音量。API 返回播放完成后，还需要本人确认是否在眼镜中听到声音。

如果端口已被使用，可以先停止旧服务，或在 PowerShell 设置端口：

```powershell
$env:PORT = '4178'
node server.mjs
```

非 Windows 平台也可运行网页功能；Windows 设备桥接在该平台会明确显示不支持。

读取外骨骼状态时，在同一台电脑另行启动 ShellOS。上游默认 `http://127.0.0.1:8765/state`；若 ShellOS 使用其他端口，在启动 EYE OS 前设置 `$env:SHELLOS_PORT = '8766'`。该设置仅允许端口数字，不支持远程主机或页面传入目标地址；启动控制台不会启动或使能外骨骼。

## 哪些功能可以使用

| 功能 | 当前实现 | 使用条件与边界 |
| --- | --- | --- |
| 眼镜音频状态 | Windows 本机查询 | 显示播放、输入端点和可读取的输出音量；端点可用不等于实际听到或拾音成功 |
| 指定 E06 播放测试音 | 本机桥接直接测试 | 需要 Windows 已连接 E06-003B；听感由使用者确认 |
| 浏览器声音播放 | 系统音频输出 | 手机或电脑应在系统中选择眼镜；网页不保证输出设备就是眼镜 |
| 录音、输入电平、回听 | 浏览器麦克风接口 | 用户授权后选择音源；默认麦克风可能属于电脑或手机，必须确认来源 |
| 录音保存 | 当前浏览器 IndexedDB | 最长录音时长以界面提示为准；页面离开前结束录音 |
| 照片、音频和视频资料库 | 手动导入、预览、下载、删除 | 保存于当前浏览器，不代表从眼镜同步或由眼镜拍摄 |
| 文字朗读、语音与语速选择 | 系统文字转语音 | 可用语音取决于系统及浏览器，不是 AI 助手或翻译服务 |
| 声音旅游导览 | 预设示例讲解 | 使用系统朗读；尚未接入 Google Maps、实时街景、定位或云端多人 |
| 轻运动计时 | 本地计时器 | 不读取运动传感器，不控制外骨骼、阻力或电机 |
| 外骨骼状态 | CP210x 枚举 + 本机 ShellOS 只读桥接 | 显示角度、角速度、步频、安全状态等允许字段；USB 出现、服务在线和有效真机帧分别判断 |
| 手机和桌面适配 | 响应式页面、PWA 清单 | 安装入口由浏览器决定；离线缓存仅覆盖应用界面 |

拍照、录像、眼镜内部相册自动同步、电量、硬件按键、固件管理、AI 对话和翻译，**当前均未接入厂商或 AI 服务**。界面提供能力说明，不将这些入口表现为已可控制硬件。某项尚未接入也不等于硬件一定不支持，需要厂商协议或 SDK 验证。

## 在手机使用，不依赖电脑

手机版本的目标连接方式是：**手机运行页面，手机通过系统蓝牙连接眼镜，眼镜播放声音；麦克风路由须在目标手机上实测。** 当前交付包尚未部署公网。

1. 将以下静态文件部署到支持 HTTPS 的站点：`index.html`、`app.js`、`styles.css`、`app.css`、`icon.svg`、`manifest.webmanifest`、`sw.js`、`exoskeleton-controller.js`，以及 `display.html`、`display.css`、`display-core.js`、`display-controller.js`、`display-receiver.js`。v0.5 还需部署 `hands.html`、`hands.css`、`hands-core.js`、`hands-controller.js`、`hands-input.js`、`hands-reader.js`。此操作不需要部署 Windows 桥接脚本。
2. 用手机浏览器打开 HTTPS 地址，并在手机系统中将 E06 设为蓝牙音频设备。
3. 按需授权麦克风。选择、确认输入音源，再开始录音；手机浏览器可能把音源选择交给系统。
4. 浏览器支持时可添加到主屏幕。录音等接口需要安全上下文，直接打开本地 HTML 文件不能替代 HTTPS 部署。

`127.0.0.1` / `localhost` 只指当前设备，**手机无法通过这个地址连接电脑上的服务**。本机服务有意只监听回环地址，Windows 桥接也只处理这台电脑的眼镜。手机网页的音频由手机系统管理，不需要远程调用电脑的播放接口。

HTTPS 静态部署后没有本地 `/api` 是正常状态，应显示桥接不可用，保留浏览器支持的功能。离线界面不代表厂商接口、麦克风权限或系统语音能离线工作；个别系统语音可能需要网络。

## 本地数据与缓存

- 录音和导入文件保存在当前浏览器的 IndexedDB，本项目不自动上传这些文件。清理站点数据、浏览器存储回收或更换浏览器可能导致资料丢失，重要资料请下载备份。
- 系统文字朗读是否使用在线语音由操作系统或浏览器决定，本项目没有自建 AI 服务。
- Service Worker 只处理其作用域内的同源 GET。导航优先联网，失败时返回已缓存页面；已缓存的应用静态文件可先使用并在后台更新。
- `/api` 请求绝不进入离线缓存。离线时不会用旧缓存伪装当前眼镜已连接或测试成功。
- 每次发布更新应用文件时，都应修改 `sw.js` 中 `VERSION`。旧窗口关闭后新版本可激活；激活只清理该应用、该作用域的旧缓存，不清理 IndexedDB 资料库。

## 本机接口

此处描述已实现的服务接口，默认地址为 `http://127.0.0.1:4177`。它们供同源控制台调用，不是对公网开放的硬件控制 API。

| 接口 | 作用 | 关键约定 |
| --- | --- | --- |
| `GET /api/health` | 服务与平台信息 | `bridgeSupported` 只说明平台是否支持桥接 |
| `GET /api/device` | 目标眼镜音频端点快照 | `checkedAt` 标记查询时间；`playback` / `microphone` 各含 `detected`、`active`、`muted`、`volume` |
| `GET /api/displays` | Windows 桌面显示器几何诊断 | 只读、缓存 3 秒；浏览器选屏仍需用户授权 |
| `GET /api/exoskeleton` | USB / ShellOS / 遥测三层状态 | USB 缓存 5 秒、上游缓存 500ms；无查询参数、无运动写入；详见外骨骼指南 |
| `GET /api/hands-telemetry` | 独立手部角度输入 | 需配置独立手部端口，无旧快照缓存或 USB 枚举；硬件输出恒 false；详见双杆指南 |
| `POST /api/audio/test` | 向指定眼镜播放提示音 | 同源、`Content-Type: application/json`、请求体 `{}`；返回 `requiresConfirmation` 要求使用者确认听感 |

音量或静音不可读时为 `null`，不要将它们显示成 0 或“未静音”。`capabilities` 表示当前适配器已接通的能力，并不推断眼镜完整硬件规格。服务端的 `audibility: "unverified"` 不能擅自改为“听到了”。错误响应有 `error` 与 `message`；设备未连接、静音、桥接读取失败等都应如实显示。

音频测试接口检查请求来源并限制并发，不接收设备名、脚本路径、系统命令或自定义测试音。不要将此接口直接转发到公网，也不要为了手机访问而去掉回环地址和来源检查。

## 与 aima 合并

目标仓库为 `QiuQiuNB666/aima`，交付模块放入仓库根目录下的 `EYE-OS-Emma0923/`，不另建独立仓库。通过独立审阅分支和 PR 提交，供伙伴判断可合并内容；上传代码不代表已完成游戏集成。已核对现有 Python ShellOS 服务、Three.js `/game` 页面、`GET /state` 与 `shellos/glasses/luma.py`。除本目录外，配套提交只窄改 Windows `find_port` 发现逻辑，并增加 8 项 mock 测试；Guard、安全限制、控制循环、运动指令、游戏页面和 Luma 接口的行为不变。

最小合并步骤：

1. 在 `EYE-OS-Emma0923/` 中运行 `node server.mjs`，打开 `http://127.0.0.1:4177`。同机 ShellOS 默认在端口 8765 提供 `/state` 与 `/game`；控制台已自动只读映射 `/state`，用户也可在画面共享选择器中选中游戏窗口。真实游戏画面到显示眼镜的完整链路仍待验收。
2. 让 ShellOS 继续作为运动和场景状态来源。本控制台只读遥测；讲解、提示音和会话事件的自动联动待实现，不新增外骨骼运动控制链路。
3. 在游戏和控制台之间增加音频适配器，把“到达景点”“暂停”“训练结束”等已确认事件转成声音提示。先用预设讲解验证，再接入地图或 AI 服务。
4. 另行实现厂商适配器；确认具体权限、SDK 和设备协议后逐项开放拍摄、媒体同步或电量功能。在此之前保持能力说明状态。
5. 合并时检查部署子路径、Service Worker 作用域和现有站点缓存；不要让本控制台的 Service Worker 接管整个 aima 站点。

建议的后续事件格式如下，**它是待与伙伴确认的接口约定，并非当前已实现的游戏事件总线**：

```json
{
  "schemaVersion": 1,
  "eventId": "session-123:poi-001",
  "sessionId": "session-123",
  "type": "scene.poi.entered",
  "timestamp": "2026-09-23T08:00:00.000Z",
  "payload": { "poiId": "poi-001", "narrationText": "下一站，沿河慢行。", "locale": "zh-CN" }
}
```

消费端应按 `eventId` 去重，忽略旧会话事件，并允许用户停止或静音讲解。旅行地名是虚拟场景信息，不能当作用户真实位置。外骨骼的急停、阻力限制和运动控制继续留在原有硬件与游戏系统中。
