# Emma0924 · 穿戴自查与游戏操作教学

版本 0.8，入口 `hands.html`。两层职责分开：穿戴准备降低漏检和模式混淆；操作教学让玩家跟着演示学会当前游戏的动作。两者均不能替代设备硬件保护。

## 玩家流程

1. 选择一套或两套；一套再选择腿部行走或双手操作杆。
2. 按本次方式逐项自查。单套腿部共 5 项、单套双手 6 项、双套 11 项；两套分别检查腰部固定、腿带应系紧还是解除，并核对设备用途和活动干涉。
3. 选择真实角度输入时，额外启动只读连接检查。所需角色都必须是新鲜真实设备数据，双套不能指向同一端口。角色、端口、连接通过不等于佩戴正确。
4. 明确确认本次自查后，查看该穿戴方式的引导，再完成原有三点角度校准与画面就位。流程演练可以用键盘，不需要设备；演练的勾选不是穿戴记录。
5. 当前游戏演示并要求跟做三个动作。靶场：左侧攻击、右侧攻击、主动暂停。挖掘机：左杆动臂、左杆回中后右杆铲斗、主动暂停。
6. 完成后点「进入画面试玩」。练习计数和机械位置归零/回到初始值，校准保留，玩家需重新主动就位。重新学习、切换游戏均开始对应教学。

没有“一键全部通过”，没有自动记住上次穿戴确认。换人、刷新、切换数量/用途/输入源、离开页面或网络离线会清除检查与校准。连接失效、过期或来源改变会撤销可继续状态；新数据到达后也需主动重新确认。浏览器失焦和超过 250ms 的画面停顿继续暂停动作，自动暂停不算完成教学中的主动暂停。

## 目前能查什么

| 检查 | 来源 | 能作出的结论 |
| --- | --- | --- |
| 所选角色及数量、实体端口分离、新鲜角度 | 固定本机 ShellOS `/state` | 当前所需数据是否可读 |
| 活动空间、腰部固定、腿带、杆件支撑、左右握持 | 穿戴者逐项确认 | 本次自查已确认；没有传感器认证 |
| 左右操作、回中、主动暂停 | 当前游戏中的真实角度或演练输入 | 学会该游戏的基础输入；不代表硬件急停验收 |
| 绑带扣合、握持失效、机械固定、物理急停 | 尚未接入相应硬件证据 | 未验证，不能由网页勾选替代 |

本版页面不发送任何电机指令，不开放自动抬杆或真实阻尼。真实执行必须由现场确认的机械方案、传感器与本机控制保护共同约束；`wear.canContinue()` 只表示可以继续画面演练，绝不能传给 Guard 作为 ENABLE / deadman / 固定检测信号。

## 给游戏伙伴的接入接口

- `wear-core.js` 管穿戴会话与所选设备角色，纯状态无 I/O。`confirmItem(id, boolean)` 记录本人自查；`ingest(report, nowMs)` 接收连接证据；`confirm(nowMs, requireDevice)` 明确确认；`canContinue(...)` 只供画面准备入口使用。切换模式或换人必须 `reset(layout)` 并清空该玩家输入与校准。
- `tutorial-core.js` 管每款游戏的独立教学。`GAME_TUTORIALS` 注册步骤文案和动画提示方向；`createGameTutorial(scene)` 建立会话；`observe(gameState, operatorPause)` 判定玩家实际完成；`enter()` 只在三步完成后进入画面试玩；新场景调用 `reset(scene, initialState)`。
- 增加游戏时，补充对应动作判定，使用游戏的规范化输入/进度，不根据“点击下一步”视为已经学会；最后一步保留玩家主动停止动作。教学完成与穿戴确认不要使用同一个布尔值。先完成教程状态流和异常中断测试，再接入真实输入。
- `hands-controller.js` 是接线范例：穿戴未完成则禁用校准和画面输入；任何自查撤销都会清空旧输入；换游戏保留当前穿戴确认但重启教学；换穿戴方式连同教学一起清空。所有确认仅在本页内存存在。
- 本轮只接入 `hands.html` 的靶场、挖掘机。单套腿部展示自查和三步使用引导，跳转既有设备页；`/game`、`/worlds`、`/parkour` 等旧入口尚未强制接入此流程。不能据此宣称整个仓库已经有统一硬件安全门禁。

## 只读连接契约

`GET /api/wear-check`：固定同源、GET/HEAD、无 query，无页面自定义上游。按服务启动配置 `EXOSKELETON_MODE` 仅请求所需的固定本机 `/state`，双套并行读两路，共享进行中的请求；不枚举或打开串口。

返回 `schema: aima.wear-check.v1`、`layout`、`checkedAt` 与 `devices[]`。每行白名单字段为 `role / source / reachable / roleVerified / port / fresh / frameAgeMs / sourceTime`。另有 `sensorChecks: {straps:null, grip:null, mount:null}`、`wearVerified:false`、`hardwareOutput:false`。

前端收到时需要每路真实数据实际帧龄不超过 200ms，报告不超过 1.5 秒、无未来时间；两个角色不得重复实体端口。连接检查每 500ms 轮询，1.5 秒未更新则结果失效。这是连接检查的新鲜度，**不是允许硬件继续施力的时限**；原手部画面输入仍单独使用 200ms 的遥测时效校验。重复旧快照不能刷新时效，迟到请求不能复活旧会话。

启动配置和设备独占沿用 [DEVICE-MODES-Emma0924.md](DEVICE-MODES-Emma0924.md)；完整验证见 [VALIDATION.md](VALIDATION.md)。复验执行 `npm test`，全部使用假设备/假服务，不需要穿戴外骨骼。
